# 布局栅格与间距规范

## 1. 目的与范围

本文定义 CodeStreak 的间距体系（8pt 系统）、栅格与断点、垂直节奏、圆角、页面骨架与安全区、卡片内部结构、触控热区、列表高度标尺与多设备适配策略。

- **负责**：间距、栅格、断点、圆角、页面骨架、容器内边距、触控热区、列表高度、多设备布局。
- **不负责**：颜色见[设计令牌规范](02-设计令牌规范.md)；字号与行高见[字体与排版规范](03-字体与排版规范.md)；动效时长见[交互与动效规范](06-交互与动效规范.md)；组件编号与结构见[组件规范](05-组件规范.md)。换算基准为 360vp 宽设计稿、1px（Tailwind）= 1vp。
- **权威边界**：页面级间距、栅格、断点、圆角阶梯以本文为准；单个组件内部的固定尺寸（如 C-36 行高 60vp、C-26 四格内边距 4vp）以[组件规范](05-组件规范.md)为准，本文不重复定义。

## 2. 8pt 系统与 4pt 半档

- 间距、尺寸、高度以 **8vp** 为主刻度（`8 / 16 / 24 / 32 / 40 / 48 / 56 / 64 / 72 / 96`）；文案与紧凑簇允许 **4vp** 半档（`space-xs = 4`、`space-md = 12`、`space-lg = 20`、`space-xl = 28`），这是原型 Tailwind 的实际取值，必须保留。
- **2vp / 6vp / 10vp 仅用于光学修正**（图标与文本垂直居中、1vp 描边补偿、胶囊内边距）；禁止用作组件之间的间距，否则相邻卡片会出现 2vp 的错误缝。任何 `padding`/`margin`/`gap`/`height` 值若不在 §3 令牌表内，必须给出光学修正的理由，否则驳回。

## 3. 间距令牌表

| 令牌 | vp | Tailwind 对应 | 原型用法 | 使用场景 |
| --- | --- | --- | --- | --- |
| `space-xs` | 4 | `p-1` / `gap-1` | `p-space-xs`、TabBar `px-space-xs` | 标签簇内间距、图标与文本、周条格间距 |
| `space-sm` | 8 | `p-2` / `gap-2` | `mb-space-sm`、按钮组 `gap-space-sm` | 卡片内相邻元素、并排按钮、相邻列表项 |
| `space-md` | 12 | `p-3` / `gap-3` | `mb-space-md`、`p-space-md` | 卡片内主间距、相邻卡片、紧凑卡内边距 |
| `space-lg` / `space-xl` | 20 / 28 | `p-5` / `p-7` | `space-y-space-lg`、`space-y-space-xl` | 子区块之间 20；页面级区块之间（Hero → 推荐 → 战报）28 |
| `gutter` | 16 | `p-4` / `p-gutter` | 卡片 `p-gutter` | 卡片标准内边距、弹窗与抽屉内边距 |
| `margin` | 16 | `mx-4` | 内容区左右外边距 | 页面内容区左右外边距（折叠屏/平板随断点增大） |
| `space-2xl` / `space-3xl` | 40 / 56 | `p-10` / `p-14` | — | 平板与折叠屏的区块间距、Hero 上下留白（扩展档） |

> `gutter` 与 `margin` 在手机上同为 16vp 但语义不同：`margin` 是屏幕边缘到内容区的距离（随断点变），`gutter` 是容器内边距（跨断点恒定 16vp，不放大，以保持信息密度）。

## 4. 栅格与断点

### 4.1 列定义

- 手机：**4 列**，列间距 12vp，外边距 16vp；折叠屏展开 / 平板：**8 列**，列间距 12/16vp，外边距 24/32vp。
- 单列内容（卡片）跨满全部列；并排双卡时各跨 2 列（手机）/ 4 列（≥600vp）。

### 4.2 断点表

| 断点 | 视口宽 | 列数 | 外边距 `margin` | 列间距 | 单列宽 | 典型设备 |
| --- | --- | --- | --- | --- | --- | --- |
| compact-s | 320vp | 4 | 16 | 12 | 63 | 小屏手机（最小支持宽） |
| compact | 360vp（基准） | 4 | 16 | 12 | 73 | 主流手机 |
| compact-l / xl | 390 / 420vp | 4 | 16 | 12 | 80.5 / 88 | 大屏与超大屏手机 |
| medium | 600vp | 8 | 24 | 12 | 58.5 | 折叠屏展开、小平板 |
| expanded | 840vp | 8 | 32 | 16 | 83 | 平板横屏 |

### 4.3 ArkUI 实现

```ts
GridRow({ columns: { xs: 4, md: 8 }, gutter: { x: 12, y: 12 }, margin: { x: 16 } }) {
  GridCol({ span: { xs: 4, md: 4 } }) { ProblemCard() }
  GridCol({ span: { xs: 4, md: 4 } }) { ProblemCard() }
}
```

单列卡片流不需要 `GridRow`，直接用 `Column` + `padding({ left: 16, right: 16 })`；只有"并排卡片 / 双栏 / 宽屏"才引入栅格，避免为 1 列付栅格成本。

## 5. 垂直节奏

| 关系 | 间距 | 令牌 | 说明 |
| --- | --- | --- | --- |
| 卡片内标题 → 副标题 | 4 | `space-xs` | 视觉同一组，不能到 8 |
| 卡片内标签行 → 操作行 | 12 | `space-md` | 原型 `mb-space-md` |
| HUD 内部（眉标 / 大数字 / 周条） | 8–12 | `space-sm` / `space-md` | C-04、C-26 固定值 |
| 相邻卡片（同列表 / 同组） | 8 | `space-sm` | 列表项之间 |
| 相邻卡片（跨组） | 12 | `space-md` | 主推荐 → 竞赛挑战 |
| 区块之间 | 20–28 | `space-lg` / `space-xl` | 常规 20；Hero → 热力图 → 队列用 28 |
| 页面首元素距 AppBar | 12 | `space-md` | 原型 `main>:first-child` 归零后补 12 |
| 滚动内容底部留白 | 16 + safe + 64 | — | 防最后一张卡被 TabBar 遮挡（§7.2） |

规则：**同一页面的区块间距必须统一**——要么全 20，要么全 28；混用会让"今日核心推荐"看起来比"竞赛挑战"高一级。原则：区块间距 > 区块内卡片间距的 2 倍，用比例而非绝对值建立层级。

## 6. 圆角令牌表

| 令牌 | vp | Tailwind 对应 | 用途 |
| --- | --- | --- | --- |
| `radius-heat` | 2 | `rounded-sm` | 热力块（C-32，10×10vp + 2vp 圆角，对齐 GitHub 贡献图） |
| `radius-tag` | 4 | `rounded` | 标签、难度徽标（C-14）、平台徽记、微标签 |
| `radius-xs` | 6 | `rounded-md` | 小控件：周条 28vp 徽记、32vp 图标底、月份格 |
| `radius-sm` | 8 | `rounded-lg` | 按钮（C-09 / C-10）、Toast（C-18）、搜索框、输入框 |
| `radius-md` | 12 | `rounded-xl` | 卡片（全部）、AppBar 图标底（C-01）、弹窗（C-16）、抽屉顶部（C-17） |
| `radius-full` | 999 | `rounded-full` | 状态胶囊、筛选胶囊、头像、进度条端点 |

嵌套规则：

1. 内层圆角 = 外层圆角 − 内边距，最小 4vp（12vp 卡片内按钮用 8vp、标签用 4vp）；禁止 12vp 卡片内再套 12vp 卡片（同心圆角会露出 4 个错位的"月牙"），内层必须降档到 8vp 或 4vp。
2. 胶囊（999vp）只用于状态徽记、筛选胶囊与头像；按钮一律 8vp，卡片一律 12vp（原型 C-04 内"待完成 1/2"胶囊为正确用法）。
3. 进度条（C-15）轨道与填充端点均为 999vp，高度 2–6vp，禁止方形端点。
4. **16vp 为唯一例外**：仅 C-39 空态图标容器（64×64vp）使用，不作为通用容器圆角；出现第二处即视为违规。

## 7. 页面骨架与安全区

### 7.1 骨架

```text
 ┌──────────────────────────────────────────┐
 │ C-01 AppBar         64vp  眉标10/14+标题20/28│
 ├──────────────────────────────────────────┤
 │←16→      ┌────────────────────────────┐   │
 │         │ C-04 Hero  16 / radius 12   │   │
 │         └────────────────────────────┘   │
 │                    ↕ 12                   │
 │         ┌────────────────────────────┐   │
 │         │ 主推荐卡（C-06） 16 / 12    │   │
 │         └────────────────────────────┘   │
 │                    ↕ 28（区块间距）        │
 ├──────────────────────────────────────────┤
 │ C-02 BottomTabBar 64vp 4 等分 / navigation bar safe-bottom │
 └──────────────────────────────────────────┘
```

尺寸契约：AppBar 上方的状态栏区（safe-top ≈28vp）不绘制业务内容，AppBar 固定 **64vp**（不含 safe-top）、TabBar 固定 **64vp**（不含 safe-bottom）、内容区左右外边距 **16vp**、滚动区高度 = 屏高 − 64 − safeTop − 64 − safeBottom。四个一级 Tab 共用同一骨架，区块顺序见[今日打卡页](../03-页面设计/02-今日打卡页.md)与[页面总览与原型映射](../03-页面设计/01-页面总览与原型映射.md)。

### 7.2 安全区实现

```ts
// EntryAbility.onWindowStageCreate
windowStage.getMainWindow().then((win: window.Window) => {
  win.setWindowLayoutFullScreen(true);
  const top = win.getWindowAvoidArea(window.AvoidAreaType.TYPE_SYSTEM).topRect.height;
  const bottom = win.getWindowAvoidArea(window.AvoidAreaType.TYPE_NAVIGATION_INDICATOR).bottomRect.height;
  AppStorage.setOrCreate<number>('safeTop', px2vp(top));
  AppStorage.setOrCreate<number>('safeBottom', px2vp(bottom));
  win.on('avoidAreaChange', () => { /* 折叠/旋转时重算并写回 */ });
});
// 页面：@StorageProp('safeTop') / @StorageProp('safeBottom')
Column() {
  AppBar()                                    // .height(64)
  Scroll() { PageContent() }.layoutWeight(1).scrollBar(BarState.Off)
    .padding({ left: 16, right: 16, bottom: this.safeBottom + 64 + 16 })
  BottomTabBar()                              // .height(64 + safeBottom)
}.padding({ top: this.safeTop }).width('100%').height('100%')
```

等价原型写法：`pt-safe` = `.padding({ top: safeTop })`，`pb-safe` = `.padding({ bottom: safeBottom })`。**禁止**在 AppBar 内部再用 `expandSafeArea` 叠加一次，会导致顶部空白翻倍。滚动与遮挡：内容区 `padding-bottom = safeBottom + 64 + 16`；TabBar 作为 `Column` 最后一个子节点，若改用 `Stack` 悬浮必须给滚动容器补偿同样的底部内边距；滚动条一律隐藏（`BarState.Off`），不做滚动位置指示器。

## 8. 卡片内部结构

### 8.1 结构解剖（以主推荐题目卡为例）

```text
┌──────────────────────────────────────────┐
│ [平台徽记4] [难度徽标4]        #LC-206     │ ← 行高 20，元素间 8
│ ↕8                                      │
│ 反转链表                       headline-sm│ ← 20/28
│ ↕4                                      │
│ Reverse Linked List              body-sm  │ ← 12/18
│ ↕12                                     │
│ [标签][标签][标签]               行高 24  │
│ ↕12                                     │
│ [ 去题库做题 ] 8vp [ 完成打卡 40vp ]      │
│ ↕16                                     │
└──────────────────────────────────────────┘
```

### 8.2 内边距选择

| 内边距 | 适用组件 | 理由 |
| --- | --- | --- |
| **16vp**（`gutter`） | C-04 Hero、主推荐卡（C-06）、弹窗（C-16）、抽屉（C-17）、资料卡（C-31） | 主内容卡，留白即层级 |
| **12vp**（`space-md`） | 列表卡、题目行（C-24）、设置行（C-36）、紧凑卡、HUD 内嵌统计格 | 高密度列表，12vp 可多容纳一行信息 |
| **8vp**（`space-sm`） | 仅内嵌小块：周条徽记容器、统计小格 | 不再向内嵌套内容 |

同一列表内**必须统一**：今日页所有卡片 16vp，题单矩阵列表所有卡片 12vp。混用会让左右文字边界错位 4vp，肉眼可见。

### 8.3 标题—正文—操作三段间距

| 段间 | 间距 | 说明 |
| --- | --- | --- |
| 眉标/徽记 → 标题 | 8 | 分类与名称不同组 |
| 标题 → 正文（副标题） | 4 | 强关联，同一视觉组 |
| 正文 → 标签行 | 12 | 换组 |
| 标签行 → 操作行 | 12 | 换组 |
| 操作行内部按钮间 | 8 | 并排等宽，`.layoutWeight(1)` 平分 |
| 操作行 → 卡底 | 16（随内边距） | 不额外加 margin |

## 9. 触控热区

所有可点击元素的**热区 ≥ 44×44vp**（不符合时用 `responseRegion` 扩，而非放大视觉尺寸）。

| 控件 | 视觉尺寸 | 热区 | 实现 |
| --- | --- | --- | --- |
| 主/次按钮（C-09 / C-10） | 高 40（卡内）/ 44（页面级） | 44 | 卡内按钮 `.responseRegion({ x: 0, y: -2, width: '100%', height: 44 })` |
| 图标按钮（C-11） | 32 / 40 | 44×44 | 同上，`x`/`width` 按需外扩 |
| TabBar 项（C-02） / 筛选胶囊（C-12） | 48 / 28–32 | 48 / 44 | TabBar 已达标；胶囊上下各外扩 6–8vp |
| 列表行（C-24 / C-36） | 60 起（随内容） | 整行 | 行本身即可点击，内部箭头不单独响应 |
| 热力块（C-32） | 10×10 | 不单独响应 | 长按整块区域触发日期明细，单块不设热区 |

相邻热区**不得重叠**：并排按钮间距 8vp 时上下各扩 2vp 是正确的；扩到 6vp 就会误触相邻按钮。

## 10. 列表项高度标尺

| 高度 | 结构 | 适用 |
| --- | --- | --- |
| **56vp** | 单行：32vp 图标底 + 14fp 标题（垂直居中） | 无副标题的设置行、筛选行、紧凑榜单行 |
| **72vp** | 双行：14fp 标题 + 12fp 副标题/时间戳 | 默认列表项、题目行、带说明的设置行 |
| **96vp** | 双行 + 右侧操作，或三行（名次/头像/名称 + 指标） | 比赛卡、好友榜行（C-29 / C-35）、带进度条的题单行 |

新建列表项只允许在这三档内选择，且同一列表只用一档；列表项内边距由高度反推，不单独设置。已在组件规范中定死行高的组件优先于本表：C-35 榜单行 52vp、C-36 设置行 60vp、C-25 / C-38 64vp。

## 11. 多设备适配策略

| 形态 | 断点 | 列数 | 布局变化 | 注意事项 |
| --- | --- | --- | --- | --- |
| 手机竖屏 | < 600vp | 4 | 单列卡片流（基准稿 360vp） | v1.0 唯一必须交付的形态 |
| 折叠屏展开 | 600–839vp | 8 | 卡片可两列（各 span 4）；热力图一屏显示近 26 周 | 内屏近方形，Hero 数字改用 `headline-xl` 40fp |
| 平板 | ≥ 840vp | 8 | 两栏：左 480vp 列表 + 右详情区，栏间距 24vp | 详情默认选中首项；TabBar 保留（侧边导航为 v2） |
| 手机横屏 | 高 < 600vp | — | **锁定竖屏**（`module.json5` 中 `orientation: "portrait"`） | v1.0 不提供横屏布局，避免"半屏空白" |

适配原则：**只放大留白，不放大字号**——跨断点变化的只有外边距（16 → 24 → 32）与列数；折叠屏切换必须监听 `avoidAreaChange` 与窗口尺寸变化并重排，禁止依赖重启；任何断点下单行可交互元素 ≤ 6 个，超出改为横向滚动。

## 12. 布局反例

| 反例 | 问题 | 正确做法 |
| --- | --- | --- |
| 用 `marginTop(13)` 手写间距 | 与令牌脱节，改版必错位 | 用 §3 令牌，由容器 `space` 统一给 |
| 同一列表卡片 padding 12/16 混用 | 左右文字边界错位 4vp | 同一列表统一 12 或统一 16 |
| 四列布局里塞 5 个筛选胶囊 | 挤压变形或溢出 | 横向滚动 + `scrollSnapAlign` |
| 滚动区底部不留白 | 最后一张卡被 TabBar 遮住 | `padding-bottom = safeBottom + 64 + 16` |
| 固定 `.height()` 承载多行文本 | 系统大字号下裁切 | `minHeight` + 行高 × 行数 |
| 页面根 `Column` 加左右 padding | TabBar/AppBar 被一并缩进 | padding 只加在滚动内容容器上 |
| 用 `Grid` 做长列表 | 无法懒加载，滚动掉帧 | `List` + `LazyForEach` |
| 视觉按钮 28vp 且不外扩热区 | 热区不足 44vp，误触率高 | 保持视觉尺寸，用 `responseRegion` 扩到 44 |
