# 设计令牌规范

## 1. 目的与适用范围

本文档定义 CodeStreak 全部**原子级视觉变量**（颜色、表面、文本、描边、状态色、平台色、难度色）的唯一权威取值，并规定其命名方式、资源落地方式与使用约束。

- 适用范围：HarmonyOS 客户端（ArkTS/ArkUI）、后续 Web 端、设计稿、原型 HTML、对外截图与物料。
- **本文件与原型冲突时以本文件为准**；与 `docs/产品原型/algorithmic_precision/DESIGN.md`（下称"原始设计说明"）冲突时的裁决记录见第 10 节，完整差异清单见 [原型差异与设计裁决](../06-附录/01-原型差异与设计裁决.md)。
- 尺寸类令牌（字号、间距、圆角、栅格）分别见 [字体与排版规范](03-字体与排版规范.md)、[布局栅格与间距规范](04-布局栅格与间距规范.md)；本文只负责**色彩**。

> 关键前提：项目中 `docs/产品原型/codestreak_*/code.html` 内联的 Tailwind 主题才是原型**实际渲染**的颜色，原始设计说明中的 HEX 多为描述性文案。本规范的取值以**实际渲染值**为基线统一定义，避免"文档一套、界面一套"。

## 2. 令牌分层与命名规则

### 2.1 三层结构

| 层级 | 作用 | 是否可被业务代码直接引用 | 示例 |
| --- | --- | --- | --- |
| Primitive 基础色板 | 纯色值，无语义 | 禁止 | `#FFA116` |
| Semantic 语义令牌 | 描述用途，随主题切换 | **推荐** | `cs.color.primary` |
| Component 组件令牌 | 绑定具体组件状态 | 仅组件内部 | `cs.color.tabbar.active` |

### 2.2 命名语法

```
cs . <类别> . <角色> [ . <变体> ]

cs.color.surface.container.high    → 组件容器背景（高一层）
cs.color.text.primary              → 主文本
cs.color.state.success             → 成功/AC 状态
cs.color.platform.codeforces       → Codeforces 平台识别色
```

落地映射（同一令牌的三种写法必须一一对应）：

| 载体 | 写法 | 示例 |
| --- | --- | --- |
| 设计/文档 | `cs.color.surface.low` | 本文表格 |
| HarmonyOS 资源 | `cs_color_surface_low` | `resources/base/element/color.json` |
| ArkTS 常量 | `CsColor.SURFACE_LOW` | `commons/constants/DesignTokens.ets` |

### 2.3 硬性规则

1. 业务代码**不得出现裸 HEX**；只允许 `$r('app.color.cs_color_*')` 或 `CsColor.*`。
2. 令牌名**不得包含颜色词**（`amber`、`slate`、`blue` 禁止）、**不得包含数字序号**（`primary_2` 禁止）。
3. 新增令牌必须同时更新本节表格、`color.json`、`DesignTokens.ets` 与本文件版本号。
4. 语义令牌改名视为**破坏性变更**，需给出旧名 → 新名的迁移表。

## 3. 主题基线

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 主题数量 | **单一暗色主题** | v1.0 不提供浅色主题 |
| 系统色模式 | 强制 `COLOR_MODE_DARK` | `EntryAbility.onWindowStageCreate` 中设置 |
| 启动窗口背景 | `#10141A` | 当前工程为 `#FFFFFF`，**必须修正**，否则冷启动闪白 |
| 状态栏/导航栏图标 | 浅色（light content） | 与深色画布一致 |
| 页面底色 | `cs.color.surface` = `#10141A` | 全 App 统一，禁止分区改底色 |

## 4. 色彩令牌全表

### 4.1 表面与画布（Surface）

| 令牌 | HEX | 语义 | 典型用途 |
| --- | --- | --- | --- |
| `cs.color.surface` | `#10141A` | 画布底色 | 页面根背景、启动窗口 |
| `cs.color.surface.dim` | `#10141A` | 遮罩基准 | 弹层遮罩（80% 透明度） |
| `cs.color.surface.bright` | `#353940` | 提亮表面 | 按压态、悬浮高亮行、"当前用户"榜位 |
| `cs.color.surface.lowest` | `#0A0E14` | 最低表面 | 倒计时数字格、进度条槽、内嵌凹陷区 |
| `cs.color.surface.low` | `#181C22` | 低表面 | 区块货架、列表卡片、搜索框 |
| `cs.color.surface.container` | `#1C2026` | 容器 | 主卡片、设置行、矩阵卡 |
| `cs.color.surface.high` | `#262A31` | 高表面 | 主推荐卡、比赛卡、弹窗、HUD |
| `cs.color.surface.highest` | `#31353C` | 最高表面 | 徽标底、图标底、次按钮、标签底 |

**层级关系（由深到浅）**：`lowest → low → container → high → highest → bright`。相邻两级对比不足以单独表达层级时，叠加 `cs.color.border.subtle` 描边。

### 4.7 平台识别色（裁决后唯一映射）

| 平台 | 主令牌 | HEX | 底色写法 | 文本写法 |
| --- | --- | --- | --- | --- |
| LeetCode | `cs.color.platform.leetcode` | `#FFA116` | `primary.container` / `primary.container@20%` | `primary.on-container` / `primary` |
| Codeforces | `cs.color.platform.codeforces` | `#BFD2FF` | `tertiary.container@20%` | `tertiary` |
| AtCoder | `cs.color.platform.atcoder` | `#4EDEA3` | `secondary.container@20%` | `secondary` |
| 洛谷 Luogu | `cs.color.platform.luogu` | `#FFB4AB` | `error.container@20%` | `error` |
| ICPC / CCPC | `cs.color.platform.collegiate` | `#FFA116` / `#00A572` | 实心底 | 对比色文本 |

> `@20%` 表示以 20% 不透明度叠加在父表面上的浅底，等价 Tailwind 的 `bg-xxx/20`。

**tint 与 solid 的使用边界**（裁决 D-40）：

| 变体 | 外观 | 允许场景 |
| --- | --- | --- |
| tint（默认） | 平台色 @20% 底 + 平台色文本 | 列表行徽标（C-24）、筛选控件（C-22）、标签（C-12） |
| solid（实心） | 平台色实心底 + 对应 `on-solid` 文本 | **仅限** C-06/C-07 焦点卡首行徽标、C-29 比赛卡平台徽标、ICPC/CCPC 赛事徽标 |

solid 文本必须使用 `primary.on-container`（琥珀，6.5:1）、`secondary.on-solid`、`tertiary.on-solid`、`error.on-solid` 四者之一；**禁止**在实心底上使用 `text.primary` 或白色。

| 星级 | 语义 | 令牌 | HEX | 进度条底 |
| --- | --- | --- | --- | --- |
| ★1 | 入门 / 语法与模拟 | `cs.color.difficulty.1` | `#4EDEA3` | `secondary.container` |
| ★2 | 基础 / 基础数据结构 | `cs.color.difficulty.2` | `#4EDEA3` | `secondary` |
| ★3 | 进阶 / 动态规划与图论 | `cs.color.difficulty.3` | `#FFA116` | `primary.container` |
| ★4 | 困难 / 高级算法与数论 | `cs.color.difficulty.4` | `#FFB867` | `primary.fixed-dim` |
| ★5 | 挑战 / 竞赛压轴与黑题 | `cs.color.difficulty.5` | `#FFB4AB` | `error` |

- 星级→颜色的映射**只表达难度**，与平台色解耦。原型中"难度徽标取平台主色"的写法不采纳，见第 10 节 D-04。
- 允许 0.5 星粒度（如 `★2.5`），取相邻两星中**较低星级**的颜色。

## 5. 表面层级与抬升规则

| 层级 | 表面令牌 | 描边 | 使用场景 |
| --- | --- | --- | --- |
| L0 画布 | `surface` | 无 | 页面根 |
| L1 货架 | `surface.low` | `border.subtle` 1px | 区块分组、列表行、搜索框 |
| L2 卡片 | `surface.container` | 无（靠明度差） | 通用内容卡 |
| L3 焦点卡 | `surface.high` | 可选 `primary@25%` 1px | 主推荐、比赛卡、HUD、弹层 |
| L4 最高 | `surface.highest` | 无 | 徽标底、图标底、次按钮 |

规则：

1. **不靠阴影抬升**。全局仅允许三类阴影：底部标签栏上方 `0 -1px 12px rgba(0,0,0,0.35)`、滚动后的 AppBar 底缘 `0 1vp 8vp rgba(0,0,0,0.25)`（仅 `scrollY > 8vp` 时出现）、弹层 `shadow-2xl` 级；其余一律用表面明度 + 1px 描边表达层级。
2. 光晕（`primary.glow`）**只允许**出现在 `Streak Hero`、`Countdown HUD`、`Celebration Modal` 三处，且不得叠加第二个光斑。
3. 同一屏内表面层级跳跃不得超过 2 级；需要强调时优先加 1px 描边而非跳级。
4. 禁止纯黑（`#000000`）与纯白（`#FFFFFF`）。

## 6. 使用约束

### 6.1 色彩配额

| 色彩 | 面积配额 | 允许 | 禁止 |
| --- | --- | --- | --- |
| 琥珀 | ≤ 屏面积 15% | 连续天数、今日徽记、主按钮、选中 Tab、里程碑 | 大面积背景、正文、装饰性渐变块 |
| 翡翠 | ≤ 10% | AC/已打卡、完成率、正向增量、热力图 | 主按钮底、"未开始"状态 |
| 天蓝 | ≤ 8% | 分析图标、平台标识、次级链接 | 状态成功/失败语义 |
| 告警红 | ≤ 3% | ★5、洛谷、错误、错过提醒 | 普通卡片描边、装饰 |

### 6.2 Do / Don't

| Do | Don't |
| --- | --- |
| 用表面明度差 + 1px 描边表达层级 | 用大面积高斯阴影堆叠"卡片感" |
| 主按钮：琥珀底 + `#482900` 文案 | 琥珀底 + 白字（对比度不足 3:1） |
| 元信息用 `text.tertiary`（5.8:1） | 用 `text.ghost` 承载可读信息（2.0:1） |
| 平台色只出现在平台徽标/筛选胶囊 | 用平台色给整张卡上色 |
| 难度色阶表达难度 | 用平台色表达难度（同一平台难度不可辨） |

## 9. 对比度与可访问性

实测相对对比度（前景 vs `#10141A` 画布）：

| 组合 | 比值 | 判定 |
| --- | --- | --- |
| `text.primary` / 画布 | ≈ 14.3:1 | AAA |
| `text.secondary` / 画布 | ≈ 10.9:1 | AAA |
| `text.tertiary` / 画布 | ≈ 5.8:1 | AA（正文 12fp 亦合格） |
| `secondary` / 画布 | ≈ 10.8:1 | AAA |
| `primary.container` / 画布 | ≈ 9.1:1 | AAA |
| `primary.on-container` / `primary.container` | ≈ 6.5:1 | AA+ |
| `primary.on-container-alt` / `primary.container` | ≈ 4.5:1 | AA 边界（仅大字号） |
| `text.ghost` / 画布 | ≈ 2.0:1 | 不合格，**仅装饰** |

强制要求：

1. 任何承载信息的文本对比度 ≥ 4.5:1；≥ 18fp 或 ≥ 14fp/700 可放宽至 3:1。
2. **不得仅以颜色区分状态**（已打卡/待做/未开始）：必须同时提供图标或文案（原型已用 `check_circle`/`schedule` 图标 + 文本，保持）。
3. 热力图必须提供图例与当日摘要文本（原型已有"今天已打卡 3 题"），满足色觉障碍用户。
4. 焦点态使用 1px `primary.container` 描边 + 外扩 2vp，不使用颜色闪烁。

## 10. 与原始设计说明（DESIGN.md）的差异裁定

| 编号 | 项 | 原始设计说明 | 本规范（裁定） | 理由 |

/** 透明度叠加：把 #RRGGBB 转成带 alpha 的 #AARRGGBB */
export function withAlpha(hex: string, alpha: number): string {
  const a = Math.round(Math.min(1, Math.max(0, alpha)) * 255).toString(16).padStart(2, '0');
  return `#${a}${hex.replace('#', '').toUpperCase()}`;
}

/** 难度色阶：1..5，0.5 粒度取较低星级的颜色 */
export function difficultyColor(norm: number): string {
  if (norm < 3) return CsColor.SECONDARY;            // ★1、★2 共用翡翠
  if (norm < 4) return CsColor.PRIMARY_CONTAINER;    // ★3
  if (norm < 5) return CsColor.PRIMARY_FIXED_DIM;    // ★4
  return CsColor.ERROR;                              // ★5
}

### 11.4 机器可读导出

[`assets/design-tokens.json`](assets/design-tokens.json) 是本规范的结构化镜像（Design Tokens 社区格式），用于设计稿变量同步、代码生成与对比度校验脚本。

- **唯一性**：JSON 与本文冲突时以本文为准，JSON 视为派生数据。
- **同步机制**：修改令牌必须同时改本文表格、`color.json`、`DesignTokens.ets`、`design-tokens.json` 四处，缺一视为未完成。
- **可用命令**（示例，校验 JSON 与 `color.json` 取值一致）：

```powershell
$tokens = Get-Content 'docs/02-设计规范/assets/design-tokens.json' -Raw -Encoding UTF8 | ConvertFrom-Json
$colors = (Get-Content 'entry/src/main/resources/base/element/color.json' -Raw -Encoding UTF8 | ConvertFrom-Json).color
$map = @{ 'surface.canvas' = 'cs_color_surface'; 'primary.container' = 'cs_color_primary_container' }
foreach ($k in $map.Keys) {
  $node = $tokens.color; foreach ($seg in $k.Split('.')) { $node = $node.$seg }
  $res = ($colors | Where-Object { $_.name -eq $map[$k] }).value
  if ($node.'$value' -ne $res) { Write-Output "MISMATCH $k : $($node.'$value') vs $res" }
}
```
