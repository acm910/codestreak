# 设计原则与视觉风格

## 1. 目的与范围

本文定义 CodeStreak 的**设计判断依据**：品牌调性、六条设计原则、视觉风格边界、禁止项、语气与图标策略。它回答"该不该做、做成什么气质"，不重复具体取值。

- **负责**：原则、风格定性、禁止项、文案语气、图标与插画策略、评审口径。
- **不负责**：颜色取值见[设计令牌规范](02-设计令牌规范.md)（唯一权威 `cs.color.*`）；字号与字族见[字体与排版规范](03-字体与排版规范.md)；间距、栅格、圆角见[布局栅格与间距规范](04-布局栅格与间距规范.md)；动效时长与交互态见[交互与动效规范](06-交互与动效规范.md)；组件结构与编号见[组件规范](05-组件规范.md)。
- **适用对象**：HarmonyOS 客户端（ArkTS/ArkUI）、后续 Web 端、设计稿、原型 HTML 与对外截图物料。
- **冲突裁决**：与其他规范文档冲突时，颜色以 02-02 为准，尺寸以 04 为准；本文与原型冲突时以本文 + 02-02 为准。

> 一句话定位：**CodeStreak 是竞赛选手与求职者的"连胜作业台"**，不是学习社区、不是打卡游戏、不是题解阅读器。

## 2. 品牌调性与情绪关键词

| 关键词 | 英文 | 含义 | 界面证据 | 出现即失分 |
| --- | --- | --- | --- | --- |
| 专注 | Focus | 一屏只服务一个任务 | 每页唯一琥珀实心主操作 | 同屏两个并列主按钮 |
| 动量 | Momentum | 连胜、补题、进度是可累计的量 | C-04 首屏大数字 + 周条 | 把连胜做成徽章墙 |
| 精确 | Precision | 尺寸、对齐、数字宽度可预测 | 4vp 网格、等宽数字 | 手工像素微调、数字跳动 |
| 克制 | Restraint | 颜色与动效本身也是信息 | 色彩配额（02-02 §6.1） | 庆祝动效超过 320ms |
| 可信 | Trust | 每个数字有口径、有时间戳 | 数据行 + 同步状态 | 百分比无分母、无更新时间 |
| 竞技 | Arena | 有对手、有名次、有 Rating | 榜单、赛历、Rating 标签 | 积分商城、抽奖、养成宠物 |

**三个必须回答的问题**（首屏 3 秒内）：今天还差什么？连胜是否安全？下一步点哪里？

**反向定位（明确不做）**：不做社交 Feed 流、不做课程售卖、不做宠物养成、不做需要连续动画的娱乐化庆祝。

## 3. 六条设计原则

编号 P1–P6 仅作引用索引；冲突时按 **P1 > P5 > P2 > P4 > P3 > P6** 的顺序让位（P1 最高）。

### 3.1 P1 信息优先（Information First）

| 维度 | 规定 |
| --- | --- |
| 是什么 | 首屏必须以信息与可操作卡为主体；任何装饰不得挤占信息位。 |
| 为什么 | 目标用户日均打开 1–3 次、单次停留 < 20 秒，界面是"核对工具"而非"浏览内容"。 |
| 怎么做 | ① 每页第一条内容必须是可操作卡（C-04 / C-06）；② 每 100vp 垂直高度至少承载 1 个信息块；③ 区块标题右对齐必须有眉标给出口径（如 `PRIMARY TARGET`、`WEEK 42`）；④ 空态必须同时给原因与下一步动作（C-39）。 |
| 反例 | 首屏放品牌 Slogan 或插画空态；"今日推荐"沉到第二屏；卡片右上角纯装饰渐变块压住标题。 |

### 3.2 P2 即时反馈（Instant Feedback）

| 维度 | 规定 |
| --- | --- |
| 是什么 | 任何可点击元素在 90ms 内出现按压反馈；状态改变先本地生效（乐观更新），网络失败再回滚。 |
| 为什么 | 打卡是一次"低成本高情绪"的动作，等待会直接摧毁连胜心理；延迟感 = 数据不可信。 |
| 怎么做 | ① 按压态 `translateY(1vp)` 或 `scale(0.98)`，90ms（见 06）；② 点击"完成打卡"立即把按钮切为"已打卡 AC"禁用态并写本地缓存，再后台同步；③ 失败用 C-18 Toast + 可重试入口，不弹模态；④ 同步中显示"上次成功同步 xx:xx"。 |
| 反例 | 点击后按钮无变化直到接口返回；失败只弹一个"网络异常"（无对象、无下一步）。 |

### 3.3 P3 机械精确（Mechanical Precision）

| 维度 | 规定 |
| --- | --- |
| 是什么 | 所有尺寸落在 4vp 网格；同层级组件同尺寸、同圆角；所有数字等宽。 |
| 为什么 | "仪表盘气质"来自可预测性——第 2 张卡与第 1 张卡的对齐误差会直接被读成"产品不专业"。 |
| 怎么做 | ① 间距只用令牌（04 §3），禁止 `padding(13)`、`margin(7)`；② 同类卡片圆角只能取 12vp，标签 4vp；③ 数字容器统一 `fontFeature('"tnum" 1')`（03 §5）；④ 图标与文本基线用 2vp 光学修正，不进主网格。 |
| 反例 | 同一屏出现 8/10/12 三种卡片圆角；倒计时每秒刷新时数字宽度变化导致整行抖动。 |

### 3.4 P4 克制的色彩（Restrained Color）

| 维度 | 规定 |
| --- | --- |
| 是什么 | 颜色只做语义，不做装饰；琥珀是唯一"行动色"，配额见 02-02 §6.1。 |
| 为什么 | 暗色界面里高饱和色面积稍大就变成噪声，连胜数字会与"新建""筛选"抢注意力。 |
| 怎么做 | ① 一屏内琥珀**实心块 ≤ 1 个**（主操作），其余琥珀只做文本/图标/1vp 描边；② 翡翠只表达"已完成"，不用于可点击；③ 平台色仅出现在徽标与筛选胶囊，不给整卡上色；④ 新增颜色必须走 02-02 变更流程。 |
| 反例 | 今日页同时出现"求职高频"实心胶囊 + "全部"难度胶囊 + 打卡按钮 + 列表"去打卡"四处琥珀实心（见原型 codestreak_2），需降级为描边/文本态。 |

### 3.5 P5 可核对的数据（Verifiable Data）

| 维度 | 规定 |
| --- | --- |
| 是什么 | 每个统计数字必须能回答"什么口径、什么时间、来自哪个平台"。 |
| 为什么 | 竞技用户对数据极敏感，一次对不上就永久失信；也是"可信"关键词的落地方式。 |
| 怎么做 | ① 指标三件套：名称 + 时间范围 + 来源；② 无口径文案必须补口径（原型"击败 89% 工程师"需补"近 30 天活跃用户"）；③ 数字可点开明细（C-17 底部抽屉）；④ 热力图必须带图例与当日摘要；⑤ 同步失败显示"上次成功同步时间"。 |
| 反例 | 百分比无分母；热力图无图例；平台同步 ping 无时间戳；"历史最长 64 天"不注明统计起点（口径应为生涯最长）。 |

### 3.6 P6 零装饰惯性（Zero Decoration Inertia）

| 维度 | 规定 |
| --- | --- |
| 是什么 | 新增任何视觉元素前必须通过"三问"，否则不添加。 |
| 为什么 | 高密度界面里，装饰的成本不是"不好看"，而是"吃掉一条信息的位置"。 |
| 怎么做 | 三问：① 它承载什么信息？② 去掉后用户会损失什么？③ 去掉后布局是否更清楚？三问皆无答案即删除；光斑（`primary.glow`）仅允许 C-04、C-26、C-16 三处（02-02 §5 规则 2）。 |
| 反例 | 卡片右下角装饰斜纹、双层投影、图标加彩色描边框、用 `🔥` 等 emoji 代替图标（原型庆祝文案"29 DAYS 🔥"须替换为 `local_fire_department` 图标）。 |

## 4. 视觉风格定义

风格命名为 **Modern Dark Terminal Minimalist（现代暗色终端极简）**：以深色多层表面为底、1vp 描边定义边界、等宽字体承载元信息、单一琥珀色驱动行动，整体呈"高信息密度的竞技仪表盘"。判断某个界面是否"像 CodeStreak"，看三条：**表面是否靠明度分层、元信息是否等宽、琥珀是否只出现在行动点。**

| 对标参考 | 借鉴什么 | 不借鉴什么 | 落地到 CodeStreak |
| --- | --- | --- | --- |
| VS Code / Zed 编辑器 | UI 无衬线 + 代码等宽的双字体纪律；状态栏常驻元信息；命令面板式单入口；暗色但不冷蓝 | 多级侧栏树、编辑器标签页密度、语法高亮的多色噪点 | AppBar 64vp 常驻（C-01）；元信息统一 JetBrains Mono；设置页单列（C-36） |
| 金融终端 | 数字右对齐等宽、刷新不跳动、语义色固定（涨/跌/告警）、表格无斑马纹 | 满屏密集表格、闪烁报价、滚动跑马灯 | 倒计时四格对齐（C-26）；进度数字 tabular-nums；榜单列对齐（C-35） |
| GitHub 贡献图 | "5 档色阶 + 图例 + 当日摘要"三件套；10vp 方块 + 2vp 圆角 | 一年 53 周默认全展开（手机上过密）、纯绿单色系 | C-32 默认近 16 周、横向滚动看全年；图例与"今日已打卡 N 题"固定 |

## 5. 风格构成要素

| 要素 | 规定 | 落地引用 |
| --- | --- | --- |
| 深色多层表面 | 6 档 `cs.color.surface.*` 表达层级，同屏跨度 ≤ 2 级；画布唯一 `cs.color.surface` | 02-02 §4.1、§5 |
| 1vp 描边 | 需要边界时加 `cs.color.border.subtle` 1vp 内描边，不用阴影 | 02-02 §4.2 |
| 微标签 | 10fp 全大写、+0.5vp 字距、`cs.color.text.tertiary`，只做分类不承载正文 | 03 §9 |
| 等宽元信息 | 题目 ID、复杂度、时间、Rating、平台名一律 JetBrains Mono | 03 §2 |
| 单一强调色 | 琥珀 = 行动，翡翠 = 完成，天蓝 = 分析，告警红 = 风险 | 02-02 §6.1 |
| 直角优先 | 圆角 2/4/6/8/12vp；胶囊（999vp）仅状态徽记与头像 | 04 §6 |
| 无阴影抬升 | 抬升一律靠表面明度 + 1vp 描边；全站仅 TabBar 顶部、AppBar 滚动底影、弹层三处允许阴影（02-02 §5 规则 1 与 §7 的合并口径） | 02-02 §5、05 §3 |
| 高密度节奏 | 卡片间 8–12vp、区块间 20–28vp、卡片内边距 12/16vp | 04 §5、§8 |

## 6. 明确禁止项

| 禁止项 | 判定标准 | 替代表达 | 例外 |
| --- | --- | --- | --- |
| 玻璃拟态滥用 | 除 C-01/C-02 的 `@85%`、`@90%` 背景模糊与弹层遮罩外，出现任何 `blur` + 半透明卡片 | 用 `cs.color.surface.container` 实色 + 1vp 描边 | 仅 AppBar、TabBar、遮罩三处 |
| 多彩渐变 | 同一渐变出现 ≥ 3 个色相或非语义色过渡 | 单色填充，或 `primary.container → secondary` 两段渐变 | 仅题单封面卡进度条（02-02 §8.2） |
| 拟物投影 | 内阴影、多层投影、"浮起纸片"效果 | 表面明度差 + 1vp 描边 | 仅 TabBar 顶部、AppBar 滚动底影、弹层 |
| 圆润卡通 | 卡片圆角 > 12vp、按钮用胶囊、圆角表情符号 | 12vp 卡片 / 8vp 按钮 | 状态徽记与头像可用 999vp |
| 大面积纯黑 | 出现纯黑或纯白作为背景/文本（02-02 §5 规则 4） | 画布统一 `cs.color.surface`，文本用 `text.primary` | 无 |
| 彩色插画与照片 | 除用户头像外出现插画、3D 素材、实拍图 | 线性图标 + 文案 + 主按钮 | 头像（§8.3） |
| emoji 作图标 | 用 emoji 承担图标/状态语义 | Material Symbols Outlined 对应图标 | 无 |

## 7. 语气与文案风格（Tone of Voice）

### 7.1 四条基调

1. **短句**：一句话只做一件事，UI 文案 ≤ 24 汉字，按钮 ≤ 5 汉字。
2. **动词开头**：按钮用"动词 + 对象"（完成打卡、去题库做题、重试同步）。
3. **给数字**：涉及进度/时间一律给具体数值与单位（`距结束还有 2 天`，不写"即将结束"）。
4. **给下一步**：错误与空态必须包含"发生了什么 + 怎么办"，不允许只有结论。

称呼用"你"，不用"您"；不堆感叹号（全屏最多 1 个）；不用"亲/哦/啦/~"；不使用 emoji（庆祝用图标 + 文案）。

### 7.2 UI 文案示例表

| 场景 | 推荐文案 | 字数 | 说明 |
| --- | --- | --- | --- |
| 主按钮 | 完成打卡 | 4 | 动词 + 对象，明确结果 |
| 次按钮 | 去题库做题 | 5 | 说明跳转目标 |
| 完成后按钮 | 已打卡 AC | 5 | 过去式 + 结果，配合禁用态 |
| 危险操作 | 取消今日打卡 | 6 | 必须二次确认，按钮文案写清后果 |
| 空态标题 / 描述 | 今天还没有推荐 / 在题单矩阵中选一个目标平台，系统会在 06:00 生成推荐。 | 7 / 28 | 描述必须给触发条件 |
| 错误 | 同步失败：Codeforces 接口超时 / 重试 | 14 / 2 | 结构：发生了什么 + 动作 |
| 庆祝 | 打卡成功，连胜延续 | 9 | 不用感叹号，不用 emoji |
| 加载 | 正在同步 4 个平台… | 10 | 给对象与数量，不给"请稍候" |
| 破坏性确认 | 删除后不可恢复 | 7 | 只说后果，不劝阻 |

### 7.3 禁用表达

| 禁用 | 原因 | 替换 |
| --- | --- | --- |
| 操作成功 / 保存成功 | 无对象，用户不知道什么成功了 | 已同步至 4 个平台 |
| 暂无数据 | 只有结论，无下一步 | 今天还没有推荐 + 触发条件 |
| 请稍候 / 加载中… | 无时长、无对象 | 正在同步 LeetCode 榜单（约 3 秒） |
| 哎呀 / 出错了 | 无信息量、破坏专业感 | 同步失败：{原因} |
| 亲，加油哦 | 与竞技语气冲突 | 今天还差 1 题，加油不是方案，去打卡 |

## 8. 图标与插画策略

### 8.1 图标：Material Symbols Outlined

与原型保持同一图标族，避免二次绘制导致笔画粗细不一致。

| 尺寸 | 使用位置 | 说明 |
| --- | --- | --- |
| 16vp | 文本内联（`去题库做题 ↗`）、标签前缀 | 与 10–12fp 文本同基线，配 4vp 间距 |
| 18vp | 按钮内主图标、卡片内前导图标 | 按钮默认尺寸 |
| 20vp | 列表项前导（C-36）、搜索框 | 图标底容器 32vp（圆角 6vp） |
| 22vp | C-02 TabBar | 固定值，切换不缩放 |
| 24vp | 空态、庆祝弹窗（C-16） | 仅大场景，不用于列表 |

| FILL 规则 | 取值 | 适用图标 |
| --- | --- | --- |
| 默认线性 | `FILL 0` | 全部导航、操作、装饰类图标 |
| 状态强调 | `FILL 1` | `check_circle`、`task_alt`（已打卡/已完成）、`local_fire_department`（C-04 内）、`military_tech`（C-16）、`bookmark`（已收藏） |

- 图标颜色**继承文本令牌**（`.fontColor($r('app.color.cs_color_text_*'))`），仅状态图标可单独取 `secondary`/`primary.container`/`error`。
- 图标字重固定 400，禁止把图标加粗模拟选中；选中态用颜色 + 右侧 2vp 竖条或背景变化表达。
- 图标**不得作为唯一信息载体**：TabBar 图标必须配文案；状态图标必须配文案（02-02 §9.2）。
- 禁止：emoji、彩色图标、与 Material Symbols 混用的自定义 SVG、带投影的图标。

### 8.2 插画与照片

**不使用插画与照片**。空态统一按 C-39 落地：64×64vp 图标容器（圆角 16vp，`surface.low`）+ 32vp 线性图标（`text.tertiary`）+ 16fp 标题 + 12fp 说明 + 36vp 主按钮，四件套缺一不可。原因：插画会把首屏高度占满，与 P1 冲突；且难以在多语言/多尺寸下保持精度。

### 8.3 头像例外

头像是全站唯一允许的位图：

| 位置 | 尺寸 | 形状 | 缺省态 |
| --- | --- | --- | --- |
| C-01 AppBar 右侧 | 28vp | 圆形 | 姓名首字母（Space Grotesk 600 / 12fp）+ `surface.highest` 底 |
| C-35 好友榜行 | 32vp | 圆角 8vp | 同上，10fp |
| C-31 个人资料卡 | 56vp | 圆角 12vp | 同上，20fp |

尺寸与圆角以[组件规范](05-组件规范.md)各组件的尺寸表为准，本文只约束一条规则：**缺省态不使用插画头像**，用首字母块即可，避免引入额外素材与性别/人种默认形象争议。

## 9. 评审检查清单

- [ ] 首屏 3 秒能回答三个问题（§2），且第一条是可操作卡。
- [ ] 同屏琥珀实心块 ≤ 1，色彩面积符合 02-02 §6.1 配额。
- [ ] 所有颜色引用均为 `cs.color.*`，无裸 HEX。
- [ ] 元信息（ID、时间、复杂度、Rating）为等宽字体，数字开启 tabular-nums。
- [ ] 无玻璃拟态卡片、多彩渐变、拟物投影、emoji 图标。
- [ ] 每个统计数字可回答"口径 + 时间 + 来源"。
- [ ] 文案为"动词 + 对象"，空态与错误均含下一步。
