# 工程结构与模块划分

## 1. 目的与原则

本文把 [技术架构设计](01-技术架构设计.md) 的五层架构落到目录、文件、命名与构建配置，作为编码与评审的直接依据。

- 一个页面一个文件、一个组件一个文件、一个实体一个文件；同类聚合用目录而非巨型文件。
- 目录即边界：跨目录 import 视为架构变更，需在本文件登记。
- v1 只有 `entry` 一个 HAP，不为"将来可能拆模块"预建空目录；拆分阈值见第 8 节。
- 模板残留必须清零：`Index.ets` 的 Hello World、`page_text_font_size`、`start_window_background=#FFFFFF`、`resources/dark` 副本。

## 3. 目录职责与禁止事项

| 目录 | 职责 | 必须 | 禁止 |
| --- | --- | --- | --- |
| `entryability/` | 生命周期、窗口、深链入口、首帧前初始化 | 设置 `COLOR_MODE_DARK`、`layoutFullScreen` | 业务查询、页面构建 |
| `pages/` | 唯一 `@Entry`：`Tabs` + 4 个 `Navigation` | 只做容器与 Tab 切换 | 具体业务 UI、网络请求 |
| `views/` | 12 个页面内容，根节点 `NavDestination` | 只与自己的 ViewModel 交互 | 直接 `getRdbStore`、裸写 SQL |
| `components/` | C-xx 组件；业务组件只接收数据与回调 | `@Param` 入、`@Event` 出 | import `services/**`、发请求 |
| `viewmodels/` | 页面状态、表单校验、事件订阅与解绑 | 生命周期内 `off` 掉事件 | 持有 `Context` 长引用、弹 Toast |
| `domain/` | 纯规则与 Port 接口 | 纯函数、注入 `Clock` | I/O、`@kit.*`、单例、UI 类型 |
| `services/` | 用例编排、事务边界、调度 | 一次用户动作一个事务 | 返回 `Resource`、操作组件 |
| `data/db` | 连接、Schema、迁移、DAO | 写操作走 `DbExecutor` 单队列 | 业务判断、文案拼装 |
| `data/remote` | HTTP、Cookie、限流、4 个适配器 | 平台差异封装在 Adapter 内 | 直接写库、依赖 Store |
| `data/repository` | 多表聚合、缓存、DTO ↔ Entity | 输出 Entity/领域结果 | 抛 UI 异常、含提示语 |
| `model/` | Entity、DTO、State、枚举 | 纯数据结构 | 依赖上层、含 I/O |
| `constants/` `utils/` | 令牌、路由、配置、日志、日期、加密 | 无状态函数 | 存可变全局变量 |
| `app/` | 装配、生命周期分发、事件总线、全局 Store、路由服务 | 唯一 new Service 与 connect Store 的位置 | 业务规则 |
| `resources/` | 令牌与静态资源 | 与设计规范一一对应 | 业务代码写裸 HEX/中文文案 |
| `workers/` | 大 HTML 解析卸载 | `@Concurrent` 纯函数 | 访问 UI/Store/Context |

`workers/` 判定：仅当单次解析耗时 > 8ms 或 HTML > 64KB 时启用；优先 taskpool，不用 `worker` 线程常驻。

与 [数据模型设计](03-数据模型设计.md) 第 1 节目录表述的对应关系（落地以本文为准）：其 `data/model/<Entity>.ets` 即本文 `model/entity/`；其 `services/normalize` 即本文 `domain/normalize`（算法）+ `services/sync`（编排）；其 `services/ops` 拆入 `services/export`、`services/badge`、`services/notification`；其 `platform/{rdb,net,crypto,log}` 分属 `data/db`、`data/remote/http`、`utils`，不单设目录；其 `RdbHelper`/`SchemaV1` 对应本文 `data/db/DatabaseHelper.ets`、`DbSchema.ets`。其第 4 节的 `OjAdapter` 即 `domain/port/OjAdapter.ets` 的契约细化，实现类在 `data/remote/adapters`，平台原始 JSON 只出现在 `data/remote/dto`。

## 4. 命名规范

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 页面/视图/组件/类文件 | PascalCase，文件名 = 导出 struct/class 名 | `StreakHeroCard.ets` |
| 配置/脚本/资源文件 | kebab-case | `obfuscation-rules.txt`、`official-problem-sets.json` |
| struct / class / interface | PascalCase；接口不加 `I` 前缀，用后缀表达角色 | `ProblemRow`、`OjAdapter`、`ProblemDetailParam` |
| 方法 / 字段 | camelCase；布尔用 `is/has/can/should`；事件回调 `onXxx` | `isAchieved`、`onFilterChange` |
| 常量 | UPPER_SNAKE；按域收进类 | `CsColor.PRIMARY_CONTAINER`、`RouteName.PROBLEM_DETAIL` |
| 枚举 | 类型 PascalCase，成员 UPPER_SNAKE，值为小写字符串（与 RDB `CHECK` 一致） | `Platform.CODEFORCES = 'codeforces'` |
| 数据库 | 表/列 snake_case 单数；索引 `idx_<表>_<列>`；唯一键 `uk_<表>_<列>` | `check_in`、`idx_submission_problem` |
| 路由名 | kebab-case 名词短语 | `problem-set-detail`、`contest-detail` |
| 资源 | `cs_color_*`、`cs_space_*`、`cs_radius_*`、`cs_font_*`、`cs_*`（文案） | `cs_color_surface_low` |
| 日志 tag | `CS-<模块>` | `CS-SYNC`、`CS-DB` |

约束：禁止中文文件名与空格路径；import 顺序为 `@kit.*` → 本项目绝对语义目录 → 同目录相对路径，组间空行；禁止 `any`、`@ts-ignore`、`as unknown as` 双重断言。

## 6. 权限清单

`module.json5` 的 `requestPermissions` 在本项目只声明系统授权（system_grant）权限；通知使能不是 manifest 权限，走运行时 `notificationManager.requestEnableNotification()`。

| 权限 | 级别 | 用途 | 申请时机 | 不可用降级 |
| --- | --- | --- | --- | --- |
| `ohos.permission.INTERNET` | system_grant | 同步 OJ 数据、拉取赛程与榜单 | 安装即授予 | 展示本地缓存 + "离线"标识 |
| `ohos.permission.GET_NETWORK_INFO` | system_grant | 判断 WLAN/蜂窝，蜂窝下不自动全量同步 | 安装即授予 | 默认仅手动同步 |
| `ohos.permission.PUBLISH_AGENT_REMINDER` | system_grant | reminderAgentManager 发布比赛/打卡提醒 | 安装即授予；首次开启提醒时校验 reminder 是否发布成功 | 降级为应用内横幅与日历标记 |
| `ohos.permission.KEEP_BACKGROUND_RUNNING` | system_grant | v1.1 长时同步任务（> 3min） | **v1.0 不声明**，引入长时任务时再加 | v1 用短时任务即可 |
| 通知使能（非权限） | 用户授权 | 展示打卡/比赛通知 | 首次创建提醒时 `requestEnableNotification` | 用户拒绝则仅应用内提示 |
| 文件导出（非权限） | 用户授权 URI | P-12 导出 JSON/Markdown | `FilePicker` 选择目录时一次性授权 | 取消导出并保留草稿 |

```json5
// entry/src/main/module.json5（节选）
"requestPermissions": [
  { "name": "ohos.permission.INTERNET" },
  { "name": "ohos.permission.GET_NETWORK_INFO" },
  { "name": "ohos.permission.PUBLISH_AGENT_REMINDER" }
  // v1.1 启用长时同步任务后再加入：ohos.permission.KEEP_BACKGROUND_RUNNING
],
"abilities": [{
  "name": "EntryAbility",
  "launchType": "singleton",     // 深链/通知复用同一实例，避免多任务栈
  "orientation": "portrait",
  "startWindowBackground": "$color:start_window_background"
}]
```

不申请的权限及原因：`READ_MEDIA`/`WRITE_MEDIA`（改用 Picker 授权 URI）、`READ_CALENDAR`/`WRITE_CALENDAR`（v1 不写系统日历）、`NOTIFICATION_CONTROLLER`（系统应用专有）、`DISTRIBUTED_DATASYNC`（v1 无跨设备同步）。

## 7. 构建、签名与多目标

| 项 | 配置 | 说明 |
| --- | --- | --- |
| SDK | compatible `6.1.1(24)`、target `26.0.0`、`runtimeOS: HarmonyOS` | 升 SDK 必须回归 V2 状态管理与 Navigation 行为 |
| bundleName | `AppScope/app.json5` → `com.codestreak.app` | 需同步改签名与推送证书；`vendor: codestreak` |
| 版本 | `versionCode 1000000`、`versionName 1.0.0` | 每次上架 `versionCode` 单调 +1 |
| signingConfigs | 本地生成，不入库 | `.p12`/`.cer`/`signing-configs` 进 `.gitignore`；CI 用环境变量注入 |
| buildModeSet | `debug` / `release` | release 开启混淆与压缩，debug 保留符号与日志 |
| buildProfileFields | `LOG_LEVEL`、`BUILD_MODE`、`AUTO_SYNC` | 生成 `BuildProfile`，业务代码不写 `if (isDebug)` 猜测 |
| 混淆 | `obfuscation-rules.txt` + `arkOptions.obfuscation.ruleOptions` | 见下方"必须 keep 的符号" |
| 体积门禁 | 安装包 ≤ 30MB（HAP ≤ 20MB），`rawfile` ≤ 8MB | 超限阻断合并；字体与 seed 是主要增长点 |
| 多目标 | 单 product + 双 buildMode | 不为渠道改 bundleName（签名与数据迁移成本高）；渠道用 `buildProfileFields.CHANNEL` |

必须 keep 的符号（否则线上必炸）：

1. DTO 的 JSON 字段名（`-keep-property-name`），属性混淆会导致 `JSON.parse` 后取不到值。
2. `PersistenceV2` 持久化对象的属性名：序列化按属性名落盘，混淆后老数据读不出。
3. `EntryAbility`、`EntryBackupAbility` 与 `NavDestination` 的 `@Builder` 导出名。
4. 备份扩展 `backup_config.json` 中登记的路径与文件名。

## 8. HAR/HSP 演进路线

| 阶段 | 形态 | 触发阈值（任一满足） | 动作 |
| --- | --- | --- | --- |
| v1.0 | 单 HAP | 当前状态 | 只做目录分层，不建空模块 |
| v1.1 | +`commons` HAR | 两处以上复用 `DesignTokens`/`Routes`/`Logger`/`Result`；或重复代码 > 300 行；或新增第二个 HAP | 抽静态 HAR：`constants/`、`utils/`、`model/`、`data/remote/http`，包名 `@codestreak/commons` |
| v1.2 | 按 feature 拆 HAR/HSP | 单 HAP 编译 > 180s；或 HAP > 20MB、安装总包 > 30MB；或 4 人以上并行、周冲突 > 5 次 | 拆 `feature-today`、`feature-problemset`、`feature-contest`、`feature-stats` |

拆分纪律：

- 共享**运行时单例**（`AppContainer`、`EventBus`、`CookieStore`）与大资源（字体、Web 容器）放 HSP；纯代码与令牌放 HAR，避免 HSP 被重复加载。
- 路由不跨模块硬编码：每个 feature 导出 `registerRoutes(registry)`，由 `pages/Index` 聚合，路由名仍以 `Routes.ets` 为唯一来源。
- 依赖方向不变：feature → commons，禁止 commons 反向依赖 feature；HAR 不依赖 HAP。
- v1.1 迁移 `DesignTokens.ets` 到 `commons/constants/`，类名 `CsColor` 与常量名保持不变，与 [设计令牌规范](../02-设计规范/02-设计令牌规范.md) 11.2 的路径对齐；v1.0 暂放 `entry/src/main/ets/constants/`。
- 拆分前先用 hvigor 构建报告与 HAP 体积报告取数，不凭主观感受拆模块。

## 9. 依赖管理

- 包管理器统一 ohpm；`oh-package-lock.json5` 必须提交，版本写精确值（禁止 `^`/`~`）。
- 准入清单：许可证（Apache-2.0/MIT）、近 12 个月有维护、无 native `.so`、单包 ≤ 200KB、无动态下发与热更新能力、通过安全扫描。
- 默认拒绝：状态管理库（V2 已够）、UI 组件库（设计系统自建）、ORM（手写 DAO 更可控）、网络封装（http 已够）、任何需要反射的工具库。
- `devDependencies` 仅 `@ohos/hypium`、`@ohos/hamock`，随 SDK 升级同步；不得进入运行时依赖。
- 新增依赖需在本文第 9 节登记用途、体积与替代方案，评审通过后合入。
- 合并门禁：`code-linter.json5` 的 `@performance/recommended`、`@typescript-eslint/recommended` 与 `@security/*` 规则必须无 error；warn 计入技术债并在迭代内清零。
