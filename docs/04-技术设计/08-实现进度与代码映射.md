# 实现进度与代码映射

## 1. 目的与更新义务

本文是**实现进度的唯一事实源**：记录每个模块的状态、代码落点、验证证据、与设计的偏差和下一步。

> **更新义务**：每完成一次开发任务（一个提交或一个 PR），必须同步更新本文的「模块状态」「验证证据」「偏差登记」三节。未更新视为任务未完成（与 [Git 版本管理规范](../05-项目规范/05-Git版本管理规范.md) §9 的 DoD 一致）。

## 6. 与设计的偏差登记

| 编号 | 偏差 | 原因 | 影响 | 后续 |
| --- | --- | --- | --- | --- |
| DEV-01 | 组件按 4 个文件聚合（Common/Cards/Visuals），未按 C-xx 一文件一组件 | 首版提速，21 个组件内聚管理 | 单文件较大（Cards ≈ 870 行），不利并行开发 | M3 前按 C 编号拆分 |
| DEV-02 | 图标使用字符占位（✓ ★ 🔥 →） | 未引入图标字体，避免首版资源依赖 | 视觉与设计稿有差距 | 换 `SymbolGlyph` 或字体图标 |
| DEV-03 | RDB 仅落 7/17 张表（新增 submission、sync_job） | 先保证打卡、同步与题目可用 | 题单/徽章/榜单未持久化 | 后续按 DbSchema 机制追加 |
| DEV-04 | 仅接 Codeforces 同步，AtCoder/洛谷/LC 未接 | 逐平台验证，CF 官方 API 最稳定 | 其余平台数据仍来自种子 | M1 剩余工作 |
| DEV-05 | 未接 `reminderAgentManager` | 权限与真机验证成本 | 21:30 提醒为界面开关 | M2/M3 |
| DEV-06 | 同步仅在手动点击时触发，无定时/后台同步 | v1.0 不做后台常驻（04-01） | 数据新鲜度依赖用户操作 | v1.1 评估 `workScheduler` |
| DEV-07 | 庆祝弹层用 Stack 遮罩实现，未用 `bindContentCover` | 降低 API 兼容风险 | 转场动画较简单 | 视觉打磨时替换 |
| DEV-08 | 深色主题通过 `setColorMode(DARK)` 与页面底色实现，未做系统级主题资源 | v1.0 单主题 | 无影响 | 保持 |
| DEV-09 | CF handle 以明文存于 `app_setting` | 非敏感标识，不涉及凭据 | 可被同机读取 | 与 Cookie 一样迁入 Asset Store |

## 7. 已知缺口与下一步

1. **平台同步**：CF 已端到端（节流 → HTTP → 映射 → 幂等落库 → 当日 AC 聚合），**待真机联网验证**；下一步接 AtCoder（kenkoooo）、洛谷（授权同步）、LC（WebView 登录态）；
2. **数据补全**：problem_set / badge / contest_registration 等表；`daily_ac_count` 已能从 submission 聚合，但热力图仍用种子序列，待按日期填充；
3. **同步体验**：失败重试队列（当前仅提示）、多平台并发与逐平台降级提示、同步时间戳展示；
4. **通知**：`reminderAgentManager` 每日 21:30 与赛前 15 分钟，权限拒绝路径；
5. **真机回归**：按 [测试用例集](../07-测试与质量/02-测试用例集.md) 的 P0 逐条执行，重点验证同步成功/失败提示、热力图横向滚动、倒计时 HUD 按钮宽度；
6. **签名与上架**：配置自动签名，产出可安装包。
