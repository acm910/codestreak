# 状态管理与路由设计

## 1. 目的与范围

本文规定 CodeStreak 的状态分层、ArkUI 状态管理选型、核心状态模型、路由与深链方案，是页面状态边界与跳转的唯一依据。分层前提见 [技术架构设计](01-技术架构设计.md)，目录归属见 [工程结构与模块划分](02-工程结构与模块划分.md)，实体字段见 [数据模型设计](03-数据模型设计.md)。

## 2. 状态分层与归属

| 层级 | 载体 | 生命周期 | 放什么 | 不放什么 |
| --- | --- | --- | --- | --- |
| 应用级 | `AppStorageV2` Store + `PersistenceV2` + Preferences | 进程 / 安装周期 | 登录态、同步态、今日打卡、全局提示、设置、跨 Tab 筛选（共 6 个 Store） | 页面临时态、输入草稿、弹窗开关 |
| 页面级 | 页面内 `@Local`（ViewModel 实例 + UI 态） | `NavDestination` 实例 | 本页 ViewModel、滚动位置、展开项、表单草稿 | 被其他页面引用的共享数据 |
| 组件级 | `@Param` 入 / `@Event` 出 / `@Local` 内部 | 组件实例 | 按压、hover、内部折叠、局部动画开关 | 直接读写 Store、发网络请求 |

跨页共享最小化原则：

1. 只有"两个以上页面同时需要，或页面销毁后仍需保留"的状态才进应用级，其余留在页面级。
2. 页面间优先走路由参数（只传 `id` 与枚举）；应用级只保留 6 个 Store：`AuthStore`、`SyncStore`、`CheckInStore`、`AlertStore`、`SettingsStore`、`FilterStore`，新增需登记理由。

## 3. 状态管理选型：V2 为主

`compatibleSdkVersion` 为 API 24，V2 全量可用。新代码统一用 V2；`pages/Index.ets` 以 `@Entry @ComponentV2` 承载容器，页面生命周期改用 `NavDestination.onShown/onHidden` 与 Ability 回调，不依赖 `onPageShow`。

| 维度 | V1 | V2 | 本项目结论 |
| --- | --- | --- | --- |
| 深度观测 | `@State` 只观察第一层，嵌套需 `@Observed` + `@ObjectLink` | `@ObservedV2` + `@Trace` 任意深度 | V2，避免拆对象图 |
| 组件入参 | `@Prop` 深拷贝、`@Link` 双向 | `@Param` 只读 + `@Event` 显式回调 | V2，单向流可审计 |
| 派生状态 | 无，靠 `@Watch` 手工同步 | getter 自动依赖追踪 | V2，删除冗余布尔字段 |
| 多字段监听 | `@Watch` 单字段单回调 | `@Monitor('a', 'b.c')` 支持路径 | V2，减少手工比对 |
| 全局状态 | `AppStorage` + `PersistentStorage`，类型弱 | `AppStorageV2` + `PersistenceV2`，泛型安全 | V2，键与类型集中声明 |
| 更新粒度 | `@Prop` 大对象拷贝开销 | 引用传递，按 `@Trace` 精确刷新 | V2，长列表更稳 |

限制与纪律：

- 同一组件内**禁止**混用 V1/V2 装饰器；V1 只允许出现在"包装系统/三方 V1 组件"的适配层，且不持有业务状态。
- `@Param` 只读，子组件改值必须 `@Event` 上抛；要深度响应，传入对象必须是 `@ObservedV2` 实例。
- `@Local` 只在自身赋值或所持 `@ObservedV2` 的 `@Trace` 变化时刷新，普通对象内部字段改动不触发。
- `PersistenceV2` 只支持可 JSON 序列化字段：`Date` 存时间戳，`Map`/`Set`/类实例不持久化。

## 4. 核心状态模型

接口是**可序列化快照 + 持久化契约**，Store 类以 `@Trace` 字段承载运行时状态；两者字段同名，通过 `snapshot()` / `apply()` 转换。★ 为持久化字段，`AlertItem` 等子类型同文件维护。

```ts
// model/state/AppStates.ets —— camelCase 与 04-03 的列映射一致
export interface AuthState {
  userId: number;                 // ★ Preferences: auth.userId
  nickname: string;
  boundPlatforms: Platform[];
  expiredPlatforms: Platform[];
  lastVerifiedAt: number;         // ★ Preferences: auth.lastVerifiedAt
}
export interface SyncState {
  status: SyncStatus;             // queued | running | success | partial | failed | canceled
  runningPlatform: Platform | null;
  lastSuccessAt: number;          // ★ Preferences: sync.lastSuccessAt
  dataVersion: number;            // 内存递增，不持久化
}
export interface CheckInState {
  checkinDate: string;            // ↔ check_in.checkin_date
  status: CheckInStatus;          // done | partial | repaired | missed | pending
  targetProgress: number;         // ↔ check_in.daily_target_progress（0–2，驱动达标与连胜）
  acCount: number;                // ↔ check_in.daily_ac_count（可 >2，驱动热力图与摘要）
  goal: number;                   // ↔ check_in.goal
  streakCurrent: number;          // ↔ user.streak_current
  streakLongest: number;          // ↔ user.streak_longest
  repairCardBalance: number;      // ↔ user.repair_card_balance
}
export interface ProblemFilterState {
  platforms: Platform[];          // ★ PersistenceV2: cs_problem_filter
  difficulty: [number, number];   // difficulty_norm 1.0–5.0
  solveState: SolveState;         // ★ all | solved | attempted | todo
  keyword: string;                // ★
  sortBy: SortBy;                 // ★ difficulty | recent | progress
}
export interface ContestFilterState {
  platforms: Platform[];          // ★ PersistenceV2: cs_contest_filter
  status: ContestStatus | 'all';  // ★ upcoming | registering | running | ended | canceled
  windowDays: 7 | 30 | 90;        // ★
  onlyRegistered: boolean;        // ★
}
export interface AlertState {
  current: AlertItem | null;
  queue: AlertItem[];             // 不持久化
  lastNotifiedDayKey: string;     // ★ Preferences: alert.lastDay
}
```

```ts
// app/store/CheckInStore.ets —— 字段与 CheckInState 同名
@ObservedV2
export class CheckInStore {
  @Trace checkinDate: string = '';
  @Trace status: CheckInStatus = 'pending';
  @Trace targetProgress: number = 0;
  @Trace acCount: number = 0;
  @Trace goal: number = 2;
  @Trace streakCurrent: number = 0;
  @Trace streakLongest: number = 0;
  @Trace repairCardBalance: number = 0;
  get achieved(): boolean { return this.targetProgress >= this.goal; }
  get remaining(): number { return Math.max(0, this.goal - this.targetProgress); }
  apply(next: CheckInState): void { /* 逐字段赋值，禁止对象展开 */ }
}
```

`achieved`、`remaining` 是 getter，不落库、不进接口；`status` 直接取 `check_in.status`，`pending` 仅内存态。`SyncState.dataVersion` 每次同步成功 `+1`，页面 `onShown` 比对后决定是否重查。

## 5. 状态更新规则

1. **单向数据流**：View 事件 → ViewModel → Service → Repository → Store → `@Trace` → View。View 不直接写 Store。
2. **不可变更新**：集合字段整体替换，禁止 `push/splice/sort` 原地改；Entity 只读。
3. **派生用 getter**：不再存 `isAchieved`、`completionRate`，避免双份真相。
4. **一次动作一个事务**：一个 Service 方法 = 一个 RDB 事务 + 一次 Store 提交。
5. **受控写入**：字段对外可读，写入只经 `apply()` / `patchXxx()`；禁止组件内 `store.acCount = 3`。
6. **日期滚动集中处理**：`AppLifecycle` 每次前台检测 `checkinDate` 变化，统一重置并触发一次重算。
7. **禁止在 `build()` 内**发请求、写状态、读 RDB、创建定时器。

## 6. 路由方案

`pages/Index.ets` 是唯一 `@Entry`，承载 `Tabs` 与 4 个 `Navigation`；每个 Tab 一个独立 `NavPathStack`，P-05…P-12 全部是 `NavDestination` 内容，不注册为独立路由页。

```text
pages/Index.ets  (@Entry @ComponentV2)
└─ Tabs(activeTab) ── C-02 BottomTabBar
   ├─ Tab('today')   → Navigation(todayStack)   → TodayPage            P-01
   ├─ Tab('sets')    → Navigation(setsStack)    → ProblemSetMatrixPage P-02
   ├─ Tab('contest') → Navigation(contestStack) → ContestCalendarPage  P-03
   └─ Tab('stats')   → Navigation(statsStack)   → StatsPage            P-04
二级页压入发起方 Tab 的栈；栈对象由 RouterService 持有，切换 Tab 不跨栈
```

实现规则：

- `NavPathStack` 是非响应式对象，禁止放进 `@Trace`；由 `RouterService` 单例持有，`Navigation` 通过构造参数绑定。
- 每个 `Navigation` 使用 `.mode(NavigationMode.Stack).hideTitleBar(true)`，标题由各页 `AppBar`（C-01）自绘。
- 目标页映射集中在 `app/router/RouteMap.ets` 的 `@Builder destinationBuilder(name, param)`，新增页面只改这一处。
- 禁止 `@ohos.router` 与 `Navigation` 混用；禁止组件内 `new NavPathStack()`。

## 7. 路由表与参数契约

| 路由名 | 页面 | 所属 Tab | 参数 | 返回行为 | 数据缓存 |
| --- | --- | --- | --- | --- | --- |
| `problem-set-detail` | P-05 | 调用方 Tab | `{ id, fromTab? }` | pop 回来源页 | 10min |
| `problem-detail` | P-06 | 调用方 Tab | `{ id, fromTab? }` | pop 回来源页 | 30min |
| `contest-detail` | P-07 | contest | `{ id, fromTab?, action? }` | pop 回来源页 | 5min |
| `upsolve-detail` | P-08 | contest | `{ id }` | pop 回来源页 | 不缓存 |
| `account-bind` | P-09 | stats | `{ platform? }` | pop 回设置页 | 不缓存 |
| `settings` | P-10 | stats | `{ section? }` | pop 回统计页 | 不缓存 |
| `badge-wall` | P-11 | stats | `{ highlight? }` | pop 回统计页 | 60min |
| `data-export` | P-12 | stats | `{}` | pop 回设置页 | 不缓存 |

```ts
// constants/Routes.ets
export type TabKey = 'today' | 'sets' | 'contest' | 'stats';
export class RouteName {
  static readonly PROBLEM_DETAIL: string = 'problem-detail';
  static readonly PROBLEM_SET_DETAIL: string = 'problem-set-detail';
  static readonly CONTEST_DETAIL: string = 'contest-detail';
  static readonly UPSOLVE_DETAIL: string = 'upsolve-detail';
  static readonly ACCOUNT_BIND: string = 'account-bind';
  static readonly SETTINGS: string = 'settings';
  static readonly BADGE_WALL: string = 'badge-wall';
  static readonly DATA_EXPORT: string = 'data-export';
}
export interface DetailParam { id: number; fromTab?: TabKey; }
export interface ContestDetailParam extends DetailParam { action?: 'REGISTER' | 'UPSOLVE'; }
export function parseDetailParam(raw: Object | undefined): DetailParam | null;
```

参数校验统一在 `RouteGuard` 执行：`id` 必须是正整数（`Number.isInteger(id) && id > 0`，对应 `INTEGER` 主键）；枚举值必须在白名单；未知字段忽略；校验失败不抛异常，记 WARN + Toast"链接已失效" + `stack.clear()` 回 Tab 根。禁止传对象实例、函数、`NavPathStack`。

## 8. Tab、返回与深链

- **Tab 与栈**：4 个 Tab 各保留独立栈，切换不清理、不重建；再次点击当前 Tab 执行 `clear()` 并让列表回到顶部。
- **返回键**：当前栈非空 → `pop()`；栈空 → 系统默认（退到后台），v1.1 再做"双击退出"；未保存页面在 `NavDestination.onBackPressed` 返回 `true` 拦截并确认。
- **手势**：侧滑返回由 Navigation 统一处理，业务不自行监听；转场固定 250ms。
- **深链格式**：

```text
codestreak://checkin/today
codestreak://problem/detail?id=1024&fromTab=today
codestreak://contest/detail?id=12&action=REGISTER
codestreak://settings/reminder
```

`module.json5` 的 `EntryAbility.skills` 增加 `actions: ["ohos.want.action.viewData"]`、`entities: ["entity.system.browsable"]` 与对应 `uris`；`launchType: "singleton"`。冷启动走 `onCreate`、热启动走 `onNewWant`，共用 `DeepLinkParser.parse(want)` 生成 `RouteTarget { tab, name, param }`：冷启动先 `queue()`，Index 首次 `aboutToAppear` 后 `applyPending()`；热启动直接 `push()`。通知经 `wantAgent` 携带 `parameters: { route: 'contest-detail', param: '{"id":12}' }`。只接受路由表白名单，未知 host/path 丢弃并记 WARN，绝不把外部 URL 交给 Web 组件打开。

## 9. 状态恢复与缓存失效

| 场景 | 恢复内容 | 不恢复 |
| --- | --- | --- |
| 冷启动 | RDB 数据、`PersistenceV2` 设置与筛选、Preferences 的 `lastTab` | 路由栈、滚动位置、弹窗 |
| 热启动 | 内存 Store 原样保留，仅做日期滚动与 TTL 校验 | — |
| 深链冷启动 | 目标 Tab + 参数 | `lastTab`（被深链覆盖） |

| 数据 | TTL | 失效触发 |
| --- | --- | --- |
| 今日打卡 / 连续天数 | 30s | 同步完成、补签、跨日 |
| 题单矩阵 / 题单进度 | 10min | 同步完成、订阅变更 |
| 比赛赛程 | 30min | 手动刷新、同步完成 |
| 榜单 | 5min | 手动刷新、本人打卡变化 |
| 徽章墙 | 60min | 解锁事件、跨日 |
| 账号绑定状态 | 每次前台 | 绑定/解绑、鉴权失效 |

统一入口 `AppLifecycle.onForeground()`：`checkinDate` 变化 → 重置 `CheckInState` 并重算；`now - lastSuccessAt > 6h` → `SyncScheduler.tryStart('foreground')`；页面 `onShown` 比对 `dataVersion`，变化则重查。

## 10. 示例代码

```ts
// app/router/RouterService.ets
export class RouterService {
  private static readonly INSTANCE: RouterService = new RouterService();
  readonly todayStack: NavPathStack = new NavPathStack();
  readonly setsStack: NavPathStack = new NavPathStack();
  readonly contestStack: NavPathStack = new NavPathStack();
  readonly statsStack: NavPathStack = new NavPathStack();
  private pending: RouteTarget | null = null;
  static getInstance(): RouterService { return RouterService.INSTANCE; }
  stackOf(tab: TabKey): NavPathStack {
    return tab === 'sets' ? this.setsStack : tab === 'contest' ? this.contestStack :
      tab === 'stats' ? this.statsStack : this.todayStack;
  }
  push(tab: TabKey, name: string, param: Object): void {
    this.stackOf(tab).pushPathByName(name, param);
  }
  queue(target: RouteTarget): void { this.pending = target; }
  applyPending(): void {
    const t = this.pending;
    if (t === null) return;
    this.pending = null;
    this.push(t.tab, t.name, t.param);
  }
}
```

```ts
// app/AppContainer.ets —— 全局状态只在装配期连接一次
const checkIn: CheckInStore = AppStorageV2.connect(CheckInStore, 'cs_checkin',
  () => new CheckInStore())!;
const settings: SettingsStore = PersistenceV2.connect(SettingsStore, 'cs_settings',
  () => new SettingsStore())!;
```

`PersistenceV2` 在 `@Trace` 字段变更后异步落盘；关键设置（`daily_goal`、`notify_time`）写入后追加 `PersistenceV2.save('cs_settings')` 兜底；筛选状态在用户点"重置"时整体替换并立即保存。页面用 `@Local` 持有 connect 返回值，只读引用、不复制数据。

## 11. 测试与调试

- Domain 纯函数用 Hypium 覆盖：跨日边界、改时区不回算、同日重复 AC 去重、补签窗口与余额、目标 1/2/5。
- Store 提供 `snapshot(): XxxState`，输出可 JSON 序列化对象供日志与缺陷复现；禁止直接打印 Store 实例。
- 日志开关由 `BuildProfile.LOG_LEVEL` 注入：debug 输出 DEBUG，release 仅 WARN；Cookie、token、handle 一律 `%{private}s`。
- 调试面板（debug 构建）：查看 `dataVersion`、最近 20 条 `sync_job`、强制同步、清缓存、重置筛选；回归清单为冷启动进上次 Tab、深链冷/热启动、通知跳转后返回、Tab 切换保栈、连点不重页。

## 12. 常见反模式

1. 在 `build()` 里调用 Service 或写 Store。
2. 用 `@State` 存大数组并 `push/splice`（V1 观测不到深层变化），或依赖 `@Trace` 数组原地修改，刷新范围不可控。
3. 把 `AppStorageV2` 当页面间传参通道。
4. ViewModel 持有 `Context`/`UIContext` 长引用，页面销毁后泄漏。
5. 组件内直接 `relationalStore.getRdbStore()` 或拼 SQL。
6. Store 与 ViewModel 各存一份实体，出现双份真相。
7. 用 `@Watch`/`@Monitor` 手工同步派生值，而不是 getter。
8. 路由参数传对象实例或回调，深链与恢复必然失败。
9. `@ohos.router` 与 Navigation 混用，返回栈错乱；深链只 push 不校验，返回栈被外部参数无限撑大。
