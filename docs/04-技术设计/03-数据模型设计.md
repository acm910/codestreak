# 数据模型设计

## 1. 目的与范围

本文定义 CodeStreak 唯一持久化数据模型：17 张 RDB 表、枚举、可执行 DDL、统计口径 SQL、连续天数算法、迁移与保留、隐私与容量。RDB / Preferences / 云备份 / 导出四条路径以本文为准；上层状态管理与路由文档只依赖第 6 节实体与字段名，不得自行建表、加列。

- 分层：Presentation（pages/components）→ Application（viewmodel + services）→ Domain（纯算法、不依赖 `@kit.*`、可单测）→ Data（repository/dao/model）→ Platform（`@kit.ArkData`/`@kit.NetworkKit`/`@kit.CryptoArchitectureKit` 封装）。与 [技术架构设计](01-技术架构设计.md)、[工程结构与模块划分](02-工程结构与模块划分.md) 同一约定；若 01 号调整分层，以 01 为准并回写第 3 节。落地目录 `entry/src/main/ets/data/{db,dao,model,repository}`、`services/{sync,streak,normalize,ops}`、`platform/{rdb,net,crypto,log}`，DDL 与迁移脚本只允许存在于 `data/db`；目录与 02 号文档的映射见其"目录映射"表，**落地以 02 为准**（`data/model` ↔ `model/entity`、`DatabaseHelper.ets` ↔ 早期 `RdbHelper`）。
- 字段中文名见 [术语表与数据字典](../01-产品设计/04-术语表与数据字典.md)；平台字段来源与难度映射见 [平台同步与难度归一化](04-平台同步与难度归一化.md)。

## 2. 建模原则

| 原则 | 落地约束 | 反例（禁止） |
| --- | --- | --- |
| 离线优先 | 写操作先落本地事务，同步只做"补齐"；无网可打卡、补签、编辑题单 | 打卡按钮串行等网络 |
| 幂等 | 业务唯一键 upsert；重复同步不增行、不重复加天数、不重复发徽章 | 以自增 `id` 判重 |
| 可回溯 | 原始提交留 180 天、聚合永久；口径变更只重算聚合不改历史行；删除写 `deleted_at`，聚合一律带 `deleted_at IS NULL` | 覆盖旧 `verdict`；物理删除导致同步复活 |
| 隐私最小化 | RDB 不存 Cookie/token 明文，只存 `cred_ref` 与指纹 | Cookie 塞进 `app_setting.value` |
| 单一事实源 | 连续天数、总 AC 由事实表派生，禁止手工 UPDATE 计数列 | 前端直接改 `streak_current` |

## 3. 命名、类型与映射规则

| 维度 | 规则 |
| --- | --- |
| 表 / 列 | 小写 snake_case、表名单数；主键恒为 `id`，外键 `<表名>_id`；禁止反射映射，每表维护显式列常量（如 `SUBMISSION_COLUMNS`），`ResultSet` 逐列取值，缺列即编译期报错 |
| ArkTS 模型 | camelCase，`data/model/<Entity>.ets` 一实体一文件，字段带默认值满足严格初始化 |
| 枚举 | `TEXT` 存字面量 + `CHECK`；ArkTS 用字符串联合类型，禁止数字枚举落库 |
| 时间 / 日期 | 时间 `INTEGER` epoch **毫秒**（UTC），禁止 `Date`/ISO 入库；日粒度用 `TEXT 'YYYY-MM-DD'`（`local_day`），按用户时区算好再落库 |
| 布尔 / 数组 | 布尔 `INTEGER` 0/1（列名 `is_` 前缀）；数组用逗号分隔 canonical slug，不依赖 JSON1（设备是否编译 JSON1 **待验证**） |

```ts
// data/model/Problem.ets —— 逐字段显式映射：snake_case → camelCase
export class Problem {
  id: number = 0;
  platform: Platform = 'leetcode';
  externalId: string = '';                  // ← external_id
  canonicalKey: string = '';                // ← canonical_key：跨平台同题归一标识
  difficultyNorm: number = 3;               // ← difficulty_norm：算法计算值
  difficultyOverride: number | null = null; // ← difficulty_override：人工覆盖，优先级最高
}
export const PROBLEM_COLUMNS: string[] = ['id', 'platform', 'external_id', 'canonical_key', 'difficulty_norm', 'difficulty_override'];
/** 生效难度统一口径：COALESCE(difficulty_override, difficulty_norm) */
export function effectiveDifficulty(p: Problem): number { return p.difficultyOverride ?? p.difficultyNorm; }
```

## 4. ER 图

```text
① 身份与同步
  user(PK id) 1 ──── N platform_account(PK id, FK user_id, UK user_id+platform+handle)
                              └─ 1 ──── N sync_job(PK id, FK platform_account_id, FK user_id)
  user 1 ──── N app_setting(PK id, FK user_id, UK user_id+key)
② 做题、题单与打卡
  problem(PK id, UK platform+external_id, IX canonical_key) 1 ──< N submission
  platform_account 1 ──< N submission(PK id, FK problem_id, FK platform_account_id,
                                      UK platform+external_id, UK local_day+canonical_key WHERE counted=1)
  contest(PK id) 1 ──< N submission(FK contest_id，可空：非赛事提交)
  user 1 ──< N check_in(PK id, FK user_id, UK user_id+checkin_date, IX checkin_date)
  user 1 ──< N streak_record(PK id, FK user_id, UK user_id+start_date)
  user 1 ──< N problem_set(PK id, FK user_id，官方题单 user_id 为 NULL)
  problem_set 1 ──< N problem_set_item(PK id, FK set_id, FK problem_id, UK set_id+platform+external_id)
  problem N ──< problem_set_item >── N problem_set      （N:M，经联结表实现）
③ 赛事、补题与激励
  contest(PK id, UK platform+external_id) 1 ──< N contest_registration(PK id, FK contest_id, FK user_id,
                                                                      UK user_id+contest_id)
  contest 1 ──< N upsolve_task(PK id, FK contest_id, FK user_id, UK user_id+contest_id)
  upsolve_task 1 ──< N upsolve_item(PK id, FK task_id, FK problem_id, UK task_id+problem_index)
  badge(PK id, UK code) N ──< user_badge(PK id, FK badge_id, FK user_id, UK user_id+badge_id) >── N user
  leaderboard_entry(PK id, FK user_id 弱引用, UK scope+period_key+user_id)   // 榜单快照，冻结当期数值
```

取舍：`leaderboard_entry` 对 `user` 是**弱引用**（好友可能不在本地 `user` 表），外键可空；`submission` 跨平台去重靠 `canonical_key` 而非 `problem_id`（同一题在洛谷与 LeetCode 各有一行 `problem`）；`upsolve_item.slot_status` 与 `submission` 解耦，手动补题标记不伪造提交。

## 5. 枚举定义

| 枚举 | 取值 | 说明 |
| --- | --- | --- |
| `platform` | `leetcode` / `codeforces` / `atcoder` / `luogu` | 固定小写；`collegiate`（ICPC/CCPC）仅作 `contest.platform` 扩展值 |
| `verdict` | `AC`/`WA`/`TLE`/`MLE`/`RE`/`CE`/`PE`/`OLE`/`OTHER` | 平台判罚在适配器内映射；仅 `AC` 计入统计 |
| `contest_status` | `upcoming`/`registering`/`running`/`ended`/`canceled` | 由 `start_at`/`end_at` + 远端状态推导，每 10 分钟刷新 |
| `checkin_status` | `done`/`partial`/`repaired`/`missed`/`pending` | `pending` 仅内存态不落库；`missed` 由重算写入用于展示 |
| `difficulty_norm` | `1.0`–`5.0`，步长 `0.5` | `REAL` + `CHECK BETWEEN 1 AND 5`；★3 = 进阶／DP 与图论 |
| `sync_status` | `queued`/`running`/`success`/`partial`/`failed`/`canceled` | `partial` = 多平台部分成功，见第 9 节降级 |
| 辅助枚举 | `auth_state`：`valid`/`expired`/`revoked`；`auth_mode`：`none`/`cookie`/`token`/`webview`；`source`：`builtin`/`imported`/`custom`；`trigger`：`timer`/`foreground`/`manual`/`first_bind`/`contest_followup` | 与所属实体同文件维护，改动须同步本节 |

## 6. 表与字段清单

### 6.1 统一字段（17 表全部具备）

| 字段 | 类型 · 约束 · 默认 | 说明 |
| --- | --- | --- |
| `id` | `INTEGER PRIMARY KEY AUTOINCREMENT` | 本地主键，不复用、不对外暴露 |
| `created_at` / `updated_at` | `INTEGER NOT NULL DEFAULT 0` | epoch 毫秒，由 `Clock.now()` 统一写入，禁止各层自造时间 |
| `deleted_at` | `INTEGER NULL` | 墓碑；非 NULL 一律排除出聚合与列表 |
| `sync_version` | `INTEGER NOT NULL DEFAULT 0` | 每次成功 upsert 自增，用于增量导出与冲突判定 |

### 6.2 身份与同步（4 表）

- **`user`** ｜ 用户主体与展示快照（单用户单机 1 行；索引 `uk_user_nickname`）：`nickname TEXT NOT NULL`、`avatar_ref TEXT`、`uid_public TEXT`（`#9042`）、`tier_label TEXT`（`TIER-1 CODER`）、`timezone TEXT NOT NULL DEFAULT 'Asia/Shanghai'`、`daily_goal INTEGER NOT NULL DEFAULT 2`（≡术语表 `daily_target`）、`streak_current`/`streak_longest`/`total_ac`/`total_checkin_days` 均 `INTEGER NOT NULL DEFAULT 0`、`repair_card_balance INTEGER NOT NULL DEFAULT 2 CHECK (>=0)`（≡`makeup_credits`，v1.0 仅里程碑 D7/D30/D100 各 +1，不售卖）、`badge_unlocked_count INTEGER NOT NULL DEFAULT 0`、`last_checkin_date TEXT`；四类计数只允许 `services/streak` 重算写入。`streak_longest` 为**生涯口径**（样例 64），不拆"近 365 天"字段。
- **`platform_account`** ｜ 平台绑定与同步游标（`uk_pa_platform(user_id, platform, handle)`、`idx_pa_sync(last_sync_at)`）：`user_id INTEGER NOT NULL REFERENCES user(id)`、`platform TEXT NOT NULL`、`handle TEXT NOT NULL`、`display_name TEXT`、`avatar_url TEXT`、`auth_mode TEXT NOT NULL DEFAULT 'none'`、`auth_state TEXT NOT NULL DEFAULT 'valid'`、`sync_mode TEXT NOT NULL DEFAULT 'manual'`（`auto`/`auth`/`manual`，对应同步模式 A/B/C，UI 徽标唯一来源）、`cred_ref TEXT`（HUKS 别名）、`cred_fingerprint TEXT`（SHA-256 前 8 字节）、`rating REAL`、`max_rating REAL`、`sync_cursor TEXT`（毫秒时间戳串）、`last_sync_at INTEGER`、`last_sync_status TEXT`、`is_enabled INTEGER NOT NULL DEFAULT 1`；`auth_state='expired'` 时同步即失败并提示重绑，不清历史。
- **`sync_job`** ｜ 同步任务与可观测性（`idx_sj_status(status, scheduled_at)`、`idx_sj_pa(platform_account_id, started_at DESC)`）：`user_id`、`platform_account_id`、`trigger TEXT NOT NULL`、`status TEXT NOT NULL DEFAULT 'queued'`、`attempt INTEGER NOT NULL DEFAULT 0`、`scheduled_at`/`started_at`/`finished_at`/`duration_ms`、`cursor_before`/`cursor_after TEXT`、`fetched`/`inserted`/`updated`/`skipped INTEGER`、`error_code`/`error_msg`/`partial_reason TEXT`、`clock_skew_ms INTEGER`。
- **`app_setting`** ｜ 可导出/需审计的设置（`uk_setting(user_id, key)`；启动型轻量标记仍走 Preferences）：`user_id`、`key TEXT NOT NULL`、`value TEXT`、`value_type TEXT NOT NULL DEFAULT 'string'`（`string`/`int`/`bool`/`json`）、`scope TEXT NOT NULL DEFAULT 'ui'`；常用键 `notify_time='21:30'`、`auto_sync='1'`、`sync_interval_min='360'`、`dedupe_window_days='30'`、`export_format='ics'`、`heatmap_weeks='16'`（每日目标只存 `user.daily_goal`，禁止双源）。

### 6.3 做题、题单与打卡（6 表）

- **`problem`** ｜ 题目元数据（`uk_problem(platform, external_id)`、`idx_problem_canonical(canonical_key)`、`idx_problem_diff(difficulty_norm)`）：`platform`、`external_id`（`LC-206`/`CF-1899A`/`P3372`）、`canonical_key TEXT NOT NULL`（默认 `<platform>:<external_id>`，跨平台同题由导入合并）、`title TEXT NOT NULL`、`title_en TEXT`、`difficulty_raw TEXT`（`Medium`/`1200`/`4`）、`difficulty_norm REAL NOT NULL DEFAULT 3`、`difficulty_source TEXT NOT NULL DEFAULT 'fallback'`、`difficulty_override REAL NULL`、`rating INTEGER`、`tags TEXT`、`url TEXT`、`contest_external_id TEXT`、`problem_index TEXT`（`A`..`G`）、`first_seen_at INTEGER`。
- **`submission`** ｜ 提交事实表，唯一统计源，保留 180 天：`platform_account_id`、`platform`、`external_id TEXT NOT NULL`、`problem_id`、`canonical_key TEXT NOT NULL`（冗余，供日级去重）、`verdict TEXT NOT NULL`、`language TEXT`、`submitted_at INTEGER NOT NULL`、`local_day TEXT NOT NULL`、`ac_at INTEGER`、`contest_id INTEGER`（可空）、`is_upsolve INTEGER NOT NULL DEFAULT 0`、`target_slot TEXT`（`recommend`/`challenge`/NULL，仅 P-01 两张目标卡当日完成时写入——自动同步命中的目标题与目标卡发起的手动打卡都写；补题一律 NULL）、`counted INTEGER NOT NULL DEFAULT 0`、`source TEXT NOT NULL DEFAULT 'sync'`（`sync`/`manual`）、`sync_job_id INTEGER`、`extra TEXT`（截断 512B）；索引 `uk_submission_ext(platform, external_id)`、`idx_submission_day(local_day, verdict)`、`idx_submission_problem(problem_id, submitted_at)`、`uk_submission_day_canon(local_day, canonical_key) WHERE counted=1 AND deleted_at IS NULL`（部分索引支持**待验证**，不支持则事务内先 SELECT 判重）。`counted` 规则：该 `canonical_key` 当日首次出现，且近 `dedupe_window_days`（默认 30）天无 `counted=1`；冲突更新不动 `counted`。**两个计数口径**：`daily_ac_count` = `COUNT(DISTINCT canonical_key)`（含补题，可 >2）；`daily_target_progress` = `COUNT(DISTINCT target_slot)`（0–2，补题不计入）。
- **`check_in`** ｜ 日打卡结果（`uk_checkin(user_id, checkin_date)`、`idx_checkin_date(checkin_date)`）：`user_id`、`checkin_date TEXT NOT NULL`、`status TEXT NOT NULL`（≡术语表 `daily_status`）、`daily_ac_count INTEGER NOT NULL DEFAULT 0`、`daily_target_progress INTEGER NOT NULL DEFAULT 0 CHECK (BETWEEN 0 AND 2)`、`goal INTEGER NOT NULL DEFAULT 2`（≡`daily_target`）、`focus_minutes INTEGER`（外跳往返估算，单题 ≤30 分钟，无样本为 NULL → UI 显示 `--`）、`platform_mask INTEGER NOT NULL DEFAULT 0`（位图 LC=1/CF=2/AC=4/LG=8）、`first_ac_at`、`last_ac_at`、`is_manual INTEGER NOT NULL DEFAULT 0`、`repair_item_id INTEGER`、`note TEXT`；只落库 `done`/`partial`/`repaired`/`missed`，无记录即"无活动"，热力图补零。
- **`streak_record`** ｜ 连续段（`uk_streak(user_id, start_date)`、`idx_streak_len(user_id, length DESC)`）：`user_id`、`start_date TEXT`、`end_date TEXT`、`length INTEGER NOT NULL`、`status TEXT NOT NULL DEFAULT 'active'`、`break_reason TEXT`、`repair_count INTEGER NOT NULL DEFAULT 0`。
- **`problem_set`** ｜ 题单（官方/导入/自建；`uk_set_url(source_url) WHERE source_url IS NOT NULL`、`idx_set_track(user_id, track)`）：`user_id INTEGER`（官方为 NULL）、`title TEXT NOT NULL`、`description TEXT`、`cover_ref TEXT`、`track TEXT NOT NULL DEFAULT 'interview'`、`source TEXT NOT NULL DEFAULT 'builtin'`、`source_url TEXT`、`platform_scope TEXT`、`total_count`/`solved_count INTEGER`、`progress_pct REAL`、`is_subscribed`/`sort_no INTEGER`、`last_import_at INTEGER`。
- **`problem_set_item`** ｜ 题单条目（`uk_item(set_id, platform, external_id)`、`idx_item_order(set_id, order_no)`）：`set_id`、`problem_id INTEGER`（可空：未抓元数据时占位）、`platform TEXT NOT NULL`、`external_id TEXT NOT NULL`、`order_no INTEGER NOT NULL DEFAULT 0`、`difficulty_norm_snapshot REAL`、`solved_at INTEGER`、`added_at INTEGER`。

### 6.4 赛事、补题与激励（7 表）

- **`contest`** ｜ 比赛元数据（`uk_contest(platform, external_id)`、`idx_contest_start(start_at)`）：`platform`、`external_id`、`title TEXT NOT NULL`、`start_at INTEGER NOT NULL`、`end_at INTEGER`、`duration_min INTEGER`、`url TEXT`、`division TEXT`（`Div. 2`）、`rated_limit TEXT`（`≤2100`/`≤1999`）、`participant_count INTEGER`、`difficulty_span TEXT`（`普及+~省选`）、`status TEXT NOT NULL`、`fetched_at INTEGER`。
- **`contest_registration`** ｜ 报名与提醒（`uk_reg(user_id, contest_id)`）：`user_id`、`contest_id`、`status TEXT NOT NULL DEFAULT 'none'`、`team_name TEXT`、`team_size INTEGER NOT NULL DEFAULT 1`、`remind_at INTEGER`、`remind_id TEXT`（`reminderAgentManager` 提醒 id）、`calendar_exported_at INTEGER`、`note TEXT`。
- **`upsolve_task`** ｜ 赛后补题任务（`uk_upsolve(user_id, contest_id)`）：`user_id`、`contest_id`、`title TEXT`、`contest_end_at INTEGER`、`total_items`/`solved_items INTEGER NOT NULL DEFAULT 0`、`completion_pct REAL NOT NULL DEFAULT 0`、`avg_delay_hours REAL`、`target_pct REAL NOT NULL DEFAULT 80`、`status TEXT NOT NULL DEFAULT 'open'`、`last_marked_at INTEGER`。
- **`upsolve_item`** ｜ 补题题位（`uk_upitem(task_id, problem_index)`）：`task_id`、`problem_id`、`problem_index TEXT NOT NULL`、`slot_status TEXT NOT NULL DEFAULT 'pending'`（`solved_in_contest`/`solved_after`/`pending`/`skipped`）、`solved_at INTEGER`、`delay_hours REAL`、`hint TEXT`、`submission_id INTEGER`、`note TEXT`。
- **`badge`** ｜ 徽章定义（12 枚；`uk_badge_code(code)`，`is_active` 支持下线不删以保证旧 `user_badge` 可显示）：`code TEXT NOT NULL`、`name TEXT NOT NULL`、`category TEXT NOT NULL`（`streak`/`contest`/`upsolve`/`coverage`/`difficulty`）、`description TEXT`、`icon_ref TEXT`、`metric TEXT NOT NULL`（`streak_days`/`ac_total`/`contest_ak`/`upsolve_rate`/`platform_count`/`max_star`）、`target_value INTEGER NOT NULL`、`rarity TEXT`、`sort_no INTEGER`、`is_active INTEGER NOT NULL DEFAULT 1`。
- **`user_badge`** ｜ 用户徽章进度（`uk_user_badge(user_id, badge_id)`）：`user_id`、`badge_id`、`progress INTEGER NOT NULL DEFAULT 0`、`target INTEGER NOT NULL DEFAULT 1`、`unlocked_at INTEGER`、`is_pinned INTEGER NOT NULL DEFAULT 0`。
- **`leaderboard_entry`** ｜ 榜单快照，保留 24 个月（`uk_lb(scope, period_key, user_id)`、`idx_lb_rank(scope, period_key, rank_no)`）：`scope TEXT NOT NULL`（`week`/`month`）、`period_key TEXT NOT NULL`（`2026-W44`/`2026-10`）、`user_id INTEGER`、`display_name TEXT`、`avatar_ref TEXT`、`streak_days INTEGER NOT NULL`、`rank_no INTEGER NOT NULL`、`is_self INTEGER NOT NULL DEFAULT 0`、`delta_days INTEGER`、`source TEXT NOT NULL DEFAULT 'remote'`、`snapshot_at INTEGER`。

## 7. 完整 DDL

```sql
-- 时间戳统一 INTEGER epoch 毫秒；布尔 INTEGER 0/1；枚举 TEXT + CHECK；软删判据 deleted_at IS NULL
-- 建表顺序即依赖顺序；脚本作为字符串常量维护于 data/db/DbSchema.ets，由 data/db/DatabaseHelper.ets 在事务中逐条 executeSql，并在 OPEN 后执行 PRAGMA foreign_keys = ON（relationalStore 是否默认开启外键**待验证**）
CREATE TABLE IF NOT EXISTS user (id INTEGER PRIMARY KEY AUTOINCREMENT, created_at INTEGER NOT NULL DEFAULT 0, updated_at INTEGER NOT NULL DEFAULT 0, deleted_at INTEGER, sync_version INTEGER NOT NULL DEFAULT 0, nickname TEXT NOT NULL, avatar_ref TEXT, uid_public TEXT, tier_label TEXT, timezone TEXT NOT NULL DEFAULT 'Asia/Shanghai', daily_goal INTEGER NOT NULL DEFAULT 2 CHECK (daily_goal BETWEEN 1 AND 20), streak_current INTEGER NOT NULL DEFAULT 0, streak_longest INTEGER NOT NULL DEFAULT 0, total_ac INTEGER NOT NULL DEFAULT 0, total_checkin_days INTEGER NOT NULL DEFAULT 0, repair_card_balance INTEGER NOT NULL DEFAULT 2 CHECK (repair_card_balance >= 0), badge_unlocked_count INTEGER NOT NULL DEFAULT 0, last_checkin_date TEXT);
CREATE TABLE IF NOT EXISTS platform_account (id INTEGER PRIMARY KEY AUTOINCREMENT, created_at INTEGER NOT NULL DEFAULT 0, updated_at INTEGER NOT NULL DEFAULT 0, deleted_at INTEGER, sync_version INTEGER NOT NULL DEFAULT 0, user_id INTEGER NOT NULL REFERENCES user(id) ON DELETE CASCADE, platform TEXT NOT NULL CHECK (platform IN ('leetcode','codeforces','atcoder','luogu')), handle TEXT NOT NULL, display_name TEXT, avatar_url TEXT, auth_mode TEXT NOT NULL DEFAULT 'none' CHECK (auth_mode IN ('none','cookie','token','webview')), auth_state TEXT NOT NULL DEFAULT 'valid' CHECK (auth_state IN ('valid','expired','revoked')), sync_mode TEXT NOT NULL DEFAULT 'manual' CHECK (sync_mode IN ('auto','auth','manual')), cred_ref TEXT, cred_fingerprint TEXT, rating REAL, max_rating REAL, sync_cursor TEXT, last_sync_at INTEGER, last_sync_status TEXT, is_enabled INTEGER NOT NULL DEFAULT 1);
```

## 8. 关键聚合查询与口径校验

```sql
-- 8.1 近 16 周热力图按日聚合：列=周（周一起），行=周一..周日，共 112 格
WITH RECURSIVE d(day) AS (SELECT '2026-07-13' UNION ALL SELECT date(day, '+1 day') FROM d WHERE day < '2026-11-01')
SELECT d.day, COUNT(DISTINCT s.canonical_key) AS ac_cnt,
       CASE WHEN COUNT(DISTINCT s.canonical_key) = 0 THEN 0 WHEN COUNT(DISTINCT s.canonical_key) <= 2 THEN 1
            WHEN COUNT(DISTINCT s.canonical_key) <= 5 THEN 2 WHEN COUNT(DISTINCT s.canonical_key) <= 8 THEN 3
            ELSE 4 END AS heat_level                       -- 五档阈值同《设计令牌规范》8.1
FROM d LEFT JOIN submission s ON s.local_day = d.day AND s.verdict = 'AC' AND s.counted = 1 AND s.deleted_at IS NULL
GROUP BY d.day ORDER BY d.day;
-- 校验：daily_ac_count=3（LeetCode 2 + CF 1）→ heat_level=2（cs.color.secondary）；补题计入本口径
-- 8.2 难度分布（★1..★5；占比 round-half-up 到 0.1）
SELECT CAST(ROUND(COALESCE(p.difficulty_override, p.difficulty_norm) * 2) / 2 AS REAL) AS star,
       COUNT(DISTINCT p.canonical_key) AS ac_cnt,
       ROUND(COUNT(DISTINCT p.canonical_key) * 100.0 / SUM(COUNT(DISTINCT p.canonical_key)) OVER (), 1) AS pct
FROM submission s JOIN problem p ON p.id = s.problem_id
WHERE s.verdict = 'AC' AND s.counted = 1 AND s.deleted_at IS NULL AND p.deleted_at IS NULL
GROUP BY star ORDER BY star;
-- 校验（精确四舍五入）：85/112/130/45/12（合计 384）→ 22.1 / 29.2 / 33.9 / 11.7 / 3.1；补题 AC 计入总 AC 与分布
-- 8.3 当日两口径（打卡判定入口）：daily_target_progress 只数目标卡，daily_ac_count 含补题
-- 校验：ac_count=3（LeetCode 2 + CF 1）、target_progress=2 ≥ goal(2) → check_in.status='done'，streak_current 保持 28
SELECT COUNT(DISTINCT s.target_slot) AS target_progress, COUNT(DISTINCT s.canonical_key) AS ac_count
FROM submission s
WHERE s.local_day = '2026-10-26' AND s.verdict = 'AC' AND s.counted = 1 AND s.deleted_at IS NULL;
-- 8.4 连续天数（SQL 校验版，仅供单测对拍；运行时用第 9 节 ArkTS 算法）；校验：28 天，历史最长 64（生涯口径）
SELECT MAX(cnt) AS longest FROM (SELECT COUNT(*) AS cnt FROM (
    SELECT date(c.checkin_date, '-' || ROW_NUMBER() OVER (ORDER BY c.checkin_date) || ' day') AS grp
    FROM check_in c WHERE c.user_id = 1 AND c.status IN ('done','repaired') AND c.deleted_at IS NULL
  ) GROUP BY grp);
-- 8.5 题单完成度；校验：代码随想录 42/60=70%，CF 1200-1400 15/45=33%，剑指 Offer 67/75=89%
SELECT ps.id, COUNT(i.id) AS total,
       CAST(SUM(CASE WHEN i.solved_at IS NOT NULL THEN 1 ELSE 0 END) * 100.0 / COUNT(i.id) AS INTEGER) AS pct
FROM problem_set ps JOIN problem_set_item i ON i.set_id = ps.id AND i.deleted_at IS NULL GROUP BY ps.id;
-- 8.6 排行榜名次（当期快照，不实时重算）；校验：45/34/28 → 1/2/3，本人距第 2 名 6 天
SELECT RANK() OVER (ORDER BY streak_days DESC) AS rank_no, display_name, streak_days, is_self
FROM leaderboard_entry WHERE scope = 'week' AND period_key = '2026-W44' AND deleted_at IS NULL ORDER BY rank_no;
```

| 指标 | 样例值 | SQL 计算值 | 结论 |
| --- | --- | --- | --- |
| 总 AC / 题单完成度 | 384；42/60=70%、15/45=33%、67/75=89% | 85+112+130+45+12=384；同除式取整 | 一致 |
| 双口径（当日） | `daily_ac_count=3`（LC 2 + CF 1）、`daily_target_progress=2` | `COUNT(DISTINCT canonical_key)=3`、`COUNT(DISTINCT target_slot)=2` | 一致（补题只进前者） |
| 难度占比 | 22.1 / 29.2 / 33.9 / 11.7 / 3.1 | 22.135、29.167、33.854、11.719、3.125 精确四舍五入 | 一致，合计 100.0%（原型 33.8/3.2 经裁决按精确值） |
| 补题率 | 75%（15/20，目标 80%） | 15/20=75.0%，差 1 题（16/20） | 一致；原型"打卡 D 后升至 80%"可复现 |
| 连续天数 / 历史最长 | 28 / 64 | run(2026-09-29..10-26)=28；MAX(length)=64（生涯口径） | 一致 |

## 9. 连续天数算法

**定义**：达标 = `check_in.daily_target_progress ≥ goal`（补题不计入）；`run(lastDone)` = 自 `lastDone` 起向前逐日回溯、命中 `status IN ('done','repaired')` 的连续天数；`gap = today - lastDone`（按 `user.timezone` 的自然日）。

```text
recomputeStreak(userId, now):
  today = localDate(now, user.timezone)                      // 'YYYY-MM-DD'
  days  = SELECT checkin_date FROM check_in WHERE user_id = ? AND status IN ('done','repaired') AND deleted_at IS NULL ORDER BY checkin_date DESC LIMIT 400
  set = HashSet(days); lastDone = days.first() ?? null; gap = dayDiff(today, lastDone)   // 空 → INF
  switch
    gap == 0 / gap == 1: state = NORMAL / PENDING_TODAY; cur = run(lastDone)   // gap=1 时今日未达标，天数不降
    2 <= gap <= 8 && balance > 0: state = REPAIRABLE; cur = run(lastDone)   // 断签可补
    default:   state = BROKEN;        cur = 0; break_reason = 'gap>window|no_card'
  user.streak_current = cur; user.streak_longest = max(user.streak_longest, cur)
  upsert streak_record(start = lastDone - cur + 1, end = lastDone, length = cur)
```

| 状态 | 触发条件 | 展示 | 允许动作 |
| --- | --- | --- | --- |
| `NORMAL` | `gap = 0`（今日已达标） | "28 天连续打卡 · 今日已达标" | 继续刷题（不重复加天） |
| `PENDING_TODAY` | `gap = 1` | "28 天 · 待完成 1/2" | 打卡，今日达标即 29 |
| `REPAIRABLE` | `2 ≤ gap ≤ 8` 且余额 > 0 | "断签可补 · 27 天" | 消耗 1 张卡补 `today-1` |
| `BROKEN` | `gap > 8` 或余额 = 0 | "已断签 · 重新开始" | 仅重建连续，不补历史 |

**补签规则**：1 张卡补 1 个自然日；只可补最近 **7 天**（`today-1..today-7`）；连续断签最多补 2 天（余额 2 张，与样例一致）；写 `check_in.status='repaired'`、`is_manual=1`、`repair_item_id`，扣减 `repair_card_balance` 并立即 `recomputeStreak`；补签**不增加** `total_ac`，也不改 `submission.counted`。

**时区与时钟**：`local_day` 在写入时由 `localDate(ts,'Asia/Shanghai')` 固化，历史行永不重算（改时区只影响新数据）；中国无夏令时，跨天边界恒为 `00:00:00.000+08:00`；未来支持 DST 时区时改用 `Intl.DateTimeFormat` 取日历日并补单测。时钟漂移：`since` 游标取平台返回时间；`sync_job.clock_skew_ms` 记录本机与 HTTP `Date` 头差值，`|skew| > 5min` 时该平台回看 48h 并告警。

| 方案 | 实现 | 优点 | 代价 / 边界 | 结论 |
| --- | --- | --- | --- | --- |
| ArkTS 单遍回溯 | 近 400 天入 Set，逐日回退 | 无方言依赖、可解释、纯函数易单测 | 读 ≤400 行（<5 ms） | **采用** |
| SQL 窗口函数 | `ROW_NUMBER()` + `date(d,'-n day')` 分组 | 一条语句，可与 ArkTS 对拍 | 依赖 SQLite ≥3.25 与 `date()` 的 UTC 语义，跨天易错 | 仅单测/校验 |
| 递归 CTE | 逐日递归 JOIN | 声明式 | 112+ 层递归，性能与可读性差 | 不采用 |

## 10. Schema 版本与迁移

| 项 | 约定 |
| --- | --- |
| 版本源 / v1 | `RdbStore.version` 为唯一权威（Preferences `cs.pref.schema_version` 仅作备份镜像）；v1 = 第 7 节 17 表 + 索引，`version=1`，首建在 `data/db/DatabaseHelper.ets` 单事务完成 |
| v2 策略 | **只增不删**：`ALTER TABLE ... ADD COLUMN ... NOT NULL DEFAULT x`；不重命名、不改类型、不删列；重命名/拆表用 `<table>_new` → `INSERT ... SELECT`（逐列显式）→ `DROP` → `RENAME`，单事务完成 |
| 失败处理 | 抛错即 `rollback`，`version` 不变，进入只读降级并提示"数据升级失败，可恢复云备份"，禁止半迁移运行 |
| 数据回填 | 迁移后一次性重算 `submission.counted`、`check_in`、`user.total_*`、`streak_*`，以 `trigger='manual'` 的 `sync_job` 记录耗时 |
| 备份配合 | `onBackup` 前 `wal_checkpoint(FULL)` 并写 `backup_meta`（schema_version、导出时间）；`onRestore(bundleVersion)` 比对版本，备份较低先迁移再恢复、较高（降级安装）拒绝加载并提示升级；**凭据密文不参与备份**，恢复后需重新绑定 |

## 11. 数据保留与清理

| 数据 | 保留 | 清理方式 |
| --- | --- | --- |
| 原始 `submission`（含 `extra`） | 180 天滚动 | 每日首次前台 `DELETE ... WHERE local_day < date('now','-180 day')`，单批 ≤500 行 |
| 聚合（`check_in`、`streak_record`、`user.total_*`、`problem`） | 永久 | 不清理；`user.total_ac` 每次重算与 `submission` 双向校验 |
| `sync_job` / `leaderboard_entry` | 90 天 / 24 个月 | 任务保留最近 20 条失败记录；榜单按 `period_key` 整期删除 |
| 墓碑（`deleted_at` 非空）/ 库空间 | 墓碑 90 天 | 墓碑到期物理删除，保留期内用于跨端冲突判定；每月 1 次 `VACUUM`（仅充电 + 前台 + 空闲触发），避免阻塞主线程 |
