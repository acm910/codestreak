# 技术架构设计

## 1. 目的与范围

本文确定 CodeStreak HarmonyOS 客户端的分层架构、技术选型、同步管线与关键架构决策，是 [工程结构与模块划分](02-工程结构与模块划分.md)、[数据模型设计](03-数据模型设计.md)、[平台同步与难度归一化](04-平台同步与难度归一化.md)、[状态管理与路由设计](05-状态管理与路由设计.md) 的上位约束。

- 覆盖：分层与依赖方向、模块边界、关键选型、同步与打卡数据流、ADR、风险。
- 不覆盖：表结构与索引（见 04-03）、平台字段映射与难度算法（见 04-04）、视觉与交互细节（见 02 系列）。
- 冲突裁决：架构冲突以本文为准；视觉冲突以 [设计令牌规范](../02-设计规范/02-设计令牌规范.md) 为准。

## 2. 设计目标与约束

| 编号 | 目标 / 约束 | 可验收口径 |
| --- | --- | --- |
| G-01 | 离线优先 | 断网可打开四个一级页；写操作先落 RDB，同步失败不阻塞打卡展示 |
| G-02 | 多平台聚合 | 统一以 `(platform, external_id)` 标识题目，跨平台同题用 `canonical_key` 聚合，难度归一为 1–5 星 |
| G-03 | 暗色单主题 | 仅 `#10141A` 画布，`setColorMode(COLOR_MODE_DARK)`，不维护浅色资源 |
| G-04 | 手机优先 | `deviceTypes: ["phone"]`，竖屏单列，断点仅 1 档（< 600vp） |
| G-05 | 无自建后端 MVP | 无账号服务器与云同步；数据存应用沙箱，卸载即清空，以导出兜底 |
| C-01 | 单 HAP | 仅 `entry` 模块；HAR/HSP 拆分阈值见 04-02 第 8 节 |
| C-02 | ArkTS 强约束 | 禁用 `any`、动态属性、运行时代码加载与反射式对象构造 |
| C-03 | 性能预算 | 冷启动首帧 ≤ 800ms、首屏可交互 ≤ 1.2s；一级页滚动 ≥ 55fps；总包 ≤ 30MB（HAP ≤ 20MB） |
| C-04 | 合规 | 仅同步本人账号；不高频抓取；导出路径由用户显式选择 |

当前工程 `compatibleSdkVersion "6.1.1(24)"`、`targetSdkVersion "26.0.0"`，状态管理 V2、`Navigation`、`PersistenceV2` 均可用；`bundleName` 需由 `com.example.project` 改为 `com.codestreak.app`（见 04-02 第 7 节）。

## 3. 总体架构

```text
┌──────────────────────────────────────────────────────────────────────┐
│ Presentation   pages/Index · views/ · components/                     │
│                渲染与事件上抛；可读 Store，不写 Store、不碰 RDB          │
├──────────────────────────────────────────────────────────────────────┤
│ Application    viewmodels/ · services/ · app/AppLifecycle             │
│                用例编排、事务边界、同步调度、事件分发                    │
├──────────────────────────────────────────────────────────────────────┤
│ Domain         domain/（纯 ArkTS，不 import @kit.*、不 import UI）      │
│                打卡判定 / 连续天数 / 补签策略 / 比赛窗口 / 排名计算       │
│                以 Port 声明外部能力（OjAdapter、Repositories、Clock）       │
├──────────────────────────────────────────────────────────────────────┤
│ Data           data/db · data/remote · data/repository · mapper       │
│                RDB/Preferences 实现、HTTP/Web 抓取、DTO → Entity 映射   │
├──────────────────────────────────────────────────────────────────────┤
│ Platform       entryability/ · workers/ · constants/ · utils/         │
│                生命周期、权限、后台任务、加密、日志、设计令牌             │
└──────────────────────────────────────────────────────────────────────┘
        调用方向 ▼ 自上而下；实现方向 ▲ Data 实现 Domain 声明的 Port
```

依赖规则（评审阻断项）：

1. Presentation 内部（pages/views/components）可互相引用；对外只允许 import Application / Model / Constants，禁止 import `data/**` 与 `services/**` 实现类。
2. Application 可 import Domain / Data / Model；Domain 只 import `model/**`，禁止 import 其他层与任何 `@kit.*`。
3. Data 实现 Domain 的 Port；装配只在 `app/AppContainer` 启动时完成，禁止在 DAO 内 new Service。
4. 跨层只传 Entity / DTO / 值对象；禁止传 `Resource`、`Color`、`UIContext` 等 UI 类型。
5. Service 之间只通过 `AppContainer` 暴露的接口调用，禁止静态类互相引用形成环。
6. 事件只描述"已发生的事实"（`SYNC_DONE`、`CHECKIN_CHANGED`），不得作为命令使用。

### 3.1 冷启动时序

```text
UIAbility.onCreate(want)
  → DeepLinkParser 暂存 want.uri / want.parameters（不立即跳转）
  → AppContainer.init(context)          // 只装配，不做 I/O
  → DatabaseHelper.open()               // 读 user_version，按需执行 Migrations
  → Preferences 读取 lastTab、auth.userId
  → PersistenceV2.connect(SettingsStore / FilterStore)
  → windowStage.loadContent('pages/Index')
  → 首帧渲染（Skeleton C-40 占位）
  → 异步：SyncScheduler.tryStart('foreground')   // 冷启动按前台触发
  → 异步：CheckInService.loadToday() / StreakService.load()
  → RouterService.applyPending()        // Tab 挂载后消费深链
```

`loadContent` 前不得同步发起网络请求或全表查询，阻塞预算 50ms；`onCreate` 只做装配与解析。

### 3.2 并发模型

- 主线程：仅 UI 与 Store 写入。Store 字段更新必须回到主线程，禁止在 taskpool 内改 `@Trace`。
- 数据库：relationalStore 线程安全，但写事务必须串行；所有写操作经 `AppContainer` 持有的单队列 `DbExecutor`，规避 `database is locked`。
- 网络：每平台一个串行队列（`RateLimiter` 1 req/2s），平台之间并发上限 2，避免触发风控。
- 解析：HTML > 64KB 或单次解析 > 8ms 时投递 taskpool（`workers/SyncParserTask.ets`），入参与返回值必须可序列化。
- 禁止在 worker/taskpool 内访问 UI、Store、AbilityContext。

## 4. 模块职责

| 目录 | 职责 | 允许依赖 | 禁止 |
| --- | --- | --- | --- |
| `entryability/` | Ability 生命周期、窗口配置、深链入口、首帧前初始化 | Platform、Application | 业务查询、UI 构建 |
| `pages/` | 唯一 `@Entry`：`Tabs` + 4 个 `Navigation` 容器 | views、constants | 具体业务渲染、网络请求 |
| `views/` | P-01…P-12 页面内容（`NavDestination` 根） | components、viewmodels | 直接读写 RDB、拼 SQL |
| `components/` | C-xx 展示与输入组件，无业务查询 | model、constants、utils | import services/data |
| `viewmodels/` | 页面状态编排、表单校验、调用 Service、订阅事件 | services、model、constants | 持有 `Context`/`UIContext` 长引用 |
| `domain/` | 纯规则与 Port 接口，可单测 | model | I/O、`@kit.*`、UI 类型、全局单例 |
| `services/` | 用例编排、事务边界、调度、通知 | domain、data、model | 直接操作 UI、返回 `Resource` |
| `data/db` | RDB 连接、Schema、迁移、DAO | model、constants | 业务规则、格式化文案 |
| `data/remote` | HTTP、Cookie、限流、4 个 OjAdapter、HTML 抽取 | model、domain Port、utils | 直接写库、依赖 Store |
| `data/repository` | 聚合多表、缓存、DTO ↔ Entity 映射 | db、remote、model | 抛 UI 异常、拼提示语 |
| `model/` | Entity、DTO、枚举，无行为 | 无 | 依赖任何上层、含 I/O |
| `constants/` `utils/` | 令牌、路由表、配置、日志、日期、加密 | 无（utils 可依赖 constants） | 存放可变全局状态 |
| `workers/` | 可选：大 HTML 解析卸载到 taskpool | 纯函数、model | 持有 AbilityContext |

## 5. 关键选型

| 能力 | 选型 | 理由 | 备选与否决 |
| --- | --- | --- | --- |
| UI 框架 | ArkUI 声明式 + `@ComponentV2` | NEXT 唯一一等公民；属性级 diff；V2 深度观测 | 类 Web 范式（无 DOM/动态性）；Flutter/RN（NEXT 无官方运行时） |
| 结构化存储 | `@kit.ArkData` relationalStore（SQLite） | 事务、索引、聚合查询（热力图/周月榜）、可迁移 | Preferences（无查询能力）；JSON 文件（并发与部分写风险） |
| 轻量配置 | Preferences | 冷启动毫秒级、KV、无 schema 负担 | RDB（为十余个开关建表过重） |
| 网络 | `@kit.NetworkKit` http | 官方稳定，超时/重试/证书校验齐全，与 Cookie 管理可组合 | 再引入 rcp 形成双栈（v1 不引入）；自研 socket（无必要） |
| 登录态抓取 | Web 组件 + `WebCookieManager` + http | 复用真实登录流程，规避验证码与风控；Cookie 显式同步给 http | 逆向私有接口（易失效、合规风险高） |
| 本地提醒 | `@kit.NotificationKit` + reminderAgentManager | 闹钟式提醒，进程被杀仍生效，无需常驻 | 后台定时器（不可靠、耗电）；WorkScheduler（不保证准时） |
| 后台任务 | `@kit.BackgroundTasks` 短时任务 | 单次同步 < 3min，短时任务足够且合规 | 常驻 Service（NEXT 不允许）；长时任务（需 KEEP_BACKGROUND_RUNNING，审核敏感） |
| 导出 | `@kit.CoreFileKit`（Picker + fileIo） | 用户选目录授权 URI，免存储权限 | 直写 Downloads（需权限且受限） |
| 加密 | `@kit.CryptoArchitectureKit` AES-256-GCM + `@kit.UniversalKeystoreKit` | Cookie 落盘加密，密钥存 HUKS 不出 TEE，满足 linter 安全规则 | 明文/Base64（不合格）；自管密钥（易泄漏） |
| 日志 | `@kit.PerformanceAnalysisKit` hilog | 域 + 级别 + `%{public}s`/`%{private}s` 脱敏，可被 hdc 过滤 | `console.log`（无级别、无法脱敏） |
| 路由 | `@kit.ArkUI` Navigation + `NavPathStack` | 官方推荐，支持分栈、参数、转场与拦截，替代 router | `@ohos.router`（能力弱且不再演进） |

选型细化（Cookie、难度、限流）见 [平台同步与难度归一化](04-平台同步与难度归一化.md)；每个否决项的理由沉淀为第 9 节 ADR。

## 6. 数据流与同步管线

### 6.1 触发时机

| 触发 | 前置条件 | 范围 |
| --- | --- | --- |
| 冷启动 | 首帧后、距 `last_sync_at` > 6h | 全平台增量 |
| 前台恢复 | `onForeground` 且距 `last_sync_at` > 6h，每日 ≤ 12 次 | 全平台增量 |
| 手动下拉 | 用户显式操作，60s 内合并 | 强制刷新当前页数据 |
| 通知点击 | 比赛提醒 / 打卡提醒 | 仅对应平台 |
| v1.1 延迟任务 | v1.0 不做后台常驻；v1.1 再评估 WorkScheduler（≥ 20min，不保证准时） | 增量 |

### 6.2 管线

```text
[触发]              [Application]                 [Domain]          [Data]                [外部]
AppLifecycle ─┐
PullToRefresh ─┼─> SyncScheduler ──> SyncOrchestrator
ReminderClick ─┘        │                    │
                        │ ① 建 sync_job(queued) ├────────────────> SyncJobDao
                        │ ② 读账号与游标         ├────────────────> AccountDao
                        │ ③ adapter.fetch(since) │                 OjAdapter ──> HTTP/Web ──> OJ
                        │                       │<── RawSubmission[]
                        │ ④ 归一化 ────────────> Normalizer（04-04）
                        │                       │<── Submission[]（difficulty 1..5）
                        │ ⑤ 幂等落库             ├────────────────> SubmissionDao（单事务）
                        │ ⑥ 打卡判定 ──────────> CheckInEvaluator
                        │ ⑦ 连击重算 ──────────> StreakCalculator
                        │ ⑧ 写 CheckIn/Streak    ├────────────────> CheckInDao / StreakRecordDao
                        │ ⑨ 完成 sync_job        ├────────────────> SyncJobDao
                        ▼
              EventBus.emit(SYNC_DONE | CHECKIN_CHANGED)
                        │
                        ▼
        SyncStore / CheckInStore @Trace ──> 页面 getter / @Monitor ──> 局部重渲染
```

`sync_job.status` 状态机：`queued → running → success | partial | failed | canceled`。`partial` 表示部分平台失败；同一平台同时只允许一个 `running`，失败重试上限 3 次、指数退避（2s/8s/30s），重试时刻写入 `scheduled_at`。事件总线统一为 `EventBus`，同步主题对外暴露为 `SyncEventBus`（见 [平台同步与难度归一化](04-平台同步与难度归一化.md) 第 2 节）。

### 6.3 幂等与事务

- 唯一键：`submission(platform, external_id)`、`problem(platform, external_id)`、`check_in(user_id, checkin_date)`、`contest(platform, external_id)`，与 [数据模型设计](03-数据模型设计.md) 第 7 节索引一致。
- 写库统一在 DAO 内执行 `INSERT ... ON CONFLICT(...) DO UPDATE`，一个平台一次拉取 = 一个事务；失败整体回滚，`sync_job` 记 `failed`。
- 重复拉取不产生重复行；打卡按 `checkin_date` **全量覆盖**而非累加，重放安全。
- UI 不感知 `sync_job`：页面只消费 Store 的 `dataVersion` 与 `lastSuccessAt`。

### 6.4 失败与降级

| 失败 | 判定 | 处理 |
| --- | --- | --- |
| 网络超时 | 10s 无响应，重试 2 次仍失败 | 标 `failed`，保留旧数据，Toast 提示"稍后重试" |
| 鉴权失效 | 401 / 跳转登录页 / Cookie 缺失 | 标 `partial`，`platform_account.auth_state='expired'`，引导 P-09 重登 |
| 解析失败 | 关键字段缺失或选择器命中 0 条 | 记录平台与选择器版本，降级为"未获取到新数据"，不写脏数据 |
| 频繁限流 | 429 或连续 3 次非预期响应 | 指数退避并暂停该平台 30min，写入 `sync_job.error_code` |
| 进程被杀 | 启动时发现 `running` 状态的 Job | 置为 `canceled`，不自动重试，等下一次触发 |

## 7. 打卡判定与连续天数：领域服务定位

- 位置：`domain/checkin/`，纯函数、零 I/O，Hypium 可直接覆盖跨日、时区、重复 AC、补签等分支。
- 调用链：`CheckInService.recordSolve()` → `CheckInEvaluator.evaluate()` → `StreakCalculator.recompute()` → `CheckInRepository.save()`（单事务）→ `EventBus.emit(CHECKIN_CHANGED)`。
- 判定口径（与 [数据模型设计](03-数据模型设计.md) 第 9 节一致）：
  1. 只计 `verdict='AC' AND counted=1`；同一 `canonical_key` 在 30 天去重窗口内只计 1 次；
  2. 日界为设备本地时区 00:00，`checkin_date` 写入时固化，改时区不回算历史；
  3. `goal` 默认 2、取值 1–20（来源 `user.daily_goal`），`achieved = acCount >= goal`；
  4. 补签卡只补最近 1–7 天（`today-1..today-7`），余额存 `user.repair_card_balance`，连续断签最多补 2 天；补签只续链、不加 `total_ac`；
  5. 连续天数四态 `NORMAL / PENDING_TODAY / REPAIRABLE / BROKEN`；今日未达标不立即断链。
- 禁止：在 ViewModel 里算 streak；在 SQL 里用窗口函数拼连续天数（规则变更成本高且难测）。

```ts
// domain/checkin/CheckInEvaluator.ets —— 无 I/O，可单测
export interface CheckInInput {
  checkinDate: string;            // 本地 YYYY-MM-DD
  solvedCanonicalKeys: string[];  // 当日去重后的 canonical_key
  goal: number;
  now: number;                    // 注入时钟，便于测试
}
export interface CheckInResult {
  checkinDate: string;
  acCount: number;
  achieved: boolean;
  firstAcAt: number;
}
export function evaluate(input: CheckInInput): CheckInResult;
```

## 8. 实体与字段口径（与 04-03 对齐）

字段与 DDL 的**唯一权威**是 [数据模型设计](03-数据模型设计.md)，本文不重复 17 张表。架构层锁定以下跨文档口径，其他文档与实现不得改写：

| 口径 | 约定 | 依据 |
| --- | --- | --- |
| 主键 | `id INTEGER PRIMARY KEY AUTOINCREMENT`，本地自增，不对外暴露 | 04-03 §6.1 |
| 题目标识 | `problem(platform, external_id)` 唯一；跨平台同题用 `canonical_key` 聚合 | 04-03 §6.3 |
| 提交标识 | `submission(platform, external_id)` 唯一；统计只认 `verdict='AC' AND counted=1` | 04-03 §6.3 |
| 日期 | `local_day` / `checkin_date` 为 `TEXT 'YYYY-MM-DD'`，写入时按用户时区固化 | 04-03 §3 |
| 难度 | `difficulty_norm REAL 1.0–5.0`（步长 0.5），生效值 `COALESCE(difficulty_override, difficulty_norm)` | 04-03 §3 |
| 连续天数 | 由 `check_in` 派生写入 `user.streak_current` / `streak_longest`，UI 与同步层只读 | 04-03 §9 |
| 补签 | 扣 `user.repair_card_balance`，写 `check_in.status='repaired'`；窗口 7 天、最多补 2 天 | 04-03 §9 |
| 设置 | `app_setting(user_id, key, value)` KV；启动型轻量标记走 Preferences | 04-03 §6.2 |
| 同步任务 | `sync_job.status` 取 `queued/running/success/partial/failed/canceled` | 04-03 §5 |

命名映射：RDB 列 snake_case ↔ ArkTS 字段 camelCase（`external_id` ↔ `externalId`、`checkin_date` ↔ `checkinDate`、`repair_card_balance` ↔ `repairCardBalance`），映射只发生在 `data/mapper` 与实体列常量中，业务层只见 camelCase。

## 9. 架构决策记录（ADR）

| 编号 | 决策 | 背景 | 备选 | 结论 | 影响 |
| --- | --- | --- | --- | --- | --- |
| ADR-01 | 无自建后端 vs 轻后端 | MVP 需聚合 4 平台但无服务端资源 | 轻后端代抓、纯本地 | 采纯本地；v1.1 若做跨设备再引入轻后端，且不代理 OJ 请求 | 无服务端成本；换机靠导出；Cookie 只存本机 |
| ADR-02 | RDB vs 文档存储 | 热力图、周月榜、题单进度需聚合 | 纯 JSON 文件、Preferences | 采 relationalStore，Preferences 仅存标量 | 需维护 Schema 与迁移；查询能力换来实现成本 |
| ADR-03 | ArkUI V1 还是 V2 | 模板为 V1，需一次定型避免返工 | V1、V1/V2 混用 | 新代码全量 V2；边界用适配组件包 V1 | 团队需统一心智；禁止同组件混用装饰器 |
| ADR-04 | Web 抓取 vs 官方 API | 4 平台开放程度不同 | 全 API、全抓取 | 优先公开 API/GraphQL，缺失或需登录态时用 Web + Cookie；限速 1 req/2s | 稳定性依赖页面结构；适配器需可降级 |
| ADR-05 | 单 HAP vs 多 HAR | 当前仅 entry，团队规模小 | 立即拆多模块 | v1 单 HAP，按 04-02 阈值演进 | 早期迭代快；后期需一次结构迁移 |
| ADR-06 | 离线优先策略 | 移动网络不稳定，OJ 可能限流 | 在线优先、强一致 | 本地为唯一事实源，远端只做增量合并；冲突以平台最新提交时间为准 | 需幂等与全量重算；不提供删除传播 |
| ADR-07 | 主题策略 | 设计仅交付暗色，浅色未验收 | 跟随系统、双主题 | 强制 `COLOR_MODE_DARK`，删除 `resources/dark` 副本 | 少一半令牌与测试矩阵；需在设置页说明 |

## 10. 可观测性与诊断

- hilog 域划分：`0x0C01` app、`0x0C02` sync、`0x0C03` db、`0x0C04` ui；release 仅输出 WARN 及以上。
- `sync_job` 即本地审计日志：保留 90 天、最近 20 条失败，P-10 可查看失败原因与时间。
- 关键指标仅本地统计、不上报：同步成功率、单次平均耗时、解析失败次数、冷启动耗时。
- 隐私：Cookie/token 只允许 `%{private}s` 或哈希后 8 位出现；导出文件不含任何凭据。
- Debug 构建下，设置页连点版本号 5 次打开调试面板（dataVersion、最近 Job、强制同步、清缓存）。

## 11. 风险与缓解

| 风险 | 触发信号 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 平台页面/接口变更 | 适配器解析成功率骤降、字段缺失 | 同步失败、数据陈旧 | 适配器隔离 + 契约测试 + 失败降级为"仅手动录入"；灰度开关 |
| ToS 与反爬合规 | 出现验证码、429、封号反馈 | 账号风险、上架审核风险 | 只同步本人数据、串行限速、随机抖动、不并发轰炸；文档留存合规说明 |
| 鉴权失效 | Cookie 过期、401/跳登录 | 无法同步 | 加密存储 + `expiredPlatforms` 标红 + 一键重登引导 |
| 包体积 | 字体/Web 内核资源增长 | 下载转化下降 | 字体子集化 ≤ 2MB（中文用系统字体）、rawfile 分级、HAP 体积门禁 20MB |
| 性能 | 热力图/长列表掉帧、冷启动超时 | 体验下降 | 懒加载 + `LazyForEach` + 分页；首帧前不做全量查询 |
| 数据丢失 | 卸载、清数据、迁移失败 | 用户资产损失 | 迁移事务 + 备份扩展 + P-12 导出（JSON/Markdown） |
