# 平台同步与难度归一化

## 1. 目的与范围

本文定义四平台（LeetCode 中国站、Codeforces、洛谷、AtCoder）的**采集边界、适配器契约、难度归一化公式、打卡判定、补签与连续天数状态机、幂等与降级、合规与可观测性**。数据落库结构见 [数据模型设计](03-数据模型设计.md)；模块分层与目录见 [技术架构设计](01-技术架构设计.md)、[工程结构与模块划分](02-工程结构与模块划分.md)；术语见 [术语表与数据字典](../01-产品设计/04-术语表与数据字典.md)。

> **端点、请求头、字段映射与限流的实际契约**统一维护在 [技术栈与外部接口](07-技术栈与外部接口.md) §6；本文只描述同步流程与算法，二者冲突时以 04-07 的接口事实为准、以本文的流程为准。

**硬边界**：只同步用户本人主动绑定的账号；不抓取他人数据、不抓题面全文（只存标题/难度/标签/URL）；任何平台接口失效都必须降级为"本地可用 + 明确提示"，不得阻断打卡。

**同步模式（统一三类，任一平台必须能落到模式 C）**

| 模式 | 含义 | 平台与优先级 | 数据来源 |
| --- | --- | --- | --- |
| A 自动同步 | 官方或公开只读接口，无需登录 | Codeforces（官方 API，P0）、AtCoder（kenkoooo AtCoder Problems 公开 API，P1） | 公开接口 |
| B 授权同步 | App 内置 WebView 完成平台登录，只读**用户本人**提交记录，Cookie 存 HUKS | LeetCode 中国站（GraphQL + `csrftoken`/`LEETCODE_SESSION`，P1）、洛谷（`record/list?_contentOnly=1` 公开接口优先，失败退化为登录态，P1） | 用户授权 |
| C 手动确认 | 深链跳转平台做题，返回 App 手动打卡 | **所有平台的兜底模式**，也是 v1 保底可用路径 | 用户确认 |

- 降级链：**A → C、B → C**。任一平台在 A/B 不可用时自动降级为模式 C，不得写成"LeetCode/洛谷无公开 API 故只能手动"——它们是授权同步，只是失败后才落到手动。
- UI 强制展示：平台卡与今日卡必须同时显示"同步方式（自动/授权/手动）+ 上次同步时间"，禁止让模式 C 的数据看起来像自动同步；`platform_account.sync_mode` 为唯一数据源。

## 2. 同步总体流程

```text
触发源               SyncOrchestrator           OjAdapter(平台)          RdbStore                UI
  │ timer/前台/手动/首次/赛后 │                        │                       │                    │
  ├─────────────────────────►│ 1. 入队 sync_job(status=queued)               │                    │
  │                          ├──────────────────────────────────────────────►│                    │
  │                          │ 2. 读取 sync_cursor + 申请限流令牌             │                    │
  │                          ├───────────────────────►│ 3. fetchSubmissions(since, cursor)          │
  │                          │                       ├─ GET 端点（UA + 凭据 + 退避）               │
  │                          │◄──────────────────────┤ 4. 原始 JSON / HTTP 错误码                  │
  │                          │ 5. map：平台字段 → SubmissionDTO / verdict 枚举                    │
  │                          │ 6. normalize：difficulty_raw → difficulty_norm（第 6 节）           │
  │                          ├─ 7. 单事务 upsert：problem → submission → check_in → streak         │
  │                          ├──────────────────────────────────────────────►│                    │
  │                          │ 8. sync_job → success/partial/failed（含 counts、error_code）      │
  │                          ├──────────────────────────────────────────────►│                    │
  │                          │ 9. emit SyncEvent(platform, daySet, counts) ──────────────────────►│
  │                          │                                                   10. @Monitor 精准刷新今日卡/热力图
```

- 步骤 7 与 8 在同一事务边界内完成（先写事实表，再写任务结果）；任一失败整体回滚，`sync_job` 以独立事务落 `failed`，避免"数据写了但状态丢了"。
- 步骤 9 只发事件不发数据，UI 通过 `SyncEventBus` 订阅；跨 Tab 刷新由 `@Monitor` 按 `local_day` 精确触发，不整页重绘。
- 单平台失败不抛出到编排层（见第 9 节），`partial` 状态必须携带 `partial_reason`。

## 3. 触发源

| 触发 | 时机 | 范围 | 节流 / 约束 |
| --- | --- | --- | --- |
| `timer`（每日定时） | 由 `reminderAgentManager` 在 21:30 发布提醒，用户点开 App 后执行 | 全平台增量 | HarmonyOS 后台受限，v1.0 **不做后台常驻同步**；提醒与同步解耦，提醒失败不影响同步 |
| `foreground`（前台恢复） | `EntryAbility.onForeground` 且距 `last_sync_at` > 6h | 全平台增量 | 每日最多 12 次，避免频繁拉取 |
| `manual`（手动） | 下拉刷新、"OJ 元数据同步管理"页按钮 | 单平台或全平台 | 60s 内合并为一次，防止连点 |
| `first_bind`（首次绑定） | 绑定成功后立即执行 | 该平台近 180 天全量 + 题目元数据 | 全量分页 `count=1000`，最多 20 页，超限记 `LIMIT_EXCEEDED` |
| `contest_followup`（赛后追踪） | 关注比赛 `end_at` 后 30 分钟 | 该平台 | 用于生成 `upsolve_task`；仅一次，失败不重试 |

模式 C 平台不参与 `timer`/`foreground`/`first_bind` 的自动拉取，只响应 `manual`（用户手动打卡后本地落库）；UI 按 `platform_account.sync_mode` 显示"自动/授权/手动"徽标。

## 4. OjAdapter 接口契约

```ts
export type Platform = 'leetcode' | 'codeforces' | 'atcoder' | 'luogu';
export type AuthMode = 'none' | 'cookie' | 'token' | 'webview';
export type Verdict = 'AC' | 'WA' | 'TLE' | 'MLE' | 'RE' | 'CE' | 'PE' | 'OLE' | 'OTHER';
export type OjErrorCode = 'NET_OFFLINE' | 'NET_TIMEOUT' | 'AUTH_EXPIRED' | 'AUTH_INVALID' | 'RATE_LIMITED'
  | 'BLOCKED' | 'PARSE_ERROR' | 'UNSUPPORTED' | 'LIMIT_EXCEEDED' | 'PLATFORM_5XX';

export interface SyncCursor { sinceMs: number; pageToken?: string; }
export interface RateLimit { minIntervalMs: number; burst: number; dailyQuota?: number; }
export interface SyncProfile { userId: string; handle: string; full: boolean; sinceMs: number; maxItems: number; }
export interface SyncPage<T> { items: T[]; hasMore: boolean; nextCursor?: SyncCursor; fetchedAtMs: number; }
export interface SubmissionDTO {
  externalId: string; platform: Platform; problemExternalId: string; problemTitle: string;
  problemIndex?: string; verdictRaw: string; verdict: Verdict; submittedAtMs: number;
  language?: string; difficultyRaw?: string; rating?: number; tags?: string[]; contestExternalId?: string; url?: string;
}
export interface ProblemDTO { externalId: string; title: string; difficultyRaw?: string; rating?: number; tags?: string[]; url: string; }
export interface ContestDTO { externalId: string; title: string; startAtMs: number; endAtMs?: number; durationMin?: number; url: string; division?: string; ratedLimit?: string; }
export interface ParsedProblemSet { title: string; sourceUrl: string; platform: Platform; items: Array<{ externalId: string; orderNo: number }>; }
export interface HealthResult { ok: boolean; latencyMs: number; authState: 'valid' | 'expired' | 'unknown'; message?: string; }

export interface OjAdapter {
  readonly platform: Platform;
  readonly authMode: AuthMode;
  readonly rateLimit: RateLimit;
  syncProfile(profile: SyncProfile): Promise<SyncPage<SubmissionDTO>>;              // 首次绑定全量
  fetchSubmissions(since: number, cursor?: SyncCursor): Promise<SyncPage<SubmissionDTO>>; // 增量
  fetchProblems(ids: string[]): Promise<ProblemDTO[]>;                            // 批量补元数据/难度
  fetchContests(fromMs: number, toMs: number): Promise<ContestDTO[]>;             // 日历与赛后追踪
  parseProblemSet(url: string): Promise<ParsedProblemSet>;                        // 公开题单导入
  healthCheck(): Promise<HealthResult>;                                           // 绑定校验/连通性
}
export class OjError extends Error {
  constructor(readonly code: OjErrorCode, message: string, readonly retryable: boolean) { super(message); }
}
```

| 错误码 | 语义 | 可重试 | UI 动作 |
| --- | --- | --- | --- |
| `NET_OFFLINE` / `NET_TIMEOUT` | 无网络 / 超时 | 是 | 提示离线，使用缓存，排队等待 |
| `AUTH_EXPIRED` / `AUTH_INVALID` | 登录态过期 / 凭据无效 | 否 | 跳转重新绑定，保留历史数据 |
| `RATE_LIMITED` / `BLOCKED` | 被限流 / 被风控 | 限流可重试，风控不可 | 退避后重试；风控禁止绕过，提示稍后再试 |
| `PARSE_ERROR` | 返回结构变更（HTML/JSON 不匹配） | 否 | 上报埋点 + "平台接口变更，已降级" |
| `UNSUPPORTED` | 该能力平台不支持（如 AtCoder 无官方 API） | 否 | 隐藏入口或改走第三方源 |
| `LIMIT_EXCEEDED` | 超出全量页数/条数上限 | 否 | 提示仅同步最近 N 条 |
| `PLATFORM_5XX` | 平台服务端错误 | 是 | 1m/5m/15m 退避 |

约定：适配器**不写库、不算打卡、不做难度归一化**，只负责"拉取 + 字段映射 + 抛 OjError"；归一化与判定在 Domain 层纯函数中完成，便于单测。契约文件位置按 [工程结构与模块划分](02-工程结构与模块划分.md)：接口 `domain/port/OjAdapter.ets`，四实现与 DTO 分别在 `data/remote/adapters`、`data/remote/dto`。

## 6. 难度归一化

```text
# ① Elo 线性映射（Codeforces rating / AtCoder 难度近似值）
raw = clamp(1, 5, 1 + (rating - 800) / 400)
# ② 量化到 0.5 档：半档（0.25 / 0.75）向下取整，保证 900→1.0、1200→2.0
k   = floor(raw * 2 + 0.5 - 1e-9)
out = k / 2
```

| 平台 | 原始难度 | 归一化 `difficulty_norm` | 备注 |
| --- | --- | --- | --- |
| Codeforces | `problem.rating`（800–3500） | 公式 ① + ② | 无 rating（如未定级）→ 兜底 3.0 |
| AtCoder | kenkoooo `problem-models.difficulty`（非官方） | 公式 ① + ② | 尺度与 CF rating 不完全等价，**待验证**；缺失 → 3.0 |
| LeetCode | `Easy` / `Medium` / `Hard` | `2` / `3` / `4.5` | `acRate` 仅展示，不参与归一化 |
| 洛谷 | 站内难度 0–7 | `1`/`1.5`/`2`/`3`/`4`/`4.5`/`5`（对应入门、普及−、普及/提高−、普及+/提高、提高+/省选−、省选/NOI−、NOI） | 0 = 暂无评定 → 3.0 |
| 任意 | 解析失败/未知 | `3.0`，`difficulty_source='fallback'` | 不猜测，不阻塞入库 |
| 人工覆盖 | `difficulty_override`（用户手改） | **优先级最高**，`COALESCE(difficulty_override, difficulty_norm)` | 覆盖不改 `difficulty_norm`，可随时回退 |

> 纯四舍五入会把 CF 900 抬到 1.5，与产品样例（900→1）冲突，故量化规则显式定为"半档向下"；该规则对所有 100 分倍数完全等价于向下取整到 0.5 档。

## 7. 打卡判定、补签与连续天数

**当日窗口**：`[local_day 00:00:00.000, 次日 00:00:00.000)`，`local_day` 由 `localDate(submitted_at, user.timezone)` 固化为 `Asia/Shanghai`；跨天边界不按 UTC 切（否则 08:00 前的提交会算到前一天）。

| 规则 | 定义 | 实现位置 |
| --- | --- | --- |
| AC 去重 | 同一 `platform + external_id` 唯一；`AC` 之外判罚不计数 | `submission` 唯一索引 |
| 跨平台计数 | 按 `canonical_key` 计数，同题在洛谷与 LeetCode 各 AC 只算 1 题 | `counted` 字段 + 部分唯一索引 |
| 重复刷题 | 同一 `canonical_key` 近 `dedupe_window_days`（默认 30）天只计 1 次，防刷旧题冲打卡 | 写入事务内的窗口查询 |
| `daily_ac_count`（可 >2） | 当日全部 AC 去重数，用于热力图档位与"今天已打卡 N 题"；**补题（upsolve）计入** | `COUNT(DISTINCT canonical_key)` |
| `daily_target_progress`（0–2） | 只统计 P-01 两张目标卡（C-06 今日核心推荐、C-07 竞赛挑战）的完成数，驱动"还差 1 题 / 今日已拉满 2/2"与连续天数；**补题计入 `daily_ac_count`、总 AC 与难度分布，但不计入本字段** | `COUNT(DISTINCT target_slot)` |
| 达标条件 | `daily_target_progress ≥ goal`（术语表 `daily_target`，默认 2）→ `check_in.status='done'`，当日最多 +1 天 | `services/streak` |
| 手动补录（模式 C） | 必须提供题目 URL、日期、平台、题号；校验域名白名单、题目已在 `problem` 表、日期 ≤ 今天、当日手动补录 ≤1 条；由目标卡发起的手动打卡写 `target_slot` 并计入目标进度，补题类手动记录不计；`source='manual'` 不得伪装成自动同步 | `ManualEntryService` |
| 防作弊 | 同题多平台只计一题；手动补录不计入当日 `counted` 之外的任何加成；补录不触发补签 | 上述两条合并生效 |

**补签规则**：1 张补签卡补 1 个自然日；只可补最近 **7 天**；连续断签最多补 2 天；v1.0 补签卡**仅由里程碑发放**（连续第 7/30/100 天各 1 张），不售卖、无支付入口（"获取道具"只展示规则）。样例生涯最长 64 天已过 D7/D30 两个里程碑 → 余额 2 张（未使用）。补签只恢复连续天数，**不增加** `daily_ac_count`/`total_ac`、不改 `submission`；使用后立即重算并写 `repair_count`。

**今日沉浸时间**：`focus_minutes` = 外跳做题的往返估算（深链离开与返回的时间差，单题上限 30 分钟，同题多次往返取最长），无样本时显示 `--`（不显示 0 分钟误导）；与打卡判定解耦，仅用于战报展示。

| 状态 | 条件 | 文案 | 动作 |
| --- | --- | --- | --- |
| `NORMAL` | 今日已达标（`gap=0`） | "28 天连续打卡 · 今日已达标" | 继续刷题不加天 |
| `PENDING_TODAY` | 今日未达标（`gap=1`） | "28 天 · 待完成 1/2" | 打卡后 29 |
| `REPAIRABLE` | `2 ≤ gap ≤ 8` 且余额 > 0 | "断签可补 · 27 天" | 消耗 1 张补 `today-1`，余额 2→1 |
| `BROKEN` | `gap > 8` 或余额 = 0 | "已断签 · 重新开始" | 仅重建，不补历史 |

**时区 / 夏令时 / 时钟漂移**：v1.0 固定 `Asia/Shanghai`（无夏令时，边界恒定）；用户改时区只影响新数据，历史 `local_day` 不重算。所有"今天"判定统一走 `TimeService.today()`（单例可注入，便于单测与跨天模拟）。`since` 游标取平台返回时间，`clock_skew_ms` 记录本机与 HTTP `Date` 头差值，`|skew| > 5min` 时该平台回看 48h 并告警。

## 8. 幂等与冲突

| 场景 | 规则 | 实现 |
| --- | --- | --- |
| 重复拉取同一提交 | 唯一键 `(platform, external_id)` 命中即更新，`id` 不变 | `INSERT ... ON CONFLICT DO UPDATE`（Upsert 支持**待验证**，不支持则事务内 `SELECT` → `UPDATE`/`INSERT`） |
| 同题重复 AC | `counted` 只置 1 一次；再次 AC 仅更新 `ac_at` | 日级部分唯一索引 + 窗口查询 |
| 乱序到达 | 以 `submitted_at` 排序落库，不依赖到达顺序；`since` 固定回看 48h 覆盖延迟 | 重叠窗口 + 幂等写 |
| 远端与本地冲突 | 事实字段（`verdict`、`submitted_at`、`language`）以远端为准；用户字段（`note`、`is_upsolve`、`difficulty_override`、`is_pinned`）以本地为准 | 列级白名单更新，不做整行覆盖 |
| 手动打卡幂等 | `source='manual'` 的 `external_id` 由 `manual:<local_day>:<题号>` 生成，重复提交不新增 | `submission` 唯一键 |
| 删除与复活 | 本地墓碑优先：`deleted_at` 非空的行不被远端 upsert 复活 | upsert 时 `WHERE deleted_at IS NULL` |
| 手动补录 vs 同步 | 同日同题若远端已有 AC，手动补录自动作废并提示 | 写入前查 `counted=1` |

## 9. 失败与降级

- **退避重试**：`NET_*` / `PLATFORM_5XX` / `RATE_LIMITED` 按 **1m / 5m / 15m** 三次退避（带 ±20% 抖动）；4xx 鉴权类不重试，直接提示重绑。
- **单平台隔离**：编排层用 `Promise.allSettled` 并发四平台，任一失败只影响自身 `sync_job`，整体状态置 `partial` 并给出"3/4 平台同步成功，洛谷登录已过期"。
- **鉴权过期**：`platform_account.auth_state='expired'`，停止该平台自动同步，保留历史与本地打卡；入口处显示"重新绑定"。
- **离线队列**：无网时 `sync_job` 保持 `queued` 并记录 `scheduled_at`；`NetworkKit` 网络恢复回调触发消费；手动打卡离线照常落库。
- **降级到缓存**：日历、题单、榜单读取最近一次快照并标注"数据截至 19:42"；难度缺失走 3.0 兜底而非留空。
- **部分成功提示**：Toast 只报差异（哪个平台、什么原因、如何修复），不打断今日打卡主流程。

## 10. 合规与安全

| 项 | 要求 |
| --- | --- |
| 数据范围 | 仅同步用户本人主动绑定的 handle/登录态；不采集他人提交、不做爬虫式全站抓取 |
| 凭据 | Cookie/token 由 HUKS 密钥加密后存 Preferences，RDB 只存 `cred_ref` 与指纹；解绑即删除密文；凭据不随云备份迁移 |
| 传输 | 全部 HTTPS；`@kit.NetworkKit` 校验证书，禁止明文 HTTP 与自签证书豁免 |
| ToS / robots | 遵守各站服务条款与 `robots.txt`；只读取用户可见的记录列表与题单元数据，不抓题面、不绕过付费墙与风控 |
| 限速与 UA | 每平台独立令牌桶（CF 1 req/2s、洛谷 1/1.5s、AtCoder 1/1s）；UA 固定 `CodeStreak/1.0 (HarmonyOS; +contact@codestreak.app)`，便于站点识别与申诉 |
| 隐私政策要点 | 数据本地优先、无自有后端上传；v1 仅导出 `.ics` 日历（不含凭据）与一键彻底删除；第三方平台数据仅在本地缓存 180 天 |

## 11. 可观测性

```text
sync_job:  queued ──► running ──┬──► success          （全部平台成功）
                               ├──► partial          （部分平台失败，partial_reason 非空）
                               ├──► failed           （0 成功，error_code 非空）
                               └──► canceled         （用户取消/应用退出清理）
```

| 观测项 | 字段 / 日志 | 阈值与告警 |
| --- | --- | --- |
| 单次耗时 | `sync_job.duration_ms` | > 8s 记 warn（`hilog` 域 `0x0C02`，Tag `Sync`） |
| 拉取量 | `fetched` / `inserted` / `updated` / `skipped` | `skipped/fetched > 90%` 说明重复拉取，检查游标 |
| 失败率 | 近 24h `failed` 占比 | > 20% 触发埋点告警（第 6 号文档埋点 `cs_sync_result`） |
| 同步方式可见性 | `platform_account.sync_mode` + `last_sync_at` 随每次同步写入 | 模式 C 平台若 `last_sync_at` 被自动刷新即视为埋点异常（数据被误认为自动） |
| 时钟偏差 | `clock_skew_ms` | `abs(clock_skew_ms) > 5min` 记 error 并回看 48h |
| 日志规范 | `hilog.info(0x0C02, 'Sync', 'job=%{public}d platform=%{public}s fetched=%{public}d', ...)`；凭据永不进日志 | 统一域见《非功能设计与质量保障》 |
