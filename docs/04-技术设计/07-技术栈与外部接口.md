# 技术栈与外部接口

## 1. 目的与范围

本文回答两个落地问题：**用什么技术实现**、**调哪些外部接口**，并给出每个接口的**可行性证据与验证状态**。

- 与 [平台同步与难度归一化](04-平台同步与难度归一化.md) 的分工：04-04 定义同步架构、算法与状态机；本文定义**技术选型清单**与**接口契约**（端点、参数、字段映射、限流、错误）。
- 证据分级：
  - ✅ **已验证**：官方文档或官方仓库明确记载（本文写作时实际抓取核对）；
  - ⚠️ **待验证**：社区实现或二手资料，需在 M1 的 Spike 中用真机/真实请求确认；
  - ❌ **不可用**：无公开接口，只能人工维护或放弃。
- 所有接口调用受 [01-04 平台代码表](../01-产品设计/04-术语表与数据字典.md) 与合规条款约束：**只读用户本人数据，不写入、不代理登录、不高频抓取**。

## 4. 第三方依赖策略

原则：**默认零第三方依赖**，能用系统 Kit 就不引库；引入必须过准入。

| 候选 | 用途 | 决策 | 理由 |
| --- | --- | --- | --- |
| `@ohos/lottie`（[lottie-ohos](https://github.com/openharmony-tpc/lottie-ohos)） | C-16 庆祝动效 | **不引入** | 单次弹窗用属性动画即可，节省 ~300KB |
| `@ohos/mpchart`（[ohos-MPChart](https://github.com/openharmony-tpc/ohos-MPChart)） | 图表 | **不引入** | 热力图与进度条自绘（`Canvas`/`Grid`）更可控 |
| `@ohos/pinyin4js` | 中文题名搜索 | **可选（P1）** | 无拼音时用子串匹配；引入前评估体积 |
| `@ohos/axios` | 网络封装 | **不引入** | `@kit.NetworkKit` 已满足；避免重复能力 |

准入清单（缺一不可）：① 明确 license 且允许商用；② 最近 12 个月有维护；③ 体积增量 ≤500KB；④ 有 ArkTS 类型声明；⑤ 不重复系统 Kit 能力。

## 6. 平台接口契约

### 6.1 Codeforces（自动）

| 方法 | 端点（GET） | 关键参数 | 返回要点 |
| --- | --- | --- | --- |
| 用户信息 | `https://codeforces.com/api/user.info` | `handles`, `checkHistoricHandles=false` | `handle`、`rating`、`maxRating`、`rank` |
| 提交记录 | `https://codeforces.com/api/user.status` | `handle`, `from`, `count`（1 起） | `id`、`contestId`、`creationTimeSeconds`、`problem{index,name,rating,tags}`、`verdict` |
| 评分历史 | `https://codeforces.com/api/user.rating` | `handle` | `contestId`、`newRating`、`ratingUpdateTimeSeconds` |
| 赛事列表 | `https://codeforces.com/api/contest.list` | `gym=false` | `id`、`name`、`startTimeSeconds`、`durationSeconds`、`phase` |
| 题目库 | `https://codeforces.com/api/problemset.problems` | 可空 | `problems[]{contestId,index,name,rating,tags}` |

```text
GET https://codeforces.com/api/user.status?handle=tourist&from=1&count=100
→ { "status": "OK", "result": [ { "id": 268...,"verdict":"OK",
      "creationTimeSeconds": 1730000000,
      "problem": { "contestId": 1899, "index": "A", "rating": 900, "tags": ["math"] } } ] }
```

**增量策略**：按 `from=1` 起翻页，直到遇到本地已存的 `submissionId` 或超过 `count` 上限；首次同步只取最近 200 条，历史由 AtCoder/洛谷/LC 各自补齐（避免一次性拉全量）。

**错误与降级**：`status=FAILED` 时读 `comment`（`Call limit exceeded` / `handle not found`）；触发限流则退避 1/5/15 分钟，超过 3 次标记该平台"暂不可用"，其他平台不受影响。

**合规**：只读公开数据，匿名访问；**不申请 API key**（无需签名，避免保存 secret）。

### 6.2 AtCoder（自动，第三方）

| 用途 | 端点 | 说明 |
| --- | --- | --- |
| 用户提交 | `https://kenkoooo.com/atcoder/atcoder-api/v3/user/submissions?user={id}&from_second={ts}` | 返回该时间点后最多 **500** 条 |
| 题目难度 | `https://kenkoooo.com/atcoder/resources/problem-models.json` | 估算难度（可能为 `null`，需兜底 3.0） |
| 题目信息 | `https://kenkoooo.com/atcoder/resources/problems.json` | `id`、`contest_id`、`title` |
| 赛事信息 | `https://kenkoooo.com/atcoder/resources/contests.json` | `id`、`start_epoch_second`、`duration_second` |

```text
GET https://kenkoooo.com/atcoder/atcoder-api/v3/user/submissions?user=chokudai&from_second=1560046356
→ [ { "id": 1234567, "epoch_second": 1560046860, "problem_id": "abc001_a",
      "contest_id": "abc001", "result": "AC", "language": "C++ (GCC 9.2.1)" } ]
```

**增量策略**：本地保存 `lastEpochSecond`，每次从该点拉取；不足 500 条说明已追平，更新水位为最后一条的 `epoch_second`。

**风险与降级**：第三方无 SLA。连续 2 次失败即进入"仅手动"；`problem-models.json` 不可用时难度兜底 3.0（并在 UI 标注"难度估算"）。

**合规**：严格遵守"访问间隔 ≥1 秒"，单用户每日请求 ≤50 次。

### 6.3 洛谷（授权，非官方契约）

| 用途 | 端点 | 关键点 |
| --- | --- | --- |
| 提交记录 | `GET https://www.luogu.com.cn/record/list?user={uid}&page={n}` | 需 `x-luogu-type: content-only` 与 `x-lentille-request: content-only` 头，返回 JSON 而非 HTML |
| 用户主页 | `GET https://www.luogu.com.cn/user/{uid}` | Lentille 结构，取 `currentData.data.user` |
| 比赛列表 | `GET https://www.luogu.com.cn/contest/list` | 需同款请求头 |

```text
GET https://www.luogu.com.cn/record/list?user=123456&page=1
Headers:
  Accept: application/json; charset=UTF-8
  x-luogu-type: content-only
  x-lentille-request: content-only
  Cookie: __client_id=...; _uid=...
→ { "currentData": { "records": { "result": [ { "id": 1, "status": 12, "score": 100,
      "problem": { "pid": "P3372", "title": "【模板】线段树 1" } } ] } } }
```

**风控处理**（来自社区实现的成熟经验）：

1. **C3VK 挑战**：响应体出现 `C3VK=...` 或返回 302 携带 `Set-Cookie` 时，合并 Cookie 后重试一次；
2. **401**：登录失效 → 清除凭据、引导重新授权；
3. **403**：判定为风控拦截 → **停止重试**，降级手动，提示"平台限制访问"；
4. **429**：退避并降低频率；连续 2 次转手动。

**合规红线**：不绕过验证码/滑块；不复用他人 Cookie；仅读取本人公开记录；遇到 403 立即停止并非绕过。

**状态**：⚠️ 待 Spike 验证（S-02）：真实请求头、`status` 字段的 AC 取值、分页上限。文档中的 `status: 12` 为社区常见取值，**必须在 S-02 中核实**。

### 6.4 LeetCode 中国站（授权，GraphQL）

| 项 | 值 |
| --- | --- |
| 端点 | `POST https://leetcode.cn/graphql/` |
| 必需头 | `Content-Type: application/json`、`Referer: https://leetcode.cn/`、`x-csrftoken`、`Cookie`（`csrftoken` + `LEETCODE_SESSION`） |
| 取用户统计 | `matchedUser(username){ submitStatsGlobal { acSubmissionNum { difficulty count } } }` |
| 取最近 AC | `recentAcSubmissionList(username, limit){ id title titleSlug timestamp }` |
| 取题目信息 | `question(titleSlug){ questionFrontendId title difficulty topicTags { name } }` |

```json
{
  "query": "query recentAcSubmissions($username: String!, $limit: Int!) { recentAcSubmissionList(username: $username, limit: $limit) { id title titleSlug timestamp } }",
  "variables": { "username": "demo_user", "limit": 20 }
}
```

**关键约束**：`recentAcSubmissionList` 只返回 **AC 记录**，且社区实现普遍观察到单次上限约 **20 条**（准确上限以 Spike S-03 实测为准）。因此 v1.0 的 LC 同步策略是：

1. 首次绑定用一次 `submitStatsGlobal` 取各难度 AC 总数作为基线；
2. 之后每次同步只拉最近 20 条 AC，按 `id` 去重入库（高频轮询即可追平）；
3. **不追求历史全量**（产品侧只需"今日/近期是否 AC"与题目元数据）。

**错误与降级**：401/403 → 清除凭据、引导重新登录；429 → 退避；GraphQL `errors` 字段存在时按失败处理，不写入脏数据。

**状态**：✅ 查询语句与端点已被公开仓库验证；⚠️ Cookie 获取方式与 `x-csrftoken` 的产生需在 S-03 真机验证。

### 6.5 赛事数据（ICPC / CCPC）

- **无公开 API**，且抓取赛事官网收益低、风险高。
- 方案：`entry/src/main/resources/rawfile/contests_seed.json` 人工维护（字段与 `contest` 表一致），每季度更新一次；应用内标注"数据更新于 YYYY-MM-DD"。
- CF/AtCoder/洛谷的赛程分别由各自接口提供，与种子文件合并后按开始时间排序（见 [比赛日历页](../03-页面设计/04-比赛日历页.md) §6.2 的 10 场闭合口径）。

## 7. 鉴权与凭据管理

### 7.1 授权同步流程（LC / 洛谷）

```text
用户点"绑定" → 打开内置 Web 页（对应平台登录页）
        │
        ├─ 用户在 WebView 内完成登录（含验证码，全部由用户操作）
        │
        ▼
WebCookieManager.fetchCookieSync(平台域名) → 仅取本域 Cookie
        │
        ▼
asset.add({ alias: "cs_lc_cookie", secret: <加密串>, accessibility: DEVICE_UNLOCKED })
        │
        ▼
同步任务读取 Cookie → 发起只读请求 → 只解析本人数据
```

### 7.2 凭据规则

| 规则 | 要求 |
| --- | --- |
| 存储位置 | **仅** Asset Store Kit（别名 `cs_<platform>_cookie`）；禁止进 RDB、Preferences、日志、导出文件 |
| 生命周期 | 绑定即存；401/403 即清；解绑即删；应用卸载随之清除 |
| 传输 | 仅 HTTPS；不经过任何自建中转 |
| 可见性 | UI 只展示"已授权/未授权 + 上次同步时间"，**不回显 Cookie 内容** |
| 审计 | 每次使用写 `hilog` 元数据（平台、时间、结果码），**不写凭据本身** |

## 8. 系统能力接口

| 能力 | 方案 | 关键点 |
| --- | --- | --- |
| 21:30 每日提醒 | `reminderAgentManager.publishReminder(ReminderRequestAlarm)`，`daysOfWeek` 全选 | 权限 `ohos.permission.PUBLISH_AGENT_REMINDER` + 通知授权；用户关闭即 `cancelReminder` |
| 赛前 15 分钟提醒 | `ReminderRequestCalendar`（一次性，`dateTime` = 开赛时间 −15min） | 赛事变更需重建；`.ics` 导出为并行能力 |
| 打卡成功反馈 | 页面内 C-16 + Toast | 不依赖系统通知 |
| 深链 | `codestreak://today`、`codestreak://contest/detail?id=123` | `Want.uri` 解析失败落 P-01 并提示（FR-37） |
| 日历导出 | 生成 RFC 5545 `.ics` → 沙箱文件 → 系统分享 | 不申请日历写权限，避免越权 |
| 数据导出 | 仅 `.ics` 在 v1.0；JSON/Markdown 为 v1.1 占位 | 见 05-03 §4.3 |

## 10. 风险与合规

| 编号 | 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- | --- |
| E-01 | 洛谷风控升级（C3VK/403） | 高 | 洛谷仅手动 | 严格限频、遇 403 即停、默认手动可用；不引入代理/Tor 等绕过手段 |
| E-02 | LC 接口变更或收紧 | 中 | LC 仅手动 | 契约测试每日跑；查询语句集中到一个文件便于快速修 |
| E-03 | kenkoooo 停止服务 | 低 | AtCoder 降级手动 | 数据可回退；不把第三方作为唯一数据源 |
| E-04 | Cookie 泄露 | 低 | 账号安全 | Asset 加密 + 日志脱敏 + 导出排除 |
| E-05 | ToS 争议 | 中 | 上架/合规风险 | 只读本人数据、不绕过验证、隐私政策明示；必要时一键切"仅手动" |
| E-06 | 限流导致同步慢 | 中 | 体验下降 | 每平台独立令牌桶（CF 0.5 req/s、LG 0.66 req/s、AC 1 req/s），串行化 |

**合规三条底线**（写入隐私政策与上架说明）：

1. 只读取用户**本人**的公开提交记录，不访问他人数据；
2. 不破解、不绕过任何验证码/风控，遇阻即降级为手动；
3. 凭据仅存本机加密区，可随时解绑清除，不上传任何服务器。

## 11. 接口验收清单

- [ ] 四个平台的适配器均实现 `OjAdapter` 契约，错误码映射到 `ER-1xxx`。
- [ ] CF 请求频率 ≤0.5 次/秒，超限能识别 `Call limit exceeded` 并退避。
- [ ] AtCoder 增量水位正确，单次拉取 ≤500 条，间隔 ≥1 秒。
- [ ] 洛谷请求带 `x-luogu-type`/`x-lentille-request`，C3VK 与 302 能正确处理，403 立即停。
- [ ] LC 在 401/403 时清除凭据并引导重新授权，不重试死循环。
- [ ] Cookie 仅存 Asset Store，RDB/日志/导出文件中无明文（安全扫描通过）。
- [ ] 任一平台失败不影响其他平台；UI 显示"同步方式 + 上次同步时间"。
- [ ] 21:30 与赛前 15 分钟提醒在真机锁屏下可送达，点击可深链到对应页面。
- [ ] `.ics` 文件可被系统日历成功导入。
- [ ] 断网时所有页面可用缓存数据，写入操作进入待同步队列。
