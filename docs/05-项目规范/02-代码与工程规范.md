# 代码与工程规范

## 1. 目的与适用范围

本文档规定 CodeStreak HarmonyOS 客户端的**语言基线、命名、分层、ArkUI 写法、性能与安全红线、注释、错误处理、Git、测试与依赖**约束，使评审有客观判据、CI 有可执行检查项。

- 适用范围：`entry/src/main/ets/` 全部 ArkTS 代码、`resources/` 资源、构建配置与提交信息。
- 与 [工程结构与模块划分](../04-技术设计/02-工程结构与模块划分.md) 的目录定义冲突时以 04-02 为准；视觉取值见 [设计令牌规范](../02-设计规范/02-设计令牌规范.md)，组件编号见 [组件规范](../02-设计规范/05-组件规范.md)。

## 2. 工程与语言基线

| 项 | 当前值 | 约束 |
| --- | --- | --- |
| 产物形态 | 单 `entry` HAP | 新增 HAP/HAR/HSP 必须先修订 04-02，禁止私建 |
| bundleName | `com.example.project` | **必须**改为 `com.codestreak.app`；破坏性变更，须在里程碑 M3 前一次性完成（升级安装需卸载） |
| `compatibleSdkVersion` / `targetSdkVersion` | `6.1.1(24)` / `26.0.0` | compatible 不得上调，下调须验证 API 最低版本；target 随 IDE 升级，升级后回归 P-01~P-04 |
| 严格模式与静态检查 | `strictMode.caseSensitiveCheck`、`useNormalizedOHMUrl` 均为 `true`；`code-linter.json5` 启用 `@performance/recommended`、`@typescript-eslint/recommended` + 12 条 `@security` 规则 | 严格模式不得关闭；规则不得降级为 warn，不得 `eslint-disable` |
| 测试依赖 | `@ohos/hypium@1.0.25`、`@ohos/hamock@1.0.0` | 版本在 `oh-package.json5` 精确锁定，不写 `^`/`~` |
| 语言边界 | ArkTS（`.ets`）承载 UI 与业务 | 禁止 `.ets` 中使用 ArkTS 不支持的 TS 语法；`.ts` 仅供纯逻辑与测试 |

**类型与动态特性禁令**（违反即阻断合并）：

| 编号 | 规则 | 反例 | 正例 |
| --- | --- | --- | --- |
| T-01 | 禁止 `any`；边界数据先 `unknown` 再收窄，禁止跳过校验的断言 | `function parse(x: any)`、`raw as Problem` | `function parse(raw: unknown): Problem` + `isProblem()` 守卫 |
| T-02 | 禁止动态类型技巧（`eval`、`new Function`、`Reflect.apply`、改写原型） | `Reflect.apply(fn, null, args)` | 显式调用 `fn(...args)` |
| T-03 | 禁止扩展内建原型 | `Date.prototype.fmt = ...` | `utils/date.ets` 导出 `formatDate()` |
| T-04 | 禁止 `@ts-ignore` / `@ts-nocheck` | `// @ts-ignore` | 修正类型；确需忽略须附 `TODO(owner, date)` 与理由 |

## 3. 命名规范

| 对象 | 规则 | 正例 | 反例 |
| --- | --- | --- | --- |
| 页面/视图/组件/类文件 | PascalCase，文件名 = 导出 struct/class 名 | `views/TodayPage.ets`、`components/data/DifficultyBadge.ets` | `today-page.ets`、`todayPage.ets` |
| 配置/脚本/资源文件 | kebab-case | `obfuscation-rules.txt`、`official-problem-sets.json` | `ObfuscationRules.txt` |
| 变量/方法 | camelCase，方法动词开头；布尔 `is/has/can/should`；回调 `onXxx` | `fetchDailyProgress()`、`isAchieved`、`onFilterChange` | `Sync()`、`checked`、`handleClick2` |
| 常量 | UPPER_SNAKE，按域收进类 | `CsColor.PRIMARY_CONTAINER`、`RouteName.PROBLEM_DETAIL` | `maxTarget`、散落的 `TIMEOUT` |
| 类型/接口 | PascalCase，不加 `I` 前缀，用后缀表达角色 | `ProblemRow`、`OjPort`、`ProblemDetailParam` | `IProblem`、`problem_type` |
| 枚举 | 类型 PascalCase，成员 UPPER_SNAKE，值为字符串 | `Platform.CODEFORCES = 'CODEFORCES'` | `enum platform { leetcode }` |
| 颜色与尺寸资源 | `cs_color_*`、`cs_space_*`、`cs_radius_*`、`cs_font_*` | `cs_color_surface_high` | `bg_color_2`、`surfaceHigh` |
| 路由名 | kebab-case 名词短语，集中在 `constants/Routes.ets` | `problem-set-detail`、`contest-detail` | 页面内内联 `'pages/today/TodayPage'` |
| 数据库 | 表/列 snake_case 单数；索引 `idx_<表>_<列>`；唯一键 `uk_<表>_<列>` | `check_in`、`idx_submission_problem` | `checkIns`、`idx1` |

禁止中文文件名与含空格路径；import 顺序为 `@kit.*` → 本项目绝对语义目录 → 同目录相对路径，组间空行。

## 4. 目录与分层约束

```text
entry/src/main/ets/
├── entryability/ · entrybackupability/  生命周期、窗口、备份扩展，禁止业务
├── pages/Index.ets                     唯一 @Entry：Tabs + 4 个 Navigation
├── views/                              P-01…P-12（TodayPage … DataExportPage）
├── components/{common,surface,data,input,business}
├── viewmodels/                         一页一 VM（TodayViewModel …）
├── domain/{port,checkin,normalize,contest,ranking}   纯规则与 Port，无 I/O
├── services/{sync,checkin,streak,contest,problem,leaderboard,notification,account,badge,export}
├── data/{db,repository,remote,mapper}  db 含 dao；remote 含 http/scrape/adapters/dto
├── model/{entity,state,dto,enum}
├── constants/{DesignTokens,Routes,AppConfig,DbConfig,SyncConfig,ErrorCode}
├── utils/{Logger,DateUtil,CryptoUtil,NetworkUtil,JsonUtil,Result}
├── app/{AppContainer,AppLifecycle,EventBus,router,store}
└── workers/SyncParserTask.ets          可选：大 HTML 解析，按 04-02 阈值启用
```

| 层 | 允许依赖 | 禁止依赖 |
| --- | --- | --- |
| `pages` | `app/router`、`views`、`constants` | 具体业务 UI、网络请求 |
| `views` | 自己的 `viewmodel`、`components`、`model`、`constants` | `services`、`data`、其他页的 VM |
| `components` | `model`、`constants`、`utils` | `services`、`data`、`viewmodels` |
| `viewmodels` | `services`、`domain`、`model`、`app/store` | `data`、`components`、弹 Toast |
| `domain` | `model`、`constants`（注入 `Clock`） | I/O、`@kit.*`、单例、UI 类型 |
| `services` | `domain`、`data`、`model`、`constants`、`utils` | 全部 UI 层、返回 `Resource` |
| `data` | `model`、`constants`、`utils` | `services`、`viewmodels`、UI |
| `app` | 全部（唯一装配处） | 业务规则、页面构建 |
| `model`/`constants`/`utils` | `@kit.*` 与彼此（`utils` → `constants`） | 上层任何模块 |

1. **禁止反向依赖、循环依赖与跨层访问**：UI 不访问 `data`，链路固定 `view → viewmodel → service → domain/data`；出现 A ⇄ B 时把共享契约抽到 `model`/`domain/port`；禁止跨层 barrel（`index.ets` 批量 re-export）。
2. 文件行数上限：组件与视图 ≤ 300 行，`viewmodels`/`services` ≤ 400 行；`app/` 是唯一 `new Service` 与 `connect Store` 的位置。

## 5. ArkUI 编码规范

| 编号 | 规则 | 说明与正例 |
| --- | --- | --- |
| A-01 | 单 `@Component` ≤ 300 行，`build()` ≤ 80 行 | 超出按"一屏一卡"拆子组件，局部片段用 `@Builder` |
| A-02 | `build()` 内禁止副作用 | 禁止赋值成员、发请求、写 Preferences、`console.*`、改全局状态 |
| A-03 | `build()` 内禁止复杂计算与 `new` | 循环、排序、`filter/map` 链、日期格式化提前到 `viewmodel` |
| A-04 | `ForEach` / `LazyForEach` 必须带稳定 key | `ForEach(list, (item: Problem) => {...}, (item: Problem) => item.id)` |
| A-05 | 长列表（> 30 项）必须 `LazyForEach` + `IDataSource` | 题单矩阵、榜单、比赛日历一律懒加载 |
| A-06 | 重复结构出现 3 次即抽 `@Builder` 或子组件 | 卡片行、统计行、平台徽标 |
| A-07 | `aboutToAppear` 禁止阻塞操作 | 不同步读库/请求；`void vm.load()`，加载态由状态驱动 |
| A-08 | `aboutToDisappear` 必须释放资源 | 清定时器、注销监听、断开轮询、`off` 事件订阅 |
| A-09 | 单向数据流，变更经回调上抛 | 禁止子组件直接改父对象；输入用 `@Prop`/`@Link` 显式声明 |

**状态装饰器使用规则**：

| 装饰器 | 允许用于 | 禁止用于 |
| --- | --- | --- |
| `@State` | 组件私有、驱动本组件刷新 | 跨页共享数据 |
| `@Prop` / `@Link` | 父→子单向拷贝 / 父子双向同步 | 大对象（> 1KB）拷贝、跨层级传值 |
| `@Provide` / `@Consume` | 主题、当前用户等全局只读上下文 | 高频变更的列表数据 |
| `@Observed` / `@ObjectLink` | 对象数组元素局部刷新 | 替代全局状态管理 |
| `AppStorage` / `LocalStorage` | 会话级轻量状态（当前 Tab、筛选条件） | 持久化数据（走 Preferences/RDB） |

## 6. 性能红线

| 编号 | 红线 | 阈值/做法 | 检查方式 |
| --- | --- | --- | --- |
| P-01 | 启动与首屏 | 到 P-01 首帧 ≤ 800ms（中端机 3 次取中位数），启动窗口背景 `#10141A`；首屏数据有缓存 ≤ 300ms、4G 无缓存 ≤ 1.2s | 真机打点 + 弱网模拟 |
| P-02 | 列表 | `LazyForEach` + 稳定 key，局部 `notifyDataChange`，滚动 ≥ 55fps；单次查询 ≤ 50 条、触底分页 | Profiler 采样 |
| P-03 | 图片 | `Image` 显式 `width/height` + `objectFit`；静态图片资源总量 ≤ 2MB | 构建产物 + 解码内存 |
| P-04 | 状态刷新 | 同一帧合并写入；搜索输入防抖 300ms | 无连续丢帧 |
| P-05 | 包体·日志·定时器 | release HAP ≤ 20MB、安装总包 ≤ 30MB；`debug`/`info` 仅 debug 构建；页面不可见即停，单页定时器 ≤ 2 个 | 产物扫描 + `aboutToDisappear` 核查 |

## 7. 安全编码

| 编号 | 规则 | 反例 | 正例 |
| --- | --- | --- | --- |
| S-01 | 禁止明文存 token/密码 | `Preferences.put('token', raw)` | `huks` 加密后存密文，密钥不出 TEE |
| S-02 | 平台 Cookie 必须加密存储 | 明文 JSON 落盘 | `huks` 加密 + 会话结束校验完整性 |
| S-03 | Web 组件必须域名白名单 | `Web({ src: userInput })` | 白名单：`leetcode.cn`、`codeforces.com`、`luogu.com.cn`、`atcoder.jp` |
| S-04 | 日志脱敏 | 打印完整 Cookie/handle | 只打印 `platform`、`status`、耗时；账号掩码 `ab***` |
| S-05 | 禁止关闭安全 lint | `// eslint-disable @security/...` | 保留规则并修复调用（SHA-256 起步，禁 MD5/DES/3DES） |
| S-06 | 网络与权限最小化 | `http://` 接口、声明未使用的权限 | 全站 HTTPS、证书校验不跳过；`module.json5` 只保留实际使用项 |

## 8. 注释与错误处理

**注释**：

```ts
/** 平台同步服务：拉取各平台当日提交并按难度归一化合并。见 04-04。 */
```

文件头块注释写"职责一句话 + 所属层 + 对应文档编号"，不写作者与日期；`export` 的函数/类/接口必须有 TSDoc（`@param`、`@returns`、`@throws`），私有方法只注释"为什么"；`TODO(owner, 2026-11-15): 补齐 AtCoder 分页同步` 三要素齐全，无责任人/到期日的 TODO 视为缺陷。

**错误处理**：

```ts
/** 统一错误：code 供日志与埋点，userMessage 供 UI 直接展示 */
export class AppError extends Error {
  constructor(readonly code: string, readonly userMessage: string,
              readonly detail?: string, readonly cause?: Error) {
    super(code);
    this.name = 'AppError';
  }
}
```

| 段位 | 域 | 示例 |
| --- | --- | --- |
| `ER-1xxx` | 网络与平台同步 | `ER-1201` SyncTimeout、`ER-1202` PlatformUnauthorized |
| `ER-2xxx` | 数据与存储 | `ER-2101` RdbOpenFailed、`ER-2102` MigrationFailed |
| `ER-3xxx` | 解析与难度归一化 | `ER-3101` UnknownDifficulty、`ER-3102` SchemaMismatch |
| `ER-4xxx` | 鉴权与 Cookie | `ER-4101` CookieExpired、`ER-4102` WebLoginRequired |
| `ER-5xxx` / `ER-9xxx` | UI 与路由 / 未归类 | `ER-5101` RouteNotFound、`ER-9001` Unknown |

1. **禁止空 catch**：要么转 `AppError` 上抛，要么降级并记录；用户可读文案与日志细节严格分离，文案不含堆栈与英文原文。
2. 同一错误码文案唯一，随码定义在 `constants/ErrorCode.ets`；可恢复错误（超时）须给重试入口，不可恢复错误（数据损坏）引导重进。

## 9. Git 规范

| 分支 | 用途 | 命名 | 生命周期 |
| --- | --- | --- | --- |
| `main` | 可发布分支 | `main` | 常驻，只接受 release 合并 |
| `develop` | 集成分支 | `develop` | 常驻，日常合入目标 |
| `feature/*` | 新功能 | `feature/today-checkin` | 合并后删除 |
| `fix/*` | 缺陷修复 | `fix/streak-reset` | 合并后删除 |
| `docs/*` | 文档变更 | `docs/05-specs` | 合并后删除 |

提交信息遵循 Conventional Commits：`<type>(<scope>): <subject>`，subject 用中文、≤ 50 字、不以句号结尾。

| type | 含义 | 示例 |
| --- | --- | --- |
| `feat` | 新功能 | `feat(today): 打卡成功后播放庆祝弹层` |
| `fix` | 缺陷修复 | `fix(sync): 修复 Codeforces 分页丢题` |
| `docs` | 文档 | `docs(05): 补充错误码段位表` |
| `refactor` | 重构（不改行为） | `refactor(data): 抽出 RDB 迁移器` |
| `perf` | 性能优化 | `perf(matrix): 题单矩阵改为 LazyForEach` |
| `test` | 测试 | `test(service): 补难度归一化边界用例` |

`style`、`build`、`chore`、`revert` 分别用于格式、构建、杂务与回滚。PR 要求：标题同提交规范；描述含"变更点 / 影响范围 / 验证方式 / 关联 FR 或 P 编号"；合并用 **squash merge**（`develop` 单需求单提交）；**至少 1 名非作者 review 通过**；CI 全绿（`hvigorw clean assembleHap`、`code-linter` 零 error、单测通过、文档链接校验、提交信息检查）。

> 本节为摘要。**分支保护、标签与发布、禁止入库清单、回滚策略与「文档同步 DoD」的完整规定见 [Git版本管理规范](05-Git版本管理规范.md)**；两者冲突时以该文为准。

## 10. 测试与依赖管理

**测试规范**：

| 项 | 要求 |
| --- | --- |
| 位置·命名·框架 | 本地单测 `entry/src/test/*_test.ets`；设备测试 `entry/src/ohosTest/ets/test/*_test.ets`；`@ohos/hypium`（`describe`/`it`/`expect`），mock 用 `@ohos/hamock` |
| 覆盖要求 | `services`、`utils`、难度归一化、达标与连续天数判定：行覆盖 ≥ 70%，关键分支 100%；用例命名 `it('should_<期望>_when_<条件>')` |
| mock 边界 | 只 mock 平台 HTTP、RDB、系统能力；业务逻辑与纯函数禁止 mock |
| UI 测试 | 四页主流程（打卡、筛选、比赛列表、榜单刷新）+ 弹层开合各 1 条 |
| 门槛 | 新增 `service` 无单测不予合并；缺陷修复先补失败用例；依赖真实网络的用例禁止入库 |

**依赖管理**：

1. 新增 ohpm 依赖须在 PR 说明用途、体积、维护活跃度、是否 `@ohos` 官方，由模块负责人批准。
2. 版本必须精确锁定（`1.0.25`），禁止 `^`、`~`、`latest`；`oh-package-lock.json5` 必须提交。
3. 禁止引入与已有能力重复的库（网络、日期、状态管理、图表各只保留一套）；禁止来源不明或无 HarmonyOS 适配的 HAR；基线 `devDependencies` 仅 `@ohos/hypium`、`@ohos/hamock`，`dependencies` 在 v1.0 保持为空。

## 12. 提交前自检

1. `hvigorw clean assembleHap` 通过，无新增 warning；`code-linter` 零 error、`@security` 未被 disable；单测与设备测试全绿。
2. P-01~P-04 主流程真机走查，无白屏、无崩溃、无阻塞；冷启动无白闪；无 `console.log`、无调试开关、无硬编码密钥。
3. 变更文件与 PR 描述一致，无 `.idea/`、`build/`、`local.properties` 误提交。
4. 关联文档与变更记录已更新。
