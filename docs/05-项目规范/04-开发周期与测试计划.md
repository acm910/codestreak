# 开发周期与测试计划

## 1. 目的与范围

本文把 [版本规划与交付清单](03-版本规划与交付清单.md) 的里程碑 M0–M3 展开为**可直接排期的 12 周计划**，并给出贯穿全程的**测试过程设计**（测试分层、用例、环境、自动化、门禁、缺陷管理）。

- 覆盖：软件开发（架构、数据、四页 UI、同步适配器、通知）与测试（单测、契约、集成、UI、性能、安全、兼容、验收）。
- 不覆盖：商务与运营排期；上架审核的外部等待时间只作为风险预留。
- 阅读对象：项目负责人、客户端开发、测试、产品/设计（用于对齐评审节奏）。
- **测试细节的权威文档**：[测试方案总纲](../07-测试与质量/01-测试方案总纲.md)（策略与环境）、[测试用例集](../07-测试与质量/02-测试用例集.md)（111 条基线）、[通过条件与缺陷管理](../07-测试与质量/03-通过条件与缺陷管理.md)（门禁判据）。本文只保留与排期相关的摘要。

### 5.3 用例设计方法

1. **功能用例**：以 `03-页面设计` 每页的"状态矩阵"为骨架，一态一条；文案断言直接引用页面文档的文案表。
2. **边界用例**：时间（23:59:59 打卡、跨 00:00、时区切换）、计数（0/1/2 题、>2 题）、难度（1.0/2.5/5.0、override）。
3. **异常用例**：按 04-04 的错误码表逐条构造（401/403/429/超时/半包/字段缺失）。
4. **组合用例**：筛选（赛道 × 难度 × 平台 × 关键字）用正交表裁剪，保留 8 组高价值组合。
5. **回归集**：每次提测固定回归 **全部 P0 用例（39 条，见 [测试用例集](../07-测试与质量/02-测试用例集.md)）**，下表 ★ 为其中的高频抽样。

### 5.5 自动化与 CI

```text
提交 ──▶ lint(code-linter) ──▶ 单测(hypium) ──▶ 构建 ──▶ 冒烟(UiTest, 10 条) ──▶ 产出 debug HAP
                                          │
每日 10:00 定时 ──▶ 契约测试(fixture 回放) ──▶ 全量单测 ──▶ 报告归档
```

- **准入**：单测覆盖率（domain 层）≥80%，同步/归一化/连击模块 ≥90%。
- **稳定性**：UiTest 用例连续 3 次全绿才计入通过；flaky 用例 48h 内修复或下线。
- **可视化回归**：四页固定视口截图与基线比对（差异 >2% 报警），随 UI 变更更新基线。

### 5.6 缺陷管理

| 等级 | 定义 | 响应/修复时限 | 发布要求 |
| --- | --- | --- | --- |
| P0 阻断 | 崩溃、数据丢失、主流程不可用、隐私泄露 | 4h 响应 / 24h 修复 | 必须清零 |
| P1 严重 | 核心功能错误、口径错误、明显文案错误 | 当迭代修复 | 必须清零 |
| P2 一般 | 非核心功能异常、体验问题 | 下迭代 | ≤10 个且无累积 |
| P3 轻微 | 视觉细节、极端场景 | 排期 | 可遗留 |

缺陷流转：新建 → 确认（测试）→ 修复（开发）→ 验证（测试）→ 关闭；**回归必须由提交者以外的人执行**。

### 5.8 专项测试要点

| 专项 | 方法 | 判据 |

| 性能 | DevEco Profiler + 自建打点；三场景（启动/滚动/同步）各 5 次 | 冷启动 ≤800ms、首屏 ≤1.2s、帧率 ≥55fps、内存 ≤180MB、HAP ≤20MB |

| 安全 | 存储扫描（RDB/文件/日志）、Web 域名白名单、权限清单审计 | Cookie 不落明文、无越权权限、日志无敏感字段 |
| 兼容 | 4 设备 × 2 分辨率 × 折叠屏展开/折叠 | 布局不破、安全区正确、无裁切 |
| 无障碍 | 字号放大 1.3×、读屏走查四页 | 关键操作可被朗读、对比度达标 |
| 国际化 | 仅中文，但时区/日期格式按 Asia/Shanghai 固定 | 跨时区改日不漂移 |
