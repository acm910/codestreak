# 文档编写与命名规范

## 1. 目的与适用范围

本文档规定 CodeStreak 项目文档的**目录归属、文件命名、doc-id、头部字段、正文骨架、编号引用、评审发布**规则，使任一文档可被唯一标识、可被 CI 校验、可由任意成员在 30 分钟内补齐。

- 适用范围：`docs/` 下全部 Markdown 文档，以及需求单、评审记录、上架物料说明。
- 不适用范围：`docs/产品原型/` 下的原始 HTML 与截图（只读，见 3.4）；冲突时以 [原型差异与设计裁决](../06-附录/01-原型差异与设计裁决.md) 为最高优先级。

## 2. 文档分类与目录职责

| 分类号 | 目录 | 职责 | 主要读者 | 允许新增文件的条件 |
| --- | --- | --- | --- | --- |
| 01 | `01-产品设计/` | 定位、需求、信息架构、术语与数据字典 | 产品、设计、开发 | 出现新需求域（如"会员与订阅"） |
| 02 | `02-设计规范/` | 设计原则、令牌、字体、栅格、组件、动效 | 设计、前端 | 出现新视觉子系统（如"图标规范"） |
| 03 | `03-页面设计/` | 逐页原型映射、页面状态、弹层与全局态 | 设计、开发、测试 | 新增一级页面或全局状态层 |
| 04 | `04-技术设计/` | 架构、工程结构、数据模型、同步、状态路由、非功能 | 开发、测试 | 出现新技术横切面（如"离线缓存"） |
| 05 | `05-项目规范/` | 文档、代码、版本与交付三类约束 | 全员 | 出现新约束域，且需本文件同步修订 |
| 06 | `06-附录/` | 差异裁决、决策记录、外部资料索引 | 全员 | 一次性裁决或外部引用归档 |
| 07 | `07-测试与质量/` | 测试方案、用例集、通过条件、缺陷与报告模板 | 测试、开发、产品 | 新增测试域（如"自动化框架"）或质量门禁变更 |

1. **先归类，再起名**：10 秒内无法判断归属，说明分类边界不清，先修订上表再新建文件。
2. 新增文件必须同时更新 [文档中心](../README.md) 索引，否则链接校验不通过；同一分类下文件数 ≤ 12，超出按子域拆子目录并重新从 `01` 编号。
3. 禁止在 `docs/` 根目录新建 `.md`（`README.md` 为索引例外）；临时材料放 `docs/_draft/`（已 gitignore），不得占用正式编号。

## 3. 文件命名与 doc-id 规则

### 3.1 语法

```text
NN-中文标题.md      NN = 两位序号，同层从 01 连续递增，不跳号、不复用
                    -  = 序号与标题之间唯一允许的分隔符
                    中文标题 = 2–10 个简体汉字，不含标点、空格、英文缩写
```

### 3.2 字符集与禁用项

| 项 | 要求 | 正例 | 反例 |
| --- | --- | --- | --- |
| 序号 | 两位补零，`01`–`99` | `05-项目规范/02-代码与工程规范.md` | `5-代码规范.md`、`02_代码规范.md` |
| 分隔符 | 唯用半角 `-` | `01-产品概述与定位.md` | `01 产品概述.md`、`01、产品概述.md` |
| 语言 | 简体中文标题 | `04-平台同步与难度归一化.md` | `04-Sync.md`、`04-sync-and-diff.md` |
| 英文缩写 | 禁止混排，专有名词须评审确认 | `03-数据模型设计.md` | `03-DB模型设计.md`、`02-UI组件规范.md` |
| 标点 | 禁止 `、，。：；（）《》+&%#` | `06-非功能设计与质量保障.md` | `06-非功能设计（质量）.md` |
| 层级与长度 | 单层编号，目录承担层级；≤ 40 字符 | `03-页面设计/02-今日打卡页.md` | `03-02-今日打卡页.md` |

允许字符集：数字 `0-9`、汉字、连字符 `-`、扩展名 `.md`；空格、下划线、大写字母一律不允许。

### 3.3 doc-id 规则

| 规则 | 说明 |
| --- | --- |
| 格式 | `<分类号>-<序号>`，如 `05-01`；分类号 = 一级目录前缀，序号 = 文件名前两位，**必须一致** |
| 唯一性 | 全仓唯一、永久不复用；文件删除后 doc-id 进入作废清单，禁止重新分配 |
| 稳定性 | 改名或移动后 doc-id 不变；doc-id 变更视为破坏性变更，须全仓替换引用 |
| 引用写法 | 正文写作 `05-02`，首次出现处带相对链接指向文件 |

### 3.4 只读与例外

- `docs/产品原型/` 下文件是设计输入快照，禁止改名、移动、格式化（含 HTML 缩进与属性顺序）。
- `README.md` 作为目录索引不受 `NN-` 约束，但必须位于目录根部且只做索引；截图命名 `<页面代号>-<状态>.png`（如 `P-01-empty.png`），存该页文档同级 `assets/`。

## 4. 头部字段与正文模板

### 4.1 Front matter 字段表

| 字段 | 必填 | 取值 | 示例 |
| --- | --- | --- | --- |
| `doc-id` | 是 | `NN-NN`，与路径一致 | `05-01` |
| `title` | 是 | 与文件名去序号后**完全一致** | `文档编写与命名规范` |
| `category` | 是 | 七个一级分类名之一（`README.md` 用 `索引`） | `项目规范` |
| `status` | 是 | `草稿` / `评审中` / `待确认` / `规划中` / `生效` / `参考` / `已归档` | `生效` |
| `version` | 是 | `v<主>.<次>`；草稿从 `v0.1` 起，转生效改 `v1.0` | `v1.0` |
| `updated` | 是 | `YYYY-MM-DD`，与变更记录末行日期一致 | `2026-10-26` |
| `related` | 是 | doc-id 数组，2–8 项，不含自身 | `[04-02, 05-02]` |

### 4.2 固定骨架

| 顺序 | 二级标题 | 必填 | 内容要求 |
| --- | --- | --- | --- |
| 1 | `## 1. 目的与适用范围` | 是 | 3–6 句，写明约束谁、约束什么、不约束什么 |
| 2 | `## 2. 术语` | 视情况 | 只列新增或特指术语；通用术语引用 [术语表](../01-产品设计/04-术语表与数据字典.md) |
| 3 | `## 3..N-2. 主体` | 是 | 按"规则 → 表格 → 正反例"展开，一节只讲一件事 |
| 4 | `## N-1. 检查清单` | 规范类必填 | `- [ ]` 条目，与主体规则一一对应 |
| 5 | `## N. 变更记录` | 是 | 四列表格，见第 10 节 |


## 5. 编号与引用规范

| 对象 | 格式 | 取值范围 | 唯一性范围 | 示例 |
| --- | --- | --- | --- | --- |
| 章节 | `## N.` / `### N.M` | 文件内连续 | 文件内 | `## 4. 色彩令牌全表` |
| 图 / 表 | `图 <doc-id>-<序号>`、`表 <doc-id>-<序号>` | 文件内从 1 起 | 文件内 | `图 03-02-1 今日打卡页状态机` |
| 需求 | `FR-<两位>` / `NFR-<两位>` | 01–99 | 全仓 | `FR-02 达标判定与连胜推进`、`NFR-01 性能` |
| 页面 | `P-<两位>` | 01–12 | 全仓 | `P-01 今日打卡`、`P-12 数据导出` |
| 组件 | `C-<两位>` | 01–40 | 全仓 | `C-15 进度条` |
| 接口与错误码 | `ER-<四位>` | 1000–9999，按域分段 | 全仓 | `ER-1201 SyncTimeout` |
| 弹层 | `O-<两位>` | 01–99 | 全仓 | `O-02 创建自建题单` |
| 裁决 | `D-<两位>` | 01–35 | 06-01 内 | `D-04 难度徽标取色` |

1. 编号只增不删：删除时保留编号并标注"已废弃"，禁止重新分配；同一编号不得在不同文档表达不同含义。
2. 跨文档引用必须带文档名，写作 `FR-02（见 [需求规格说明](../01-产品设计/02-需求规格说明.md)）`，不得只写裸编号。
3. `ER-` 段位划分与 `C-` 组件清单分别由 [代码与工程规范](02-代码与工程规范.md) 第 8 节与 [组件规范](../02-设计规范/05-组件规范.md) 维护，本文只规定格式。

## 6. 表格规范

| 规则 | 要求 | 反例 |
| --- | --- | --- |
| 表头 | 必填，不得空表头或以"备注"兜底成列 | 首列为空 |
| 合并单元格 | 禁止；需分组时拆表或增加"分组"列 | `rowspan` 堆叠多个页面 |
| 单位 | 写在列名中（`时长（ms）`、`间距（vp）`），不写进单元格 | `2 题`、`800ms` |
| 数值 | 不带千分位；区间用 `–`（en dash）；空值写 `—` | `1,000`、`N/A`、`TBD` |
| 列数 | 单表 ≤ 6 列，超出拆表 | 8 列堆叠 |
| 状态 | 统一词表：`未开始` / `进行中` / `已完成` / `已阻塞` / `已取消` | `doing`、`WIP`、`50%` |
| 排序 | 有编号按编号升序；无编号按业务优先级降序 | 随意插入新行 |

## 7. 图与链接规范

### 7.1 ASCII 图

```text
┌──────────┐     ┌──────────┐     ┌────────────┐
│ pages/   │ ──► │ views/   │ ──► │ components/│
└──────────┘     └──────────┘     └────────────┘
   图 05-01-1 分层依赖方向（显示宽度 ≤ 100 字符）
```

1. 必须使用 ` ```text ` 代码块并带图题；**显示宽度 ≤ 100 字符**（汉字与全角符号按 2 字符计）。
2. 只允许 `─ │ ┌ ┐ └ ┘ ├ ┤ ┬ ┴ ┼ ► ◄ ▲ ▼` 与 ASCII 字母数字，禁止 emoji 与 `\t`。
3. 节点超过 12 个的流程改用 Mermaid 或拆图，单图只表达一个关系。

### 7.2 链接

| 规则 | 正例 | 反例 |
| --- | --- | --- |
| 只用相对路径 | `[设计令牌规范](../02-设计规范/02-设计令牌规范.md)` | `E:\code\project\docs\...`、`file:///` |
| 中文路径原样书写 | `[今日打卡页](../03-页面设计/02-今日打卡页.md)` | URL 编码后的 `%E4%BB%8A...` |
| 不链接不存在文件 | 目标已合入再引用 | 指向待创建文档的链接 |
| 锚点与格式 | `[表格规范](#6-表格规范)` | `[#section-6]`、裸 URL 作正文 |

## 8. 术语统一

1. 术语以 [术语表与数据字典](../01-产品设计/04-术语表与数据字典.md) 为唯一权威，本文不重复定义。
2. 首次出现写"中文（英文）"，其后仅用中文：`连续天数（streak）` → 后续写"连续天数"。
3. 禁用同义词：打卡≠签到/check in；补签卡≠复活卡；题单≠清单/合集；难度归一化≠难度映射（后者仅指换算过程）；新增术语先改 01-04 再使用。

## 9. 评审、发布与归档

| 状态 | 进入条件 | 责任人 | 可流转到 |
| --- | --- | --- | --- |
| 草稿 | 创建文件，front matter 完整 | 作者 | 评审中 / 规划中 |
| 评审中 | 自查清单全绿、链接可达 | 作者 | 生效 / 草稿 |
| 待确认 | 内容成型但存在未拍板 Q-xx（须在文首列编号） | 产品负责人 | 生效 / 评审中 |
| 规划中 | 属后续版本范围，本期不据此开发 | 产品负责人 | 评审中 / 已归档 |
| 生效 | ≥ 1 名非作者评审通过、CI 链接校验通过 | 模块负责人 | 已归档 / 生效（升版） |
| 参考 | 只读素材（原型、外部资料、历史快照），不接受修订 | 项目管理组 | 已归档 |
| 已归档 | 被新版本取代或阶段结束 | 项目管理组 | —（只读） |

1. 评审必检：头部七字段、编号连续、表格无合并、链接可达、术语一致、变更记录已加行；涉及需求/接口/数据模型的文档须含 1 名开发与 1 名测试。
2. 升版：`生效` 文档任何实质修改都升版本号；纯错别字可保版本并在该行注 `*`。
3. 归档：被取代的文档移入 `docs/_archive/<YYYY>/`，`status` 改 `已归档`，首行加 `> 已归档，替代文档：[链接]`；正文不再修改，doc-id 永久保留，并在 [文档中心](../README.md) 归档区登记。

## 10. 版本与变更

1. 版本语义：`v1.0` 首版 → `v1.1` 兼容增补（加章节/加行，不删不改规则）→ `v2.0` 破坏性变更（规则收紧、编号重排、字段删除）。
2. `## N. 变更记录` 固定四列（版本 / 日期 / 变更 / 作者），旧→新排列，每次只追加一行，不改写历史行。
3. 破坏性变更须在变更说明前加 `**BREAKING**`，并在正文顶部补"迁移说明"。

## 11. 文档与代码同步

| 代码侧变更 | 同一 PR 必须修改的文档 |
| --- | --- |
| 新增或修改需求 | `01-02 需求规格说明` + 受影响页的 `03-页面设计` 文档 |
| 新增设计令牌 | `02-02 设计令牌规范`（表格 + `color.json` + `DesignTokens.ets`） |
| 新增页面或路由 | `03-01 页面总览` + 该页文档 + `04-05 状态管理与路由设计` |
| 改数据表或字段 | `01-04 术语表与数据字典` + `04-03 数据模型设计` |
| 改错误码或接口契约 | `05-02 代码与工程规范` 第 8 节 |
| 调整版本范围 | `05-03 版本规划与交付清单` |

PR 检查项（缺一不合并）：文档已改 / 变更记录已加行 / `updated` 已更新 / `docs/README.md` 索引已更新 / 链接校验通过。

## 12. 检查清单

- [ ] 文件名符合 `NN-中文标题.md`，字符集、长度、分隔符合规。
- [ ] doc-id 与路径一致，全仓未重复、未复用废止编号。
- [ ] 头部七字段齐全，`status` 取自第 9 节词表，`updated` 与变更记录末行一致。
- [ ] 二级标题均为编号形式，章节号连续无跳号。
- [ ] 图/表/需求/页面/组件/接口/弹层编号符合第 5 节。
- [ ] 表格有表头、无合并单元格、单位在列名、状态用统一词表。
- [ ] ASCII 图宽 ≤ 100 字符、使用 ` ```text `、有图题。
- [ ] 所有相对链接可达，无绝对路径与 URL 编码路径。
- [ ] 术语与 [术语表](../01-产品设计/04-术语表与数据字典.md) 一致。
- [ ] [文档中心](../README.md) 已收录，变更记录已加行。
