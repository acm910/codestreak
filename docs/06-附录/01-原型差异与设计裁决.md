# 原型差异与设计裁决

## 1. 目的与使用方法

产品原型由四份独立的 HTML 生成，样式说明（`algorithmic_precision/DESIGN.md`）与实际渲染存在漂移，且原型本身带有示例数据与局部缺陷。本文档承担两件事：

1. **登记**所有已发现的冲突、缺失、硬编码与工程缺陷，给出唯一编号（D-xx）；
2. **裁决**唯一正确取值或行为，并指明该裁决落在哪份文档。

使用规则：

- 开发与设计遇到原型与本套文档不一致时，**以文档裁决为准**，不得"照着原型写"。
- 新增裁决必须追加编号，不得改写历史编号的含义（可标记"已作废"）。
- 每条裁决必须可验证：能落到令牌、组件规格、页面规格或代码检查项上。

## 9. 裁决流程

```text
发现冲突
   │
   ├─ 属"颜色/尺寸/字体" → 查 02-02 / 02-03 / 02-04 → 已有令牌则直接采用
   │
   ├─ 属"交互/文案/状态" → 查 03-0x 页面文档 → 仍无定义 → 提 D-xx 草案
   │
   └─ 属"数据口径/算法"   → 查 04-03 / 04-04 → 仍无定义 → 提 Q-xx 待确认
                              │
                              ▼
                     设计评审（双周）→ 追加本文档 → 同步落点文档 → 通知开发
```

规则：

1. **编号不复用**：D-xx 一经发布即固定，作废只标记状态。
2. **一处裁决、多处同步**：裁决必须同时更新"落点文档"，并在 PR 描述中列出。
3. **不得口头裁决**：评审结论必须进本文档，否则视为未生效。
4. 待确认项（Q-xx）在未拍板前，开发按"建议"实现，但需以 Feature Flag 隔离。
