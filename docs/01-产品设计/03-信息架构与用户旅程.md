# 信息架构与用户旅程

## 1. 目的与范围

本文定义 CodeStreak 的页面地图、导航层级、内容模型与四条关键用户旅程，用于指导 `Navigation` / `NavPathStack` 落地与交互走查。

| 项 | 说明 |
| --- | --- |
| 覆盖 | 4 个一级 Tab、8 个规划二级页、4 层导航容器、12 个内容实体、4 条主旅程、空态兜底 |
| 不覆盖 | 组件视觉与状态样式（[设计令牌规范](../02-设计规范/02-设计令牌规范.md)，02-02）、字段类型与枚举（01-04） |
| 编号约束 | 页面只引用 P-01~P-12，组件只引用 C-01~C-40，**不得新增编号**；编号即契约，文档与代码注释复用 |
| 代码现状 | 仅 Entry 模板，无任何页面；本文为待实现结构 |

## 2. 信息架构原则

| 编号 | 原则 | 含义 | 落地表现 | 反例（不做） |
| --- | --- | --- | --- | --- |
| IA-1 | 一 Tab 一问题 | 四个 Tab 各答一个问题 | 今天做了没 / 刷什么 / 何时比 / 练成什么样 | 在 P-01 放题单全量列表 |
| IA-2 | 两跳可达 | 核心操作 ≤2 次点击 | 完成打卡 1 次点击，补题 2 次 | 三级菜单藏补签 |
| IA-3 | 状态外显 | 入口即见关键状态 | 题单卡进度、比赛卡"报名中/未开始" | 点进去才知道是否已打卡 |
| IA-4 | 层级封顶 | Tab→二级→抽屉/弹层，无三级页 | 抽屉不再叠抽屉 | 详情页里再开全屏页 |
| IA-5 | 模态克制 | 打断式反馈只在"达成"时出现 | C-16 每日最多 1 次 | 每次点击都弹窗 |
| IA-6 | 离线优先 | 先读本地再拉远端，写操作先落本地 | 打卡/补题可离线，标记"待同步" | 断网即白屏 |

## 4. 导航模型

### 4.1 四层容器

| 层级 | 容器 | 承载页面 | 职责 | 返回行为 | 进入动效 |
| --- | --- | --- | --- | --- | --- |
| L0 | `Tabs` + C-02 | P-01~P-04 | 一级方位，保留各 Tab 滚动位置与筛选 | 非 today 回 today；today 且栈空时二次确认退出 | 平级切换 |
| L1 | `Navigation` + `NavPathStack` + `NavDestination` | P-05~P-09 / P-11 / P-12 | 单任务深入，可叠层 | `pop()` 一层 | 右侧滑入 |
| L2 | `bindSheet` 半模态 | 补签确认 / 新建题单 / 导入题单 / 道具说明 | 轻量操作，不离开上下文 | 收起抽屉 | 底部升起 |
| L3 | `bindContentCover` / `CustomDialog` | C-16 庆祝、首次引导、隐私协议 | 打断式反馈或全屏任务 | 关闭并回到来源 | 淡入 + 缩放 |

AppBar（C-01）眉标固定 `CODESTREAK // CLI`，主标题为 Tab 名；深链统一 `codestreak://problem/{problem_key}`、`codestreak://contest/{id}`、`codestreak://tab/{name}`；做题与看比赛一律外跳系统浏览器，不内嵌 WebView。

### 4.2 返回优先级

```text
系统返回 / 右滑手势
  ├─ L3 存在 → 关闭 L3（C-16 视为已读，当日不再弹）
  ├─ L2 存在 → 收起 L2（未保存输入先确认，内容保留到下次打开）
  ├─ L1 栈非空 → pop 一层
  ├─ L0 ≠ today → 切回 today
  └─ 否则 → Toast「再按一次退出」→ 2s 内再次返回才退出
```

深链进入的页面必须先把 Tab 栈补位到目标所属 Tab，返回时落回该 Tab 根页，不出现空白容器。

## 5. 内容模型概览

### 5.1 实体清单

| 实体 | 说明 | 关键字段 | 规模 |
| --- | --- | --- | --- |
| user | 用户与等级 | `user_id` / `nickname` / `uid_short` / `tier` / `is_pro_display` | 1 条/人 |
| platform_account | 平台账号绑定 | `platform_code` / `handle` / `bind_status` / `last_sync_at` | ≤4 条/人 |
| problem | 题目元数据（不含题面） | `problem_key` / `platform_problem_id` / `difficulty_norm` / `title` | 缓存 5k–20k |
| submission | 提交/通过记录 | `verdict` / `is_ac` / `solved_at` / `problem_key` | 10²–10⁴/人 |
| checkin | 每日打卡聚合 | `checkin_date` / `daily_ac_count` / `daily_status` / `source` | 365+/年 |
| collection | 题单 | `collection_type` / `total_count` / `completed_count` | 官方 20–50 |
| contest | 比赛 | `contest_id` / `contest_start_at` / `duration_minutes` | 每周 5–15 场 |
| contest_participation / upsolve_task | 参赛与补题 | `final_ac_count` / `upsolve_rate` / `upsolve_status` | 10–50/年 |
| badge | 徽章与进度 | `badge_state` / `progress_current` / `progress_target` | 12 枚（原型 3/12） |
| makeup_credit_ledger | 补签卡流水 | `delta` / `balance_after` / `reason` / `occurred_at` | <50 条/人 |
| sync_job | 同步任务 | `status` / `started_at` / `error_code` | ≤30 条/时 |

### 5.2 关系图

```text
user 1 ── N platform_account
 │               └─ 1 ── N submission ── N ── 1 problem
 │                              └─────── N ── 1 contest
 ├─ 1 ── N checkin          （按日聚合 submission + 手动打卡）
 ├─ 1 ── N collection ── 1 ── N collection_item ── N ── 1 problem
 ├─ 1 ── N contest_participation ── 1 ── N upsolve_task ── N ── 1 problem
 ├─ 1 ── N user_badge ── N ── 1 badge
 ├─ 1 ── N makeup_credit_ledger
 ├─ 1 ── N sync_job
 └─ 1 ── 1 settings
```

### 5.3 模型约束

1. `problem_key` 全局唯一，格式 `{LC|CF|LG|AC}-{原生题号}`；跨平台同题**不去重**，按两题计。
2. `checkin` 以 `(user_id, checkin_date)` 唯一，时区固定 Asia/Shanghai，避免跨时区改日。
3. 补题产生的记录进入 `submission`，**计入** `daily_ac_count`、总 AC 与难度分布，但**不计入** `daily_target_progress`（防止赛日刷旧题冲量、变相完成当日目标）。
4. `submission` 按平台侧唯一 ID 幂等去重；手动打卡生成 `source = manual` 记录，同样参与总 AC。
5. streak、`upsolve_rate`、题单完成度均为只读派生值，除性能需要外不落冗余字段。

## 6. 关键用户旅程

### 6.1 J1 首次启动 → 绑定平台 → 完成首日打卡（≤3 分钟，单会话完成）

| 步骤 | 用户动作 | 系统响应 | 界面 | 情绪 / 风险点 |
| --- | --- | --- | --- | --- |
| 1 | 点击桌面图标 | 启动窗底色 `#10141A` 无白闪，并行初始化本地库 | 启动窗 → C-40 | 期待"快"；风险：白闪已由启动窗底色修正 |
| 2 | 首次启动 | 隐私协议通过后进入 3 步引导第 1 步 | L3 全屏引导 | 风险：引导过长，硬上限 3 步且每步可跳过 |
| 3 | 选"求职高频" | 记录赛道偏好，进入绑定步骤 | P-09 | 风险：不想绑定，提供"稍后再说"落 P-01 空态 |
| 4 | 输入 LC handle 并在内置 WebView 完成登录 | 写 `bind_status = authorized`，仅读取本人记录，标注"授权同步" | P-09 / C-13 | 风险：用户担忧账号安全，须说明仅读不写、可随时解绑 |
| 5 | 输入 CF handle | 调官方 API 校验并拉取近期提交与 rating | P-09 加载态 | 风险：拉取慢，8s 超时降级"仅手动"不阻断 |
| 6 | 完成绑定 | 计算初始总 AC、难度分布、`streak = 0`，落 P-01 | P-01 / C-04 | 情绪：0 天易挫败，文案改为"完成 2 题即开启第 1 天" |
| 7 | 完成 2 题并授权提醒 | 达成 2/2，streak 0→1，弹 C-16；写入 21:30 提醒 | C-16 / 系统弹窗 | 首日正反馈是留存关键点；拒绝授权则降级为设置页引导 |

## 8. 空态与冷启动兜底

### 8.1 空态矩阵

| 场景 | 触发条件 | 组件 | 主文案 | 次文案 | 主 CTA |
| --- | --- | --- | --- | --- | --- |
| 未绑定平台 | 引导中跳过 | C-39 | 还没有平台账号 | 绑定后可自动计算连胜与难度分布 | 去绑定 → P-09 |
| 今日目标未生成 | 题库为空或生成失败 | C-39 | 今日题目准备中 | 下拉刷新或稍后再试 | 刷新（C-10） |
| 题单为空 | 新用户无订阅 | C-39 | 还没有题单 | 先从官方精选题单开始 | 浏览官方题单（C-09） |
| 赛程为空 | 首次无缓存或离线 | C-39 | 暂无赛程数据 | 上次同步：-- | 重试（C-10） |
| 统计不足 7 天 | 新用户 | C-40 + 占位 | 数据太少，先打卡 7 天 | 连续 7 天后解锁趋势视图 | 去打卡（C-09） |
| 同步失败 | 网络或接口错误 | C-18 + 保留缓存 | 同步失败，已展示本地数据 | 附错误码便于反馈 | 重试 |

### 8.2 骨架与超时策略

1. 首屏固定 3 个骨架块（C-04、C-06、C-07），高度与真实卡片一致，避免加载完成后跳动。
2. 请求 >300ms 才显示 C-40，>8s 转错误态并提供重试，**禁止无限 loading**；骨架只用于首屏与首次进入某 Tab，下拉刷新用指示器且最小展示 600ms。

### 8.3 冷启动落地判定

| 状态 | 判定条件 | 落地页 |
| --- | --- | --- |
| 全新用户 | 无 `onboarding_done` | 引导 L3 → P-01 |
| 引导完成未绑定 | `onboarding_done = true` 且 0 个 `bound` | P-01 空态 + C-39 |
| 已绑定在线 | ≥1 个 `bound` 且网络可用 | P-01 并触发一次同步 |
| 已绑定离线 | 网络不可用 | P-01 读缓存 + C-12 离线标记 |
| 深链冷启动 | 携带 `codestreak://` 参数 | 目标页 + 补位 Tab 栈 |
| 绑定失效 | `bind_status = invalid` | P-01 + 一次性 C-18 提示重新绑定 |
