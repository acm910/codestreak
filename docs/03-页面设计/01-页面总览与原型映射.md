# 页面总览与原型映射

## 1. 目的与适用范围

本文档是 CodeStreak 客户端**页面级设计的索引与总纲**：定义 12 个页面的编号、路由、原型对应、优先级与负责组；约定全局框架（C-01 AppBar / C-02 BottomTabBar / 内容区）的骨架尺寸；给出导航拓扑、跳转矩阵与组件复用矩阵；并汇总页面文档与 HTML 原型之间**已裁决的差异**。

- 上游：[设计令牌规范](../02-设计规范/02-设计令牌规范.md)（颜色唯一权威）、[布局栅格与间距规范](../02-设计规范/04-布局栅格与间距规范.md)、[组件规范](../02-设计规范/05-组件规范.md)。
- 下游：[P-01 今日打卡](02-今日打卡页.md)、[P-02 题单矩阵](03-题单矩阵页.md)、[P-03 比赛日历](04-比赛日历页.md)、[P-04 统计榜单](05-统计榜单页.md)、[弹层与全局状态](06-弹层与全局状态.md)。
- 冲突优先级：**令牌/组件规范 > 本文 > 页面文档 > HTML 原型 > DESIGN.md**。
- 尺寸约定：设计稿 360vp 宽，1px ≈ 1vp；本文尺寸单位 vp，字号单位 fp（字体令牌见[字体与排版规范](../02-设计规范/03-字体与排版规范.md)）。

## 3. 全局框架

### 3.1 三段式骨架

| 区域 | 尺寸 | 令牌 | 行为 |
| --- | --- | --- | --- |
| C-01 AppBar | 64vp + 状态栏安全区 | 底 `cs.color.surface` @85% + 背景模糊 24vp；底缘阴影 `0 1vp 8vp rgba(0,0,0,0.25)` | 固定顶部；内容滚动不穿透；图标块 36vp、标题 `headline-sm` |
| 内容区 | 左右 16vp；顶 72vp；底 88vp | `cs.color.surface` | 单一滚动容器（`Scroll` / `List` 二选一，禁止嵌套同向滚动） |
| C-02 BottomTabBar | 64vp + 底部安全区 | 底 `cs.color.surface.lowest` @90% + 模糊；顶缘 1vp 阴影 | 固定底部；4 项；选中 `cs.color.primary.container` |

### 3.2 容器与滚动规则

1. 每个页面根节点为 `Column`（AppBar + 内容 + TabBar 三段），内容段必须 `layoutWeight(1)`，不得让内容把 TabBar 挤出屏幕。
2. 内容容器统一 `padding({ left: 16, right: 16, top: 72, bottom: 88 })`；**横滑货架**（如 P-02 C-23）用负 16vp 出血 + 内 16vp，保证卡片可从屏幕边缘滑入。
3. Tab 根页使用 `Scroll`（内容整体滚动）；长列表页（P-02 题单矩阵库、P-04 榜单）使用 `List` + `LazyForEach`，Header 区作为 `List` 的第 0 个 `ListItemGroup`。
4. Tab 切换使用 `Tabs` 组件 `barPosition: BarPosition.End` 或自绘 `NavDestination` 保活；**每个 Tab 独立保留滚动位置与筛选状态**，切回不重置。
5. 弹层（C-16 / C-17 / C-18）挂在页面根 `Stack` 上，层级高于 TabBar；C-17 抽屉需覆盖 TabBar 并阻断其点击。
6. 深色单主题，禁止页面级改底色；状态栏、导航栏图标固定浅色。

### 3.3 ArkUI 骨架（示意，落地以各页文档为准）

```ts
Column() {
  CsAppBar({ title: $title })              // C-01，64vp
  Scroll() {
    Column({ space: 20 }) { /* 页面区块 */ }
      .padding({ left: 16, right: 16, top: 8, bottom: 24 })
  }.layoutWeight(1)
  CsTabBar({ index: $tabIndex })           // C-02，64vp + 安全区
}
.backgroundColor($r('app.color.cs_color_surface'))
```

## 7. 页面骨架尺寸表

| 项 | 取值 | 说明 |
| --- | --- | --- |
| AppBar 高度 | 64vp（不含状态栏） | 背景延伸到状态栏；安全区用 `expandSafeArea` 处理 |
| 内容区顶距 | 72vp = 64 + 8 | 原型为 64（首个区块紧贴 AppBar），归一后加 8vp 缓冲（PD-06） |
| 内容区左右边距 | 16vp | 全页一致；横滑货架出血到 0，卡片内侧再 16vp |
| 内容区底部留白 | 88vp = TabBar 64 + 24 | P-01 原型为 96，归一为 88 |
| 区块间距 | 20–28vp | P-01 = 20（`space-lg`），P-02 = 28（`space-xl`），P-03 / P-04 = 20 |
| 区块内间距 | 8 / 12vp | 区块标题 → 卡片 8vp；卡片内元素 8–12vp |
| 卡片圆角 | 12vp；内层 8vp；标签 4vp；胶囊 full | 与令牌形状规范一致 |
| 卡片内边距 | 16vp（主卡）/ 12vp（列表行、货架卡） | 主推荐、Hero、比赛 HUD 用 16 |
| 横滑卡宽 | 270vp + 12vp 间距 | 328vp 可见区内露出下一张约 46vp，提示可滑 |
| TabBar | 64vp + 底部安全区 | 图标 22vp + 文案 `label-sm` 10fp |

- 待统一：02-04 §间距 将"页面首元素距 AppBar"定为 12vp，而 P-01–P-04 四份页面文档实现为 8vp（合计 72vp）；P-04 的区块间距取 16vp，与本表 20–28 冲突。两处需由布局规范裁决后回写本文与各页文档（已在 06-01 待补条目）。

| PD-07 | 阴影使用 | 原型普遍 `shadow-md` / `shadow-sm` 抬升卡片 | 令牌 5.1：仅 TabBar 与弹层允许阴影 | 卡片改用 1vp 描边（`border.subtle` 或 `primary` @20%）表达层级，禁止逐卡投影 |

## 9. 文档与原型不一致时的处理流程

1. **判定**：先比对令牌与组件规范；若规范已有取值，则原型视为实现偏差，不改文档。
2. **登记**：规范未覆盖时，在 [原型差异与设计裁决](../06-附录/01-原型差异与设计裁决.md) 新增 `D-xx` 条目（页级临时编号 `PD-xx`），写明原型值、建议值、影响页面与理由。
3. **裁决**：由交互设计组 + 视觉设计组评审，涉及颜色/形状的必须由令牌 owner 确认；裁决结论回写令牌或组件规范，而不是只写在页面文档里。
4. **落地**：页面文档升级次版本（v1.x），变更记录注明"对齐 PD-xx"；开发按页面文档实现，评审不接受"原型就是这样"作为理由。
5. **回收**：差异条目在实现验收后标记"已收敛"，超过两个版本仍未收敛的条目升级为阻塞项。
6. **红线**：颜色只允许引用 `cs.color.*`；尺寸只允许引用第 7 节骨架表或页面文档表格；两者都不满足时先补规范再写页面。
